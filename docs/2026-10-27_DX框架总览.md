# DX 框架总览（功能实现文档）

| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | DX 框架 |
| 覆盖范围 | `dx/` 目录分层、自动加载入口、管理器注册与生命周期广播、管理器职责与依赖、对外 API 面、扩展新管理器 |

> 一句话定位：`dx/` 是项目内置的运行时框架（53 个 `.gd`，约 9600 行），以自动加载单例 `DX` 的形式提供存档、文件（SAF）、弹窗、调试、本地化、对象池、时间、事件总线等能力；业务代码只通过 `DX.xxx` 访问，不直接 new 管理器。

## 1. 功能概述

- **用户视角**：没有直接界面，但几乎所有可见能力都由它托底——关掉 App 再打开能恢复歌单/播放进度（`DX.save`）、Android 上能读外部音乐目录（`DX.files`）、所有页面能弹出与返回（`DX.popup`）、三击/`F10` 能开调试面板（`DX.debug`）、切语言后界面文字即时刷新（`DX.localization`）。
- **实现视角**：
  - 入口场景 `dx/runtime/scenes/managers/dx.tscn` 的根脚本是 `dx/dx.gd`（`class_name DX_Root`），在 `project.godot:26` 注册为自动加载单例，节点名 `DX`。
  - 框架采用「注册表 + 生命周期广播」模式：管理器不是各自被业务代码调用，而是先登记到 `DX_Root._manager_map`，再由根节点按固定顺序回调 `in_ready/in_process/...` 钩子（`dx/dx.gd:19-25`）。
  - 管理器分两类：纯逻辑管理器（`RefCounted`，在 `_enter_tree` 阶段 `new()` 出来）与场景管理器（`Node`，必须来自 `dx.tscn` 的子节点：`Pool`、`Popup`）。
- **不在本期范围**：DX 不是 Godot 插件包，没有 `plugin.cfg`；它不提供 ECS、物理、网络、渲染管线，也没有二进制资源打包能力。

## 4. 关键实现

### 4.1 为什么分「两段式」启动

`_bootstrap()`（`dx/dx.gd:158`）在 `_enter_tree` 就被调用，而 `Pool`/`Popup` 的注册拖到 `_ready()`（`:108-112`）。原因：

1. `_enter_tree` 阶段子节点已经存在但 `_ready` 未触发，纯 `RefCounted` 管理器没有任何场景依赖，可以立刻建好，保证 `in_ready` 里 `dx.logger`、`dx.time` 之类已经被其它管理器拿到；
2. `Pool`/`Popup` 是 `dx.tscn` 里的 Node，需要 `@onready` 变量（如 `dx/runtime/scripts/managers/pool/pool_manager.gd:8-9` 的 `%PoolActive`/`%PoolInactive`）先解析完成，所以放到 `_ready()`；
3. `_bootstrap()` 首行有 `if not _manager_order.is_empty(): return`（`:159-160`）防止重复注册。

### 4.2 生命周期钩子是「鸭子类型」

根节点不持有任何管理器基类，只按名字查方法：

```gdscript
# dx/dx.gd:216-219
func _call_manager_no_args(manager, method_name: StringName) -> void:
	if manager == null or not manager.has_method(method_name):
		return
	manager.call(method_name)
```

因此新增管理器可以不实现任何钩子，也可以只实现关心的几个（例如 `config_manager.gd` 只实现 `in_ready`）。代价是拼错方法名不会报错，只会静默不执行——所以钩子名被提成常量（`:19-25`）供全项目统一引用。

### 4.3 注册时注入 `dx`，管理器反向访问框架

```gdscript
# dx/dx.gd:138-144
func register_manager(manager_name: StringName, manager):
	if manager == null:
		return null
	manager.dx = self
	_manager_map[manager_name] = manager
	_manager_order.append(manager)
	return manager
```

所有管理器都声明 `var dx: Node`，于是可以 `dx.logger.warning(...)`（`dx/runtime/scripts/managers/pool/pool_manager.gd:61`）、`dx.time.now_unix()`（`dx/runtime/scripts/managers/pool/pool_manager.gd:168`）。`files` 管理器把 `dx` 写成 setter（`dx/runtime/scripts/managers/files/file_manager.gd:15-23`），在注入时把 `dx` 一并传给 3 个 provider 与平台实现，避免它们各自再找根节点。

### 4.4 退出顺序与「只写一次盘」

`_dispatch_quit()`（`dx/dx.gd:208-214`）先置 `_quit_dispatched`，再**逆序**调用 `in_quit`，最后清掉序列化器的静态缓存（`JsonSerializerScript.clear_cache()`）。逆序是刻意的：`signal`/`countdown` 这种被依赖的管理器最后收尾，避免前面关掉后有人还在 `fire()`。

`dx/runtime/scripts/managers/save/save_manager.gd:31-32` 的 `in_quit()` 里 `_flush_pending_save(true)` 与此配合：Android 上「窗口关闭通知」和 `_exit_tree` 可能先后到达，幂等开关保证不会写两遍存档。

### 4.5 两个 CanvasLayer 的分工

`dx/runtime/scenes/managers/dx.tscn:11-15` 建了两个层：`UI`（layer 100）给飞入动效做宿主（`dx/runtime/scripts/effects/dx_ui_fly_effect.gd:7`、`:46`），`DebugLayer`（layer 10000）承载调试触发按钮与调试面板，保证调试 UI 永远压在最上层、不会被业务页面遮挡。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| `dx.tscn` 缺 `Pool` / `Popup` 子节点 | `push_error("DX ... node is missing.")`，该管理器不注册，`DX.pool`/`DX.popup` 返回 `null`（`:180-183`、`:190-193`） |
| 重复注册同名管理器 | `_manager_map` 覆盖值但 `_manager_order` 会重复追加——靠 `_register_*` 里的 `has_manager()` 早退避免（`:177`、`:187`） |
| 管理器未实现某钩子 | 静默跳过，不报错 |
| 管理器实现了 `in_quit` 但已 `queue_free` | `_dispatch_quit` 用 `manager == null` 判空；非法实例仍可能触发 `push_error`（`has_method` 对已释放对象返回 false） |
| 语言/前后台通知在无管理器时到达 | 广播循环对空 `_manager_order` 直接结束 |
| 序列化器静态缓存跨重启残留 | `_dispatch_quit` 末尾统一 `clear_cache()` |

## 6. 相关测试

无针对框架启动的自动化测试。手工验证步骤：

1. 用 Godot 4.7 打开项目，运行主场景；在 `_ready` 断点确认 `DX.get_manager_names()` 返回 14 个名字；
2. 打印 `DX.time.now_unix()` 与 `Time.get_unix_time_from_system()` 差值应 < 1 秒；
3. Android 上按 Home 退后台再回来，确认 `DX.background_state.is_background` 从 `true` 变回 `false`；
4. 切换系统语言（或调用 `DX.localization.set_locale()`），确认 `NOTIFICATION_TRANSLATION_CHANGED` 链路下界面文字刷新；
5. 关闭窗口后重启，确认 `user://save/data.json` 未被写坏（有 `.bak` 兜底，见 [DX存档与序列化](2026-10-27_DX存档与序列化.md)）。

## 8. 已知限制与后续

- 管理器集合是编译期固定的 14 个常量，没有运行时动态注册的公开入口；插件若要扩展只能拿到已有管理器。
- `register_manager` 不校验重名，误用时表现为顺序数组里出现两个实例，排查成本较高。
- `_process` 逐帧对全部 14 个管理器做 `has_method` + `call`，是字符串反射调用；管理器数量再增长时应改为启动时一次性缓存 Callable。
- `dx.tscn` 只有 `Pool`/`Popup` 两个场景管理器；其余能力是 `RefCounted`，无法在编辑器中可视化配置。
- `DX.effect` 依赖固定节点路径 `UI`（`dx/runtime/scripts/effects/dx_ui_fly_effect.gd:7`），改层名会静默失效（`dx.get_node()` 抛错）。
