> 一句话定位：播放队列是一份「只存 ID 的顺序数组」：`playback_state.track_ids` + `queue_index` 游标，播放器、队列弹窗、歌单页、搜索结果都通过同一个 `MusicAppPlaybackController` 改写它，界面只是它的投影。

## 1. 功能概述

用户视角：

- 在播放器页点右上角队列按钮，或点迷你播放器右侧列表按钮，底部上滑弹出队列面板；
- 面板标题显示「播放队列 · N 首」，列表按播放顺序展示曲目，当前播放项的高亮图标与标题颜色与其他行不同，打开面板时会自动滚动到当前项；
- 点某一行立即切歌，点行尾「×」把该曲移出队列，点顶部「清空」清空整个队列；
- 标题右侧的模式按钮每点一次在「列表循环 → 单曲循环 → 随机播放」间循环，图标与文案同步变化。

实现视角：

- 队列数据在存档层，不在运行时数组里：`MusicAppPlaybackStateData.track_ids` 与 `queue_index` 会被序列化到 `playback_state` 节点（`assets/scripts/save/music/music_app_state_data.gd:20`）。因此杀进程重启后队列仍然存在，存档归一化会剔除已删除的曲目；
- 三层分工：`MusicAppPlaybackQueueView` 只负责渲染与滚动，`MusicAppPlaybackQueueController` 把 ID 数组翻译成可显示的行数据，`MusicAppPlaybackController` 才是唯一能改动 `queue_index`、播放模式与音频同步的地方。

不在本期范围：队列拖拽排序、显式的「加入队列」按钮（`append_tracks_to_queue` 已实现但没有 UI 调用方，见 4.7）。

## 3. 核心数据结构

`MusicAppPlaybackStateData`（`assets/scripts/save/music/music_app_playback_state_data.gd`）：

| 字段 | 行号 | 类型 | 含义 |
| --- | --- | --- | --- |
| `selected_track_id` | :13 | `String` | 当前曲目 ID，播放器页用它取曲目信息 |
| `selected_playlist_index` | :14 | `int` | 首页最近打开的播单，与队列无关 |
| `track_ids` | :15 | `Array[String]` | 队列本体，数组顺序即播放顺序 |
| `queue_index` | :16 | `int` | 游标，当前曲目 = `track_ids[queue_index]` |
| `mode` | :17 | `int` | 0 列表循环 / 1 单曲循环 / 2 随机 |
| `elapsed_seconds` | :18 | `float` | 播放进度，用于切歌时复位 |
| `is_playing` | :19 | `bool` | 播放开关 |

模式枚举定义在 `assets/scripts/save/music/music_app_state_data.gd:8-12`（`LOOP_ALL / REPEAT_ONE / SHUFFLE`）。

队列行 DTO（由 `get_queue_rows()` 生成，不落盘）：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `queue_index` | 数组下标 | 播放/定位 |
| `title` | `track.title`，空则回退 `file_path` basename | 主标题 |
| `subtitle` | `artist - subtitle`，再拼 ` · source` | 副标题 |
| `source` | `track.source`，空则「本地文件」 | 来源标签 |
| `is_current` | `queue_index == state.queue_index` | 高亮判定 |

## 4. 关键实现

### 4.1 队列只存 ID，不存曲目对象

队列与歌单、下载记录一样只保存 `track_id` 数组，曲目对象唯一存放在 `tracks` 里。好处是改顺序、删歌都不用复制曲目数据；代价是每个读取点都要处理「ID 已失效」。

归一层有两处：

- 播放状态 `normalize()`（`assets/scripts/save/music/music_app_playback_state_data.gd:21-38`）过滤掉 `track_id_map` 里不存在的 ID，把 `queue_index` 钳到合法范围；队列清空时顺手把 `is_playing=false`、`elapsed_seconds=0`、`selected_track_id=""`，避免「没有队列却在播」；
- 视图层 `get_queue_rows()`（`assets/scripts/ui/music_app/controllers/music_app_playback_queue_controller.gd:45-65`）也 `continue` 跳过取不到的曲目，防止运行期删歌后出现空白行。

### 4.2 打开时先同步刷新，再分帧补建行

`refresh()`（`assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_view.gd:54-83`）先算出行数并调用 `_sync_queue_rows(rows.size())`（:85-93）：行数变少直接 `queue_free()`，行数变多把新建的差量交给 `_populate_queue_rows_batched()`（:113-128）。

分批的意义在真机上很直接：一次 `instantiate()` 几十上百行会占住主线程，音频回调随之抖动出现爆音。这里每 6 行 `await get_tree().process_frame` 让出一帧；`_queue_render_generation` 自增用于让上一轮的协程在弹窗关闭或队列变化后自行退出，避免把旧数据写进新行。

`refresh()` 末尾还会立刻对已存在的行调用 `_configure_queue_row()`，所以第一帧就能看到标题、当前项高亮和禁用态，不需要等分批结束。

### 4.3 高亮与滚动定位

当前行由 `is_current` 决定（`assets/scripts/ui/music_app/controllers/music_app_playback_queue_controller.gd:63` 等），行内据此切换两处视觉：

```gdscript
current_icon_rect.visible = is_current
title_label.add_theme_color_override(
    "font_color",
    ACTIVE_TEXT if is_current else PRIMARY_TEXT
)
```

`ACTIVE_TEXT = Color(1.0, 0.3, 0.4)`（`assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_row.gd:9`）与播放器页强调色一致，未播放行用 `PRIMARY_TEXT`。

滚动定位放在 `on_popup_shown()` 里 `call_deferred("_scroll_to_current_row")`（`assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_view.gd:49-51`），而不是 `refresh()` 里同步调用：弹窗刚可见时 `ScrollContainer` 的布局与内容高度都还没算出来，`ensure_control_visible()` 会按错误的矩形计算，滚动量为 0。延迟到本帧末尾，布局已就绪；分批补建完成后（:127-128）再调一次，保证新增行撑高列表后依然能滚到当前项。

### 4.4 行内操作：播放与移除

播放走 `play_queue_track(index)` → `MusicAppPlaybackController.play_queue_index(index, true)`（`assets/scripts/ui/music_app/controllers/global/music_app_playback_controller.gd:125-137`），后者统一改 `queue_index`、`selected_track_id` 再 `request_audio_sync()`。视图侧注释写得很清楚：播放器控制器会同步更新选择索引，这里只管立刻刷新高亮，真正的音频切换交给信号。

移除走 `remove_track_from_queue(queue_index)`（:140-171），信号带的是行下标而不是曲目 ID，游标修正是这段最容易写错的地方：

| 情况 | 处理 |
| --- | --- |
| 队列只剩这一首 | 直接 `clear_playback_queue()`，否则会留下空队列 |
| 删掉的是当前项 | `queue_index = mini(original, size - 1)`，即落到后一首（删的是最后一首则落到前一首） |
| 删掉的是当前项且位置变了 | 重置 `elapsed_seconds = 0` 并重新同步音频 |
| 删掉的是当前项之前的项 | `queue_index -= 1`，保持「还在听同一首」 |
| 删掉的是当前项之后的项 | 不动游标 |

如果简单地把游标减一，删当前项时会「跳过一首」；如果只钳制不重置进度，则会拿旧进度去播另一首。这两个坑在注释里都有记录。

### 4.5 清空与播放模式

`clear_playback_queue()`（:68-73）一次性复位 `track_ids`、`queue_index`、`selected_track_id`、`is_playing`，然后 `request_audio_sync()` 让音频后端停下。没有二次确认——清空是即时生效的破坏性操作，这是当前的取舍（见第 8 节）。

模式切换 `cycle_playback_mode()`（:42-46）用 `posmod(mode + 1, PLAYBACK_MODE_COUNT)` 在三种模式间循环，文案与图标分别由 `get_playback_mode_label_key()`（:213-220）和 `get_playback_mode_icon()`（:223-230）提供，视图不硬编码文本。真正消费模式的是 `advance_after_finish()`（:110-122）：

```gdscript
var current_queue_index := clampi(get_playback_queue_index(), 0, playback_track_ids.size() - 1)
match get_playback_mode():
    PlaybackMode.REPEAT_ONE: play_queue_index(current_queue_index, true)
    PlaybackMode.SHUFFLE:    play_queue_index(_pick_random_queue_index(true), true)
    _:                       play_queue_index(posmod(current_queue_index + 1, playback_track_ids.size()), true)
```

随机模式特意排除了「随机到同一首」：`_pick_random_queue_index()`（:258-268）在队列大于 1 且 `exclude_current` 为真时，从「除当前项之外的 `size-1` 个」里取值再整体偏移。否则 1/N 的概率会重播当前曲，用户感知就是「随机没反应」。注意切模式本身不会打乱队列，随机只发生在推进时。

### 4.6 队列的填充方：谁替换队列、谁置顶

代码里没有「加入队列」按钮，当前的队列语义分两类：

| 语义 | 入口 | 实现 |
| --- | --- | --- |
| 整单替换 | 歌单「播放全部」/「播放单曲」 | `MusicAppPlaylistController._play_track_list()`（`assets/scripts/ui/music_app/controllers/music_app_playlist_controller.gd:146-155`）：`set_playback_queue(playlist.tracks)` + `play_queue_index(slot)` |
| 整单替换 | 本地音乐点行 | `MusicAppLocalMusicController.play_local_track_list()`（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:117-123`） |
| 替换或置顶 | 插件搜索结果点行 | `MusicAppPluginBrowserController`：队列为空时把全部搜索结果设为队列并从选中项播；队列非空时用 `play_track_at_queue_top()` 把该曲插到队首并播放，不追加到队尾（`assets/scripts/ui/music_app/controllers/global/music_app_playback_controller.gd:197-210`） |

`append_tracks_to_queue()`（:178-194）实现了「去重后追加」的语义，全仓库没有调用方——UI 层还没有提供「加入队列」入口。写文档时不能把它描述成已上线能力。

## 5. 边界与失败处理

| 场景 | 处理 | 位置 |
| --- | --- | --- |
| 队列为空（清空或删掉最后一首） | 列表隐藏、空态文案「播放队列是空的」；模式与清空按钮禁用 | `assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_view.gd:71-83` |
| 队列中曲目被删除 | 归一化与 `get_queue_rows()` 双重跳过 | `assets/scripts/save/music/music_app_playback_state_data.gd:21-38`、`assets/scripts/ui/music_app/controllers/music_app_playback_queue_controller.gd:56-57` |
| 行标题为空 | 回退 `file_path` 的 basename | `assets/scripts/ui/music_app/controllers/music_app_playback_queue_controller.gd:68-89` |
| 连续快速点行 | 每次成功播放都 `refresh()`，行池差量重建，不累积旧行 | `assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_view.gd:141-147` |
| 弹窗关闭 | 只关视图，不停止播放；重开时 `on_popup_shown` 重新 refresh | `assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_view.gd:48-51` |
| 队列渲染过程中队列又变了 | `_queue_render_generation` 让旧协程失效 | `assets/scripts/ui/music_app/views/playback_queue/music_app_playback_queue_view.gd:113-128` |

一个已知的错位风险：`get_queue_rows()` 用原数组下标写入 `queue_index`，但视图按「行数组的位置」索引。当队列中间有失效 ID 被跳过时，行位置与 `queue_index` 不再相等，`_scroll_to_current_row()` 用 `_queue_rows[current_index]` 取行就会偏。当前归一化在启动时已经剔除了失效 ID，运行期出现的窗口很短，见第 8 节。

## 6. 相关测试

`assets/tests/` 下没有播放队列的自动化测试；`assets/tests/music_app/music_app_ui_test.gd` 只做界面构建冒烟，会实例化一次队列行场景（`assets/scenes/ui/music_app/playback_queue/playback_queue_row.tscn`），用于发现场景脚本报错。

手工验证建议：

1. 打开播放器 → 点队列按钮，确认标题计数与列表长度一致；
2. 点第 3 行，确认高亮与播放器页标题同步，再次打开队列时自动滚到该项；
3. 移除当前项，确认播到后一首且进度归零；移除当前项之前的一项，确认仍在听同一首；
4. 队列只剩一首时移除，确认弹窗变成空态且音频停止；
5. 切到随机模式，连续让曲目播完多次，确认不会重播同一首。

## 8. 已知限制与后续

- 队列不支持拖拽排序。歌单页已经有拖拽实现，队列页没有复用，因为队列里混着跨来源的曲目，排序结果无法落回任何歌单。
- 「加入队列」只有数据层能力（`append_tracks_to_queue`），没有入口；要做的话建议在搜索/歌单行菜单里加一项，并复用去重逻辑。
- 清空没有二次确认，误触成本是重建队列。
- 队列中间出现失效 ID 时，行位置与 `queue_index` 会短暂错位（见 5 节），后续可让 `get_queue_rows()` 输出「行位置」与「真实下标」两个字段。
- 场景里的 `CloseQueueButton` 是 `visible=false` 的遗留节点，关闭只能点遮罩，键盘/返回键没有绑定。
- 随机模式不做历史回溯，连续随机可能重复出现同一首（只是不相邻）。
