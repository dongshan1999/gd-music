| 文档日期 | 2026-10-27 |
| 对应代码版本 | develop @ 91d939d（工作区 2026-10-27） |
| 功能分类 | 设置页 / 音源插件 |
| 覆盖范围 | `views/settings/music_app_plugin_management_view.gd`、`views/settings/music_app_plugin_management_item.gd`、`controllers/music_app_plugin_management_controller.gd`、全局 `MusicAppPluginController` 的插件安装/卸载/启停、`settings/music_app_plugin_file_picker_*`（导入选文件） |

> 一句话定位：插件管理是「已装插件列表 + 启停开关 + 登录入口 + 本地导入」的设置子页；插件本体由全局 `MusicAppPluginController` 统一安装到 `user://gdmusic_plugins`，本页只负责展示与转发。

## 1. 功能概述

- 用户视角：设置页点「插件管理」进入。页面从上到下是返回键、标题栏（右侧 `MoreButton`）、状态文案、插件列表（每行＝插件名 + 启用开关 + 登录按钮）、空态文案、底部「安装 / 更新」面板；右下角有一个浮动 `+` 按钮用于展开/收起安装面板。安装面板里有「从文件安装」「从 URL 安装」「全部更新」「更新订阅」四个按钮。
- 实现视角：`MusicAppPluginManagementView`（255 行）只做行池化渲染与按钮分发；`MusicAppPluginManagementController`（88 行）是薄封装，全部转调自动注入的 `MusicAppPluginController`；真正的目录扫描、脚本校验、拷贝、SAF 导入都在全局控制器里。
- **与任务描述的偏差（以真实代码为准）**：
  - **没有拖拽排序，也没有上移/下移按钮**。列表顺序由 `list_plugins()` 一次性按插件名排序决定（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:84`，比较函数 `_sort_plugin_payloads` 在 `:779-782`，`name.naturalnocasecmp_to(...)`），UI 侧没有任何顺序操作入口。
  - **导入的不是 `.zip` 插件包**，而是 `.gd` 脚本文件或包含 `plugin.gd` 的目录（`install_plugin_from_file()`，`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:135`）。没有解压逻辑，`PLUGIN_IMPORT_TEMP_DIR` 只是校验用的暂存目录。
  - **没有删除按钮**。`uninstall_plugin()` 已实现（`:91`），但列表行场景只有名字、开关、登录按钮，没有删除入口。
  - **没有来源标记与元信息展示**。`install_mode`（`builtin` / `local_file` / `android_tree`）只存在于控制器内部字典，`builtin` 字段虽被序列化进 payload，UI 未渲染；版本、作者、描述也不展示。

| 入口 | 触发位置 | 处理函数 |

| 从文件安装 | `:139` | Android 走 SAF 目录选择，其余平台打开文件选择页（`PopupId.MUSIC_APP_PLUGIN_FILE_PICKER`） |
| 从 URL 安装 | `:218` | 直接提示 `install.url_unavailable`（底层固定失败） |
| 全部更新 / 更新订阅 | `:225` `:229` | `show_update_placeholder()` 占位提示 |
| 行内开关 | `:233` | `set_plugin_enabled()` |
| 行内「登录账号」 | `:243` | 打开 B 站登录弹窗，关闭后重新拉列表 |
| 文件选择页回传 | `:254` | `_on_plugin_file_picked(path) → _install_plugin_from_path()` |

一次「刷新列表」的链路：

1. `refresh()` 只同步空态与启动状态，真正的加载 `call_deferred("_reload_plugins_deferred")`（`:61-62`），避免在 `on_popup_shown` 里同步做磁盘扫描与网络请求。
2. `_reload_plugins_deferred()`（`:64`）先 `ensure_plugins_ready()` → 全局 `refresh_plugins()`（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:32`，重新扫描内置插件 + `user://gdmusic_plugins` 子目录 + Android SAF 插件）。
3. 失败则清空列表并把 `last_error` 写进状态栏（`:70-77`）；成功则 `list_plugins()` 拿排序后的数组，状态先显示「正在检查插件登录状态…」。
4. `await _refresh_login_states()`（`:118`）逐个对「支持登录且已启用」的插件 `await refresh_login_state()`（网络请求 `fetch_login_status`）。
5. 最后状态栏显示 `music_app.plugin_management.status.loaded_count`，参数 `{count}`（`:91-94`）。

## 3. 核心数据结构

插件 payload（`_build_plugin_payload`，`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:452`，序列化在 `:481`）：

| 字段 | 含义 | 来源 |
| --- | --- | --- |
| `id` | 插件唯一 id，等于 `get_platform()` 返回值 | `:461` 附近 |
| `name` / `version` / `author` / `description` | 展示与排序用元信息 | `get_plugin_name()` 等 |
| `supportedSearchType` / `defaultSearchType` | 搜索类型声明，插件浏览器据此建 tab | 插件方法 |
| `hasSearch` / `hasGetMediaSource` / `hasGetLyric` / `hasGetTopLists` | 能力布尔位 | `_supports_plugin_method()`（`:772`） |
| `path` / `dir` / `srcUrl` | 列表展示用的路径 / 安装目录 | 加载时记录 |
| `builtin` | 是否内置（`install_mode == "builtin"`） | `:481` 段 |
| `enabled` | 是否启用 | `is_plugin_enabled()`（`:304`） |
| `supports_login` | 是否实现 `fetch_login_status` | `has_method` 判断 |
| `logged_in` | 登录态缓存（`_login_states`） | `get_cached_login_state()`（`:497`） |

插件设置存档（`assets/scripts/save/music/music_plugin_settings_data.gd`）：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `disabled_plugin_ids` | `Array[String]` | **停用列表**（不是启用列表），默认全部启用 |
| `android_tree_plugins` | `Array[Dictionary]` | Android SAF 导入的插件记录：`{plugin_id, tree_uri, relative_path}` |
| `plugin_cookies` | `Dictionary` | 插件登录凭据，`plugin_id -> "k=v; k=v"`，只落本地存档 |

目录约定：

| 路径 | 说明 |
| --- | --- |
| `user://gdmusic_plugins/<插件id>/plugin.gd` | 用户插件安装目录，入口文件名固定 `plugin.gd`（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:4-5`） |
| `user://temp/gdmusic_plugin_import` | 导入前的脚本暂存目录（`:6`） |
| `user://save/data.json` | DX 存档根，内含 `music` 与 `music_plugins`（`dx/runtime/scripts/managers/save/save_data.gd:6-7`） |

## 4. 关键实现

### 4.1 加载顺序：内置先装，用户同名可覆盖

`refresh_plugins()` 先 `_plugins.clear()`，再按 `BUILTIN_PLUGINS` 顺序以内置脚本建条目（`install_mode = "builtin"`），然后遍历 `PLUGIN_ROOT_DIR` 的子目录加载 `plugin.gd`（`install_mode = "local_file"`）写进同一个字典，最后 `_load_android_tree_plugins()`（`:696`）。三者都以插件 id 为 key，后写的覆盖先写的 —— 这正是注释说明的意图：

```gdscript
# User installations may override a bundled plugin; removing the override restores it.
```

即「用户装的同名插件顶掉内置插件，卸载后内置插件自动回来」，不需要额外的优先级字段。单个插件加载失败只 `push_warning` 并继续（`:59-62`），不让一个坏插件拖垮整张列表。

### 4.2 列表行池化 + 登录态二次刷新

`_sync_plugin_items()`（`:96-116`）按需 `instantiate` 行、多余的 `queue_free()`，再逐行 `configure(plugin, enabled)` 并补一个 `logged_in` 键（来自 `get_cached_login_state()`）。行组件 `music_app_plugin_management_item.gd` 的 `configure()`（`:17`）只做三件事：标题取 `name`（空则回退 `id`）、`set_pressed_no_signal(enabled)` 避免回填勾选时触发 `toggled` 信号、`login_button.visible = supports_login and enabled and not logged_in`。

登录按钮的可见性注释写明了取舍：`# 已登录就不用再显示「登录账号」，避免状态自相矛盾`。网络请求与 UI 分离：`_refresh_login_states()` 只对 `supports_login and enabled` 的插件发请求（`:118-125`），禁用的插件不花这个网络往返。

### 4.3 启停：停用列表

`set_plugin_enabled()`（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:310`）先把插件 id 从 `disabled_plugin_ids` 里 `erase`，再在 `enabled == false` 时 `append` 并 `normalize()`。用「停用列表」而不是「启用列表」的理由是：新装插件无需任何写入即默认启用，存档里也只会记录用户真正关掉的那些。`is_plugin_enabled()` 就是一句 `not settings.disabled_plugin_ids.has(id)`（`:304`）。

### 4.4 导入：先校验再落盘

统一入口 `install_plugin_from_file(plugin_path)`（`:135`）：解析绝对路径 → `_collect_plugin_script_paths()`（`:634`）把「单文件」和「目录递归」归一成脚本列表 → 每个脚本先 `_stage_plugin_script_for_validation()`（`:790`）拷到暂存目录试装载 → 通过后 `_copy_plugin_script_absolute()`（`:784`）拷进 `PLUGIN_ROOT_DIR/<插件id>/`。校验失败会 `_summarize_install_failures()`（`:290`）汇总，最多列 3 条，其余折叠成 `| ...and N more.`，避免错误弹窗无限长。

校验的硬性要求来自 `_validate_plugin_instance()`（`:439`）：必须实现 `get_platform()` 与 `get_supported_search_types()`，失败文案分别是 `Plugin file does not provide a get_platform() method.` / `... get_supported_search_types() ...`。这两条是插件 id 与搜索 tab 的数据来源，缺了就没法进列表。

Android 是另一条路径：`_on_install_from_file_pressed()` 在 Android 上不走文件选择页，而是 `DisplayServer.file_dialog_show(..., FILE_DIALOG_MODE_OPEN_DIR, ...)` 调系统 SAF 目录选择（`:152-167`），拿到的 tree uri 交给 `install_plugin_from_android_tree()`（`:219`）。这条路径不拷贝文件，而是持久化 `persist_uri_permission` 并把 `{plugin_id, tree_uri, relative_path}` 记进 `android_tree_plugins`，之后由 `_load_android_tree_plugins()` 直接按 uri 装载。

### 4.5 卸载：内置插件拒绝、SAF 插件删记录

`uninstall_plugin()`（`:91`）的顺序值得注意：先 `refresh_plugins()` 拿到最新条目，再按 `install_mode` 分叉 —— `builtin` 直接 `_fail("内置插件不能卸载，可通过开关停用。")`；`android_tree` 只移除 `android_tree_plugins` 里对应记录并 `normalize()`；其余情况才 `_remove_directory_recursive_absolute(plugin_dir)`（`:811`）。三条分支最后都会 `refresh_plugins()` 并把插件 id 从 `disabled_plugin_ids` 里清掉，避免「删了但停用列表残留」，重装后变成默认禁用。

### 4.6 安装面板与占位按钮

`InstallPanel` 默认隐藏，由 `_toggle_install_panel()` 切 `visible`（`:136-137`）；点「从文件安装」时先收起面板再打开选择页/SAF 选择器（`:140`），避免浮层面板挡住文件列表。四个按钮里只有「从文件安装」是真实链路，`_on_install_from_url_pressed()` 直接弹 `install.url_unavailable`（插件安装自 URL 在底层就是固定失败，见 `assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:131-132`），两个更新按钮走 `show_update_placeholder()`（`assets/scripts/ui/music_app/controllers/music_app_plugin_management_controller.gd:87`）。

### 4.7 登录弹窗的入场与收尾

`_on_plugin_login_requested()`（`:243-252`）做三件事：通过 `popup_router.show_popup(POPUP_ID)` 打开登录弹窗、`popup.setup(_controller, _plugin_management_controller)` 注入两个控制器、把 `tree_exited` 连到 `_request_reload()`。注释解释了最后一句：`# 弹窗关掉后重新拉一次列表，登录状态和按钮才会跟着变`。因为登录成功后 `plugin_cookies` 与 `_login_states` 变了，但本页不会收到通知，只能靠弹窗销毁这个事件兜底刷新。

## 5. 边界与失败处理

| 情形 | 行为 |
| --- | --- |
| 全局控制器未就绪 | `ensure_plugins_ready()` 失败，清空列表，状态栏显示 `last_error` 或 host 不可用文案（`assets/scripts/ui/music_app/views/settings/music_app_plugin_management_view.gd:67-72`） |
| 一个插件都没有 | `empty_label.visible = _plugins.is_empty() and not _is_loading`（`:57`） |
| 单个插件脚本损坏 | 跳过该插件并 `push_warning`，其它插件照常（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:59-62`） |
| 导入路径为空 / 不存在 | `install_plugin_from_file()` 返回空字典 + `last_error`，视图弹 `install.local_failed` 并把错误拼进文案（`:183-197`） |
| 导入脚本缺少约定方法 | 校验失败，原因进 `install_failures`，最终以 `...and N more.` 截断展示 |
| Android 不支持 SAF | 弹「Current Android runtime does not support native SAF directory picker.」（`:155-158`） |
| URL 安装 | 恒失败，提示 `install.url_unavailable` |
| 卸载内置插件 | 后端拒绝，提示「内置插件不能卸载，可通过开关停用。」 |

## 6. 相关测试

无自动化测试覆盖。手工验证建议：

1. 打开插件管理，确认列表按名称排序、内置 bilibili 在列、开关初始为勾选。
2. 关掉 bilibili → 关闭设置页再进入，确认开关仍是关闭（写入 `disabled_plugin_ids`）。
3. 未登录时行内有「登录账号」，登录成功后返回列表，确认该按钮消失、状态栏计数刷新。
4. 点「从文件安装」选一个 `.gd` 插件脚本，确认安装后出现在列表；再选一个普通文本文件，确认提示失败且列表不变。
5. 桌面端点「从 URL 安装」「全部更新」，确认只是占位提示，不发起请求。

## 8. 已知限制与后续

- 缺少排序能力：没有拖拽、没有上移/下移，顺序固定为插件名升序；如果产品需要「常用在前」，要么加 `order` 字段进存档，要么在 UI 上接排序按钮。
- 缺少删除入口：`uninstall_plugin()` 已在后端完整实现（含内置保护与 SAF 分支），但列表行没有入口，目前只能靠脚本调用。
- 缺少来源标记：`install_mode` / `builtin` 已进 payload，行组件却不渲染；用户无法区分「内置」与「自己导入的」。
- 无元信息展示：版本、作者、描述、能力位（`hasSearch` 等）都在 payload 里，界面只显示名字。
- 只支持 `.gd` 单文件/目录导入，不支持 `.zip`；没有签名、没有版本比对，导入后无法自动更新（两个「更新」按钮都是占位）。
- `MoreButton`（场景 `assets/scenes/ui/music_app/settings/music_app_plugin_management_page.tscn:75`）与外层 `More` 容器没有任何点击处理，是预留节点。
- 插件管理页文案中英混排（`Downloading URLs are not supported...`、`Current Android runtime does not support native SAF directory picker.` 等直接内联英文），未接入翻译表。
