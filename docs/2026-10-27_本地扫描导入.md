# 本地扫描导入（功能实现文档）

| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | 应用界面 / 数据存档 |
| 覆盖范围 | SAF/桌面目录选择、内置扫描页目录浏览与勾选、递归扫描与去重、文件名解析生成曲目、歌词关联、扫描目录持久化、失败处理 |

> 一句话定位：扫描导入把「磁盘上的音频文件」转成 `TrackData` 追加进存档：文件路径是唯一身份，标题/歌手从文件名解析，歌词取同目录同名文件，重复路径直接跳过；没有任务队列、没有进度条，扫描是一次可让出主线程的协程。

## 1. 功能概述

用户视角目前只有一条入口：**系统目录选择**——本地音乐页点「导入音乐」或菜单里的「添加扫描文件夹」，弹出系统文件选择器，选中一个目录后直接开始扫描。

内置扫描页（`MusicAppLocalScanView`）实现了完整的目录浏览、勾选与「开始扫描」流程，控制器里也留了 `open_scan_page()`，但当前没有任何界面调用它（全仓库无调用方），用户暂时进不到这一页。下文仍按代码把它的实现记录下来，方便后续接线。

扫描完成后弹窗提示「扫描完成，新增 N 首本地音乐」；没有新曲目则提示「未找到音乐」。

实现视角：

- 所有文件访问都走 `DX.files`（`to_virtual_path / exists / list_dir / pick_directory`）而不是 `DirAccess`，因为 Android 上曲库在 SAF 里，真实路径不可直接读（`dx/runtime/scripts/managers/files/file_manager.gd:51`、`:172`、`:206`、`:522`）；
- 扫描递归目录、过滤扩展名、按 `file_stem` 关联歌词，先收集到内存数组，最后一次 `append` 进 `tracks`；
- 扫描与导入结果通过 `MusicAppLocalMusicController.import_local_folders()` 落地：写 `local_music_folders`、跑扫描、`normalize()` 全存档、`save(false)`。

与任务描述的偏差（以代码为准）：

| 描述 | 实际 |
| --- | --- |
| 扫描任务队列与进度 | 没有任务队列、没有进度回调；`scan_local_music_directories()` 一次协程跑完，期间只按 16ms 预算让出帧，UI 上没有任何进度展示 |
| 读取音频文件元数据 | 不读标签。标题/歌手由文件名解析，`duration` 硬编码 180，`preview_start` 恒为 0 |
| 目录权限持久化 | 选中的目录存进 `local_music_folders`，但**不会**在启动时自动重扫；仅「删除某个目录」时会用剩余目录重扫一次 |

## 4. 关键实现

### 4.1 为什么全程用 DX.files

Android 的曲库在 Storage Access Framework 里，应用拿到的是 `content://` 或框架自己的虚拟树 URI，`DirAccess` 与 `FileAccess` 无法直接读。DX 的文件管理器把这些 URI 统一成 `to_virtual_path()` 的虚拟路径，并提供 `exists()`、`list_dir()`：

```gdscript
var list_result: Dictionary = DX.files.list_dir(normalized_root)
if not bool(list_result.get("ok", false)):
	stats["invalid_targets"] = int(stats["invalid_targets"]) + 1
	return
```

`list_dir()` 返回 `{ok, entries: [{name, path, native_path, is_dir}], error}`。扫描器只信 `path`，`path` 为空时才退回 `native_path`（:204-206），这样在 SAF 与桌面两种环境下拿到的是同一套可持久化路径。

### 4.2 扫描根与盘符

`get_scan_root_path()`（:28-43）：Android 依次探测 `/storage/emulated/0`、`/sdcard`、`/storage/self/primary`，都不可用则回到 `/`；Windows 用 `windows://drives` 虚拟根（Godot 没有枚举盘符的 API，只能自造）；其他平台取 `USERPROFILE` → 文档目录 → `res://` 的 `path_root()`。

`list_windows_drive_entries()`（:93-107）在虚拟根下逐个探测 `X:/` 是否存在，拼出 A–Z 盘符；`get_scan_parent_path()`（:53-68）保证向上导航不越过根：盘符根回虚拟根，其余根目录回根自己。

### 4.3 扫描主循环：先收集，最后一次性入库

`scan_local_music_directories()`（:111-151）的步骤：

1. 用全库现有 `file_path` 建 `existing_paths` 集合（:114-118），这是去重的依据；
2. 对每个目标目录 `await _collect_audio_tracks(...)`，结果写入 `imported_tracks`；
3. 全部结束后才逐首 `tracks.append(track)`（:145-146），并回填 `stats["imported"]`（:147）。

为什么最后才 append：扫描可能持续数秒，如果边扫边入库，列表页、歌单、播放队列会在中途看到「半成品」数据，`normalize()` 也可能被其它流程触发导致计数字段抖动。先收集后入库让「一次扫描 = 一次原子变更」。

同一目标目录重复传入时用 `unique_targets` 去重（:131-136），避免用户勾选父目录又勾选子目录时重复遍历。

### 4.4 分帧让出：按时间预算而不是文件数

```gdscript
func _maybe_yield() -> void:
	if Time.get_ticks_msec() - _last_yield_msec < FRAME_YIELD_BUDGET_MSEC:
		return
	_last_yield_msec = Time.get_ticks_msec()
	await _yield_frame()
```

每个目录项与每个音频文件处理前都会调一次 `_maybe_yield()`（:212、:225）。注释写明了取舍：按时间而不是按文件数让出，是因为真机 SD 卡/SAF 的 I/O 延迟不可预测——固定「每 100 个文件让一次」在一批大文件上仍可能卡住几百毫秒，按 16ms 预算则无论文件多大都能保证输入与绘制有机会执行。

`_yield_frame()`（:161-168）优先用 showcase 的 `SceneTree`，拿不到再退回 `Engine.get_main_loop()`，因此扫描器也能在非 UI 环境（测试/工具）里跑。

### 4.5 递归、歌词关联与死循环防护

`_collect_audio_tracks()`（:171-246）：

- `visited_dirs` 记录已进入的目录（:179-181）。SAF 树与符号链接都可能出现「子目录指回父目录」，没有这个集合会无限递归；
- 先遍历一遍目录项：目录直接递归，歌词文件收进 `lyric_paths_by_stem`（键为小写 `file_stem`），其它文件进 `file_entries`（:194-217）；
- 再处理 `file_entries`：扩展名命中且未重复才生成曲目，歌词取同目录同名的那个（:225-247）。

先收歌词再建曲目，是为了避免「音频比歌词先出现」时漏关联；而 `make_local_track_from_path(..., lookup_lyric=false)`（:253-255 注释）则是为了性能：目录扫描已经汇总好歌词，逐首再调 `DX.files.exists()` 在 Android SAF 上每首都要走一次 JNI/跨进程查询，几百首就是几秒。单曲导入（`lookup_lyric=true`）时才会去 `find_lyric_path_for_audio()`（:320-327）现找。

### 4.6 文件名解析

`parse_track_name()`（:297-317）支持两类常见命名：

| 形式 | 示例 | 解析 |
| --- | --- | --- |
| `歌手 - 歌名` | `张韶涵 - 香水百合.mp3` | 以 ` - ` 切分，前段歌手、后段歌名 |
| `来源@ID@歌名@歌手` | `元力QQ@100380@香水百合@张韶涵` | 以 `@` 分段，取倒数第 2 段歌名、最后一段歌手 |
| 其它 | `track01` | 整串作标题，歌手为空 |

扫描器读不到音频标签，文件名是唯一可用信息；两种格式覆盖了从音乐平台与 B 站抓取的文件的主流命名。解析失败也不报错，宁可标题难看也不要漏导入。

### 4.7 去重只看路径

去重集合里存的是 `normalize_path(file_path)`（:354-358：反斜杠转斜杠、去尾斜杠、合并重复分隔符），扫描到的文件路径同样归一化后比较（:232-235，命中即 `duplicates += 1`）。为什么不按 `track.id` 去重：ID 要等 `track.normalize()` 才生成，而扫描阶段曲目对象还没有；且本地曲目的 ID 本身就是 `file_path` 的 SHA-256（`assets/scripts/save/music/track_data.gd:32-36`），路径一致 ID 必然一致。

同一批扫描内部也会把已生成的路径写回 `existing_paths`（:236），所以勾选父目录与子目录也不会重复。

### 4.8 落地：谁保存、什么时候归一化

`MusicAppLocalMusicController.import_local_folders()`（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:247-282`）是唯一的保存入口：

1. `_is_importing` 防重入，把本次目标目录并入 `local_music_folders` 并 `_save_music_state()`（默认只标脏，不强制落盘）——先保存目录，扫描中途退出也不会丢「这个目录被授权过」；
2. `MusicAppLocalScanController.new(self).scan_local_music_directories(paths)`；
3. `get_app_state().normalize()` 重算曲目索引、歌单 `count`、播放队列，然后再 `save(false)`。

第 3 步不能省：新增曲目后歌单计数、`tracks` 的索引缓存、`playback_state.track_ids` 都依赖归一化保持一致。

## 5. 边界与失败处理

| 场景 | 处理 | 位置 |
| --- | --- | --- |
| 目录无法列出（权限/已卸载） | `invalid_targets += 1`，跳过该目录，其余继续 | `assets/scripts/ui/music_app/controllers/music_app_local_scan_controller.gd:183-190` |
| 目录自引用或 SAF 回环 | `visited_dirs` 去重，重复进入直接返回 | `:179-181` |
| 没有音频 / 全部重复 | 扫描返回 0（`duplicates` 单独计数），扫描页提示「未找到音乐」后关闭 | `assets/scripts/ui/music_app/views/local_scan/music_app_local_scan_view.gd:158-164`、`assets/scripts/ui/music_app/controllers/music_app_local_scan_controller.gd:232-235` |
| 在虚拟根就点开始 | 未勾选且处于根目录时提示「请先进入一个磁盘，或勾选要扫描的目录」 | `assets/scripts/ui/music_app/views/local_scan/music_app_local_scan_view.gd:145-152` |
| 扫描中页面被关 | `await` 返回后检查 `is_inside_tree()`，不在树上就放弃弹窗与回调 | `assets/scripts/ui/music_app/views/local_scan/music_app_local_scan_view.gd:155-156` |
| 重复触发导入 | `_is_importing` 直接返回，避免两次扫描并发写 `tracks` | `assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:248-250` |
| 系统选择器取消 | `_on_native_import_directory_picked` 判 `cancelled` 后直接返回 | `assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:125-130` |
| 下载缓存目录 | 跳过 `.DS_Store`、`__MACOSX`、`System Volume Information`、`$RECYCLE.BIN` 与所有 `.` 开头的项 | `assets/scripts/ui/music_app/controllers/music_app_local_scan_controller.gd:368-371` |

## 6. 相关测试

`assets/tests/music_app/` 下没有扫描导入的自动化测试。扫描器依赖真实文件系统与 SAF，单测需要注入 `DX.files` 假实现，目前没有做。

手工验证建议：

1. 桌面端选一个含子目录的文件夹，确认递归导入且同名 `.lrc` 被关联；再扫同一目录，确认「未找到音乐」且曲目数不变；
2. 扫描页在根目录直接点「开始扫描」，确认提示而不是扫描整个盘；勾选父子重叠的目录，确认结果不重复；
3. Android 上选 SAF 目录，确认路径持久化后重启应用仍显示在 chips 里；
4. 扫描过程中返回上一页，确认不崩溃、不弹窗。

## 8. 已知限制与后续

- 没有进度与取消。大目录扫描期间用户只能等，且无法中止；后续可以在 `_collect_audio_tracks` 里加进度回调与取消令牌。
- 不读音频标签，标题与歌手全部来自文件名；`duration` 固定 180 秒，与本地音乐页共享同一问题。
- 不自动重扫，结果只追加不更新：`local_music_folders` 只是「授权记录」，文件在外部移动后列表会保留失效路径，只能手动删目录或重新导入。
- 内置扫描页没有接线：本地音乐页两个按钮都进系统选择器，`open_scan_page()` 没有调用方，页面代码暂时是「可运行但到不了」。
- 系统选择器一次只能选一个目录；多目录批量导入要等内置扫描页接线后才能用。
