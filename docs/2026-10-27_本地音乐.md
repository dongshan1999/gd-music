# 本地音乐（功能实现文档）

| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | 应用界面 / 数据存档 |
| 覆盖范围 | 本地音乐列表页、虚拟滚动、扫描文件夹 chips、本地曲目判定与播放、与扫描导入入口的衔接 |

> 一句话定位：本地音乐页是「存档的只读视图」：曲目全部由扫描导入写进 `tracks`，页面只做筛选、虚拟滚动与触发播放；它不解析文件、不检测目录变化，也不做分组视图。

## 1. 功能概述

用户视角：

- 首页「本地音乐」入口进入列表页，顶部是「扫描文件夹」面板，横向排列已加入的目录 chip（`文件夹名 ×`），点 × 会移除该目录并清掉它下面的曲目；
- 面板里的「导入音乐」与菜单里的「添加扫描文件夹」都走系统目录选择器（一次选一个目录）；内置扫描页虽然实现了，但当前没有接线，见 [本地扫描导入](2026-10-27_本地扫描导入.md)；
- 主题曲目列表显示「序号、标题、副标题（艺术家 - 文件夹名 · 来源）」；点任意一行，以当前列表顺序作为播放队列并跳到播放器页；
- 列表为空时显示两行引导：「暂无本地音乐」「点击右上角添加扫描文件夹」。

实现视角：

- 「本地曲目」不是按 `source` 判断，而是 `file_path` 非空 **或** `source == "LOCAL"`（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:27-35`）；
- 列表用固定行高的虚拟滚动：只实例化「视口能看到的行 + 上下各 4 行」，曲库上千首时内存与建行耗时都是常数级（`assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:84-132`）；
- 页面不持有自己的曲目数组，每次刷新把 `get_local_track_ids()` 的结果存进 `_visible_track_ids`，播放时把这个数组整体交给播放队列。

与任务描述的偏差（以代码为准）：

| 描述 | 实际 |
| --- | --- |
| 按文件夹 / 专辑分组 | 没有分组视图。文件夹信息只体现在顶部 chips 与每行副标题里的文件夹名 |
| 播放全部 / 随机播放按钮 | 没有这两个按钮。点任意行 = 以全部可见曲目为队列并从该行开始播；「随机」由全局播放模式提供 |
| 与扫描导入的关系 | 本页只读存档；导入逻辑在 `MusicAppLocalScanController`，本页只负责选目录和跳转 |

## 3. 核心数据结构

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| `local_music_folders` | `assets/scripts/save/music/music_app_state_data.gd:22` | 已加入的扫描目录，持久化；归一化时去重、去尾斜杠（`:183-192`，`_normalize_path_array`） |
| `_visible_track_ids` | `views/local_music/music_app_local_music_view.gd`（刷新时生成） | 当前列表顺序的曲目 ID，播放时直接作为队列 |
| `TrackData` 本地约定 | `assets/scripts/save/music/track_data.gd:4-15` | `source="LOCAL"`、`file_path` 必填、`lyric_path` 可空、`subtitle` 存文件夹显示名、`duration` 扫描时硬编码 180 |

行高常量（`assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:8-12`）：

| 常量 | 值 | 用途 |
| --- | --- | --- |
| `ROW_HEIGHT` | 72.0 | 必须与 `local_music_row.tscn` 里行节点高度一致 |
| `ROW_GAP` | 8.0 | 行间距 |
| `ROW_STRIDE` | 80.0 | `ROW_HEIGHT + ROW_GAP`，滚动位置换算的唯一依据 |
| `OVERSCAN_ROWS` | 4 | 视口上下各多建 4 行，避免快速滚动露白 |

## 4. 关键实现

### 4.1 本地曲目的判定

```gdscript
func get_local_track_ids() -> Array[String]:
	for track in get_tracks_ref():
		if not track.file_path.strip_edges().is_empty() or track.source == "LOCAL":
			result.append(track.id)
```

只按 `source == "LOCAL"` 判断会漏掉两类曲目：旧版本存档里没有写 `source` 的本地曲，以及插件曲目下载到本地后只补了 `file_path` 的情况。用「有文件路径」作为兜底条件，列表始终能覆盖所有可离线播放的曲目（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:27-35`）。

### 4.2 虚拟滚动

`_refresh_visible_rows()`（`assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:84-120`）每次滚动只做一件事：按 `scroll_vertical / ROW_STRIDE` 算出首个可见槽位，保留 `ceil(视口高 / ROW_STRIDE) + OVERSCAN_ROWS * 2` 个行，其余 `queue_free()`。

三个细节决定了它不会错位：

1. `local_music_list.custom_minimum_size.y` 被设置为「总行数 × 步长 − 行距」，滚动条长度才对；
2. 视口高度取 `max(scroll.size.y, ROW_STRIDE * 8)`，页面还没布局完时（`size.y == 0`）不会算出 0 行；
3. `first_slot` 会 `clamp` 到 `[0, total - visible_count]`，滚到底部时行池不会越界。

行高常量必须与场景一致，代码注释专门写明了这一点：改 `.tscn` 行高却忘了改 `ROW_HEIGHT`，表现是滚动到某处后行内容互相覆盖或跳行。

### 4.3 播放：以「当前列表」为队列

```gdscript
func _play_track(slot_index: int) -> void:
	if slot_index < 0 or slot_index >= _visible_track_ids.size():
		return
	_controller.play_local_track_list(_visible_track_ids, slot_index)
```

控制器（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:42-46`、`:117-123`）先把 ID 列表整单设为播放队列，再 `play_queue_index(slot)`，最后打开播放器页。这样用户在列表里点第 5 首，队列就是列表的完整顺序，播放器「下一首」自然接着列表走。

没有「播放全部」按钮也是同一套逻辑：`slot = 0` 就是播放全部；没有「随机播放」按钮，因为随机是全局播放模式（`PlaybackMode.SHUFFLE`），在队列推进时生效，而不是本页的一个动作。

### 4.4 扫描文件夹 chips

`_refresh_folder_chips()`（`assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:171-187`）从 `local_music_folders` 取路径，显示名来自 `get_folder_display_name()`（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:17-24`）：

- 优先取路径最后一段；
- 遇到 SAF 虚拟路径（`saf-tree://.../document/primary:Music#Music/Album`）时取 `#` 之后的部分再取最后一段，并去掉 `primary:` 这类卷标冒号前缀——直接显示完整虚拟路径在手机上一行放不下。

`_create_folder_chip()`（:189-206）是纯代码创建 `Button`：文本「显示名 ×」、tooltip 显示完整路径、圆角 `StyleBoxFlat`，`pressed` 直接绑到 `_remove_local_folder()`。

### 4.5 移除扫描目录

`remove_local_folder(folder_path)`（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:90-114`）的顺序是刻意安排的：

```
若正在导入 → 直接 return（避免扫描与删除并发）
→ local_music_folders.erase(path)
→ _remove_local_tracks_under_paths([path])      # 先删曲目
→ await _rescan_saved_local_folders(path)        # 再按剩余目录重扫
→ _save_music_state()                     # 默认 force 为假，只标脏
```

先删曲目再重扫，是为了让「删除目录」这件事立刻生效；重扫其余目录则用来回收因目录移动/改名而失效的路径，保证列表与磁盘一致。

路径匹配 `_is_track_under_any_folder()`（:332-341）不是简单 `begins_with`：SAF 虚拟路径形如 `saf-tree://.../primary:Music#Music/Album`，同一物理目录可能以带 `#` 与不带 `#` 两种形式出现，所以除了 `folder/` 前缀，还额外判断 `folder#` 前缀（同一 SAF 目录的 document 片段写法）。

`_remove_local_tracks_under_paths()`（:307-330）用 `tracks.assign(kept)` 原地替换，而不是给 `tracks` 赋新数组——歌单、播放队列、其它控制器都持有原数组引用，换数组会让它们继续看到已删除的曲目。

### 4.6 两条导入路径

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| 系统目录选择 | `open_native_import()`（`assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:49-72`） | `DX.files.pick_directory()` 选择单个目录，回调里转成虚拟路径后调用 `import_local_folders()` |
| 内置扫描页 | `open_scan_page()`（:75-83） | 打开 `MUSIC_APP_LOCAL_SCAN`，可浏览目录树、勾选多个目录后统一扫描；**当前无调用方**，UI 上到不了 |

导入完成后通过 `set_finished_callback()` 回到本页 `refresh()`（`assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:163-165`）。`_is_native_import_open` 与 `_is_importing` 两个标志分别防止「系统选择器重复打开」和「扫描期间再次触发导入」。

## 5. 边界与失败处理

| 场景 | 处理 | 位置 |
| --- | --- | --- |
| 曲库为空 | 两行空态文案，列表最小高度 180 防止塌陷 | `assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:64-67`、`:88-90` |
| 没有扫描目录 | 文件夹面板整体隐藏 | `assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:179` |
| 导入进行中移除目录 | 直接返回，不并发改数组 | `assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:91-93` |
| 目录下没有曲目 | 只移除目录并重扫，无报错 | 同上 `:96-108` |
| 点行越界 / 列表为空 | 下标检查后 return | `assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:142-146` |
| 窗口尺寸变化 | `resized` 信号重新计算可见行，防止行池错位 | `assets/scripts/ui/music_app/views/local_music/music_app_local_music_view.gd:137-140` |
| 文件路径过长 | chip 只显示末段，完整路径放 tooltip | `assets/scripts/ui/music_app/controllers/music_app_local_music_controller.gd:351-360` |

## 6. 相关测试

`assets/tests/music_app/` 下没有本地音乐页的自动化测试；`music_app_ui_test.gd` 只做列表行场景的构建冒烟。

手工验证建议：

1. 扫描导入 200+ 首，快速上下滚动，确认行内容不串位、不闪白；
2. 点第 10 首，确认播放器队列长度等于列表长度，下一首是列表第 11 首；
3. 删除一个扫描目录，确认该目录下曲目消失、其它目录曲目仍在、重启后状态保持；
4. 在文件夹面板点 × 时若正在扫描，确认操作被忽略而不是崩溃；
5. 把窗口拉窄/拉高，确认可见行数量随视口变化。

## 8. 已知限制与后续

- 没有按文件夹/专辑分组的视图，也没有排序与搜索；`music_app.local.search_message` / `edit_message` / `download_message` 三条文案仍在 CSV 里但代码未使用，是早期菜单项留下的残留。
- 没有「播放全部」「随机播放」独立按钮，语义隐含在「点第一行」和全局模式里，新用户不容易发现。
- 列表顺序等于 `tracks` 的全局顺序，扫描新增的曲目追加在末尾，没有按文件夹或标题排序的选项。
- 扫描生成的 `duration` 固定为 180 秒，播放器进度条与实际时长不符，拖到 3 分钟后会被钳制回真实长度。
- 页面不会监听存档变化，外部（扫描页、插件下载）导入后必须重新进入页面才能看到新曲目——当前靠 `set_finished_callback` 补刷新。
