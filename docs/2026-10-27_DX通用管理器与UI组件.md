# DX 通用管理器与 UI 组件（功能实现文档）

| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | DX 框架 / 通用能力与 UI 组件 |
| 覆盖范围 | `dx/runtime/scripts/managers/` 中除 save/files/popup/debug 外的管理器、`dx/runtime/scripts/component/`、`dx/runtime/scripts/effects/`、`dx/runtime/scripts/utility/` |

> 一句话定位：DX 除「存档 / 文件 / 弹窗 / 调试」四条重业务线之外的日常工具箱——配置、时间、事件总线、前后台状态、倒计时、本地化、资源库、对象池、飞入动效、滚动交互，以及两个纯函数工具（二维码、时间格式化）。日志见《DX调试工具》。

## 1. 功能概述

- **用户视角**（开发者）：新页面要「倒计时 / 文案本地化 / 列表滚动 / 列表项飞入」时不需要自己造，`DX.<manager>` 拿来即用。
- **实现视角**：管理器多为 `RefCounted`（logger、pool、popup 是 `Node`，因为要用 `%` 唯一名和 `_process`），由 `DX_Root.register_manager()` 挂到 `DX` 单例，再通过 `dx.gd` 的 `_process` / `_notification` 获得生命周期回调。
- **为什么集中**：这些能力跨页面复用且与业务无关；各自 `new` 会导致「每页一个本地化、倒计时各计时」，时间源不统一时倒计时与存档时间戳会错位。
- **不在本期范围**：没有 `settings` 管理器（`config` 只读 JSON；用户设置存于存档 `music/plugin_settings` 段），没有 `scene` 管理器（页面切换由业务路由承担）。

## 2. 功能入口与调用链

### 2.1 注册顺序（`dx/dx.gd:158-193`）

| 阶段 | 注册项 | 位置 |
| --- | --- | --- |
| `_enter_tree` → `_bootstrap` | time、logger、signals、config、background_state、countdown、save、localization、debug、effect、res、files | `dx/dx.gd:162-174` |
| `_ready` | pool、popup（场景里的节点，不是 `new`） | `dx/dx.gd:108-112`、`:176-194` |

```gdscript
# dx/dx.gd:162-174（节选）
register_manager(MANAGER_TIME, TimeManagerScript.new())
register_manager(MANAGER_LOGGER, LoggerScript.new())
register_manager(MANAGER_SIGNAL, SignalManagerScript.new())
...
register_manager(MANAGER_EFFECT, UiFlyEffectScript.new())
register_manager(MANAGER_RES, ResManagerScript.new())
register_manager(MANAGER_FILES, FileManagerScript.new())
```

顺序不是随意的：`time` 最先（logger 时间戳、save 时间都依赖它）、`logger` 第二（后续注册失败要能打日志）、`config` 在依赖配置的管理器之前；`pool`/`popup` 必须等 `_ready`，因为它们要靠 `%PoolActive`、`%PopupRoot` 找场景子节点。

### 2.2 生命周期派发

| 时机 | 派发 | 管理器方法 |
| --- | --- | --- |
| `_process(delta)` | 正序遍历 `_manager_order` | `in_process(delta)`（`dx/dx.gd:114-116`） |
| 应用暂停/恢复 | `NOTIFICATION_APPLICATION_PAUSED/RESUMED` | `in_pause(paused)`（`:127-130`） |
| 焦点变化 | `NOTIFICATION_APPLICATION_FOCUS_OUT/IN` | `in_focus(has_focus)`（`:131-134`） |
| 语言变化 | `NOTIFICATION_TRANSLATION_CHANGED` | `in_translation_changed()`（`:135`） |
| 退出 | `_exit_tree` / `WM_CLOSE_REQUEST` | 逆序 `in_quit()`，最后清 JSON 缓存（`:118-121`、`:208-214`） |

`in_process` 是自定义派发名而非 Godot 的 `_process`——管理器不必是 Node 也能拿到每帧回调，这是「管理器可用 `RefCounted`」的前提。

## 4. 关键实现

### 4.1 配置：空数据类 + `normalize()` 钩子

```gdscript
# config_data.gd:1-6
class_name DX_ConfigData
extends DX_JsonObject

func normalize() -> void:
	pass
```

`config_manager.load()`（`dx/runtime/scripts/managers/config/config_manager.gd:13-20`）每次都 `new` 新对象再反序列化；文件不存在时 `_load_config_json()` 返回 `""`（`:22-29`），**不报错**。意图：配置是「启动快照」（改 `config.json` 需重启，不做热重载，避免运行中半新半旧）；字段由 JSON 键直接映射，加配置项只需改 JSON + 加字段；`normalize()`（`:31-33`）是唯一校验点，子类可在此补默认值/纠非法值。

### 4.2 时间：可注入的「现在」

| API | 作用 |
| --- | --- |
| `now()` | 返回 `DX_DateTime`（`dx/runtime/scripts/managers/time/datetime.gd:98`），`format()` 默认 `yyyy-MM-dd HH:mm:ss`（`:154`、`:5`） |
| `now_unix()` | 当前 Unix 秒（含调试偏移） |
| `set_time_scale(v)` | 真实流逝 × v，用于倍速验证倒计时 |
| `set_debug_time_scale()` / `clear_debug_time_scale()` | 调试面板用，按需恢复 |
| `set_debug_time_offset_seconds(s)` | 整体平移「现在」，测跨天/过期逻辑 |

业务不直接 `Time.get_unix_time_from_system()` 的原因：倒计时、存档时间戳、日志时间必须**同源**，否则调试加速时三者各走各的；测试时只想移动「现在」而不改系统时钟。底座分两层：`datetime.gd` 是有状态日期对象（`from_unix_timestamp()` `:104`、`parse()` `:128`、`to_iso_string()` `:151`）；`time_utility.gd` 是全静态函数（`now_unix()` `:78`、`start_of_day_unix()` `:131`、`calculate_weekday()` `:154`、`format_datetime_dict()` `:159`），不依赖节点，任何上下文可调。

### 4.3 事件总线：事件是类，不是字符串

```gdscript
# signal_manager.gd:8 / :35
func subscribe(event_class: Variant, callback: Callable) -> void:
func fire(event: Variant) -> void:
```

订阅传**事件类或实例**，内部归一化成类名作 key（`:62-79`）；派发传实例。`DX_AppPauseEvent` / `DX_AppFocusEvent` / `DX_AppBackgroundEvent` 各只有一个字段（`dx/runtime/scripts/managers/signals/events/dx_app_pause_event.gd:4`、`dx/runtime/scripts/managers/signals/events/dx_app_focus_event.gd:4`、`dx/runtime/scripts/managers/signals/events/dx_app_background_event.gd:4`），经 `_init(value)` 构造。用类换来强类型 + 可携带字段 + IDE 跳转，代价是每加一种事件多一个 3 行小文件。回调**同步**执行，不要在回调里做重活或 `unsubscribe` 自己。

### 4.4 前后台：三个信号正交，`is_background` 是聚合结果

`in_pause(true)` fire `DX_AppPauseEvent` 并置 `_potential_*`（`dx/runtime/scripts/managers/background_state_manager.gd:15-32`）；`in_focus()` fire `DX_AppFocusEvent`（`:24`）；聚合后变化时才 fire `DX_AppBackgroundEvent`（`:34`、`:42`）。关键语义：**暂停 ≠ 后台**（分屏/弹通知可能失焦仍在跑），只有暂停且无焦点 `is_background` 才为 true，倒计时据此决定后台是否暂停走时（`dx/runtime/scripts/managers/countdown/countdown_manager.gd:158`）。

### 4.5 倒计时：绝对时间戳是唯一真相

```gdscript
# countdown_manager.gd:31-47（节选）
func start_seconds(id: StringName, duration_seconds: int, destroy_on_complete := true, run_in_background := true) -> Object:
	var end_timestamp: int = dx.time.now_unix() + maxi(0, duration_seconds)
	return start(DX_CountdownInfoScript.new(id, end_timestamp, ...))
```

`DX_CountdownInfo` 只存 `end_unix_timestamp` / `remaining_seconds` / `status`（`RUNNING/PAUSED/COMPLETED`，`dx/runtime/scripts/managers/countdown/countdown_info.gd:4-17`）；每帧 `_refresh_single()`（`:132`）用 `end - dx.time.now_unix()` 重算。不用「每秒自减 1」是因为掉帧/后台/暂停会累积误差，而绝对时间戳即使停 10 分钟恢复后也正确。`run_in_background=false` 时后台不刷新；`destroy_on_complete=false` 时完成后保留条目。`subscribe_update(id, cb, immediate=true)`（`:58`）注册即回调一次，省掉 UI 侧手动初始化。

### 4.6 本地化：`tr` key 绑定 + 语言变化自动刷新

`bind_text(target, tr_key, payload)`（`dx/runtime/scripts/managers/localization/localization_manager.gd:31-49`）登记 `instance_id → 绑定`（一个对象只绑一条）；语言变化由 `dx/dx.gd:135` 广播 → `in_translation_changed()` → `refresh_all()`（`dx/runtime/scripts/managers/localization/localization_manager.gd:68-77`）重刷并清掉已释放对象。`payload` 支持 `Array`（位置参数）/ `Dictionary`（命名参数）（`_format_text()` `:119`、`_duplicate_format_payload()` `:141`）；`text()`（`:28`）是无绑定的即时取文本。枚举只有 `EN/ZH/ZH_CN`（`:6-10`）并映射到 Godot locale code（`:13-22`），**真正的翻译资源仍由 `.translation` 提供**，DX 只负责「绑谁、何时刷、怎么格式化」。

`DX_LocalizeComp`（`dx/runtime/scripts/managers/localization/localize_comp.gd:1-3`，`@tool`）是这套 API 的组件封装：挂到 `Label`/`Button` 父节点，填 `format_args`（`:11`）/`named_format_args`（`:16`），运行时自动 `bind_text`（`:35-57`），编辑器可预览（`refresh_in_editor`，`:21`）。做成 `@tool` 是为了让策划在场景里改文案 key 而不用碰代码；当前业务场景尚未挂载该组件。

### 4.7 对象池：模板节点 + 双根容器 + 5 秒批清理

`%PoolActive` / `%PoolInactive`（`dx/runtime/scripts/managers/pool/pool_manager.gd:8-9`）区分在用/空闲。`init(pool_name, source, max_capacity=100, expiration_seconds=300.0)`（`:20-54`）：`source` 可为 `PackedScene` 或现成 `Node`，后者被 reparent 到 `_inactive_root` 作模板（`:40-44`）。`push` 池满（默认 100）直接 `queue_free` 不无限增长（`:98` 起）；`in_process` 每 5 秒扫一次（`:13-18`）释放空闲超 300s 的节点；`clear()` 不带参数清空所有池与两个根（`:130`）。`pop` 池不存在返回 null，`push` 池不存在则 warning + 直接释放（不泄漏）。

### 4.8 飞入动效：池化 + Tween + 自动归还

`effect.dx_ui_fly_effect.fly(start_position, end_position, fly_source, size, pool_name)`（`dx/runtime/scripts/effects/dx_ui_fly_effect.gd:15-41`）从池 `pop` 节点、设起点/尺寸，Tween 同时做位移与淡出，`await tween.finished` 后 `push` 回池（`:30-40`）。默认池名 `DX_UiFlyEffect`、容量 64、时长 0.45s（`:4-7`），宿主是 `dx` 下 `UI` CanvasLayer（`:7`、`:49-51`）。高频短命动效若每次 `instantiate` 会 GC 抖动，池化 + 固定时长 Tween 保证连点不掉帧。

### 4.9 滚动交互组件：一次实现覆盖四种输入

组件挂在 `ScrollContainer` 的兄弟节点（导出 `scroll_container_path`，`dx/runtime/scripts/component/scroll/scroll_interaction_comp.gd:7`），`_input`（`:61-82`）统一分发：滚轮 `_handle_mouse_wheel()`（`:93`，步长默认 96px，`:8`）、触控板 pan `_handle_pan_gesture()`（`:108`）、鼠标拖拽 `_handle_drag_scroll_button/motion()`（`:119`/`:141`）、触摸拖拽 `_handle_touch_drag_touch/motion()`（`:162`/`:181`）。两个要点：阈值 `drag_scroll_threshold` 默认 8px（`:9`），否则手指微抖会把点击变拖拽；`force_pass_scroll_events`（`:15`）处理后继续下发事件，否则容器吞掉子按钮点击（`_apply_scroll_event_passthrough()` `:84`）。横竖轴由 `enable_horizontal/vertical_scroll` 控制（`:13-14`）并在 `_set_scroll_axis()`（`:215`）里归零无用的轴。

### 4.10 工具函数：零依赖的二维码与时间格式化

| 文件 | 能力 | 关键 API |
| --- | --- | --- |
| `utility/qr_code.gd` | 纯 GDScript 二维码（Reed-Solomon + 掩码惩罚选优） | `encode(text)`（`:61`）、`encode_image(text, pixels_per_module=6, quiet_zone=4)`（`:93`） |
| `utility/time_utility.gd` | 无状态时间计算/格式化 | `now_unix()`（`:78`）、`parse_unix()`（`:81`）、`format_datetime_dict()`（`:159`） |

二维码未引入任何插件（不需要 GDExtension），代价是常量表与掩码评分在脚本里，大版本生成比 C++ 慢；目前只适合「分享/配对」这类低频场景。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| `config.json` 缺失或语法错 | 静默返回空 `DX_ConfigData`，不报错、不抛异常（`dx/runtime/scripts/managers/config/config_manager.gd:22-29`） |
| `subscribe` 传入非事件类 | `_normalize_event_class()` 归一化失败即忽略（`dx/runtime/scripts/managers/signals/signal_manager.gd:62-79`） |
| `unsubscribe` 未订阅的回调 | 静默无操作 |
| `is_background` 抖动 | 仅在聚合状态真正翻转时 fire `DX_AppBackgroundEvent` |
| `start_seconds(id, 0)` / 同 id 重复 `start` | 立即到点走完成回调；重复 start 覆盖原条目 |
| `pool.pop` 池不存在 | warning + 返回 null |
| `pool.push` 池不存在 | warning + `queue_free()` 节点（不泄漏） |
| `pool.init` 的 `source` 非法 | 打 error 返回 false（「source 必须是 PackedScene 或 Node」） |
| 语言不在 `EN/ZH/ZH_CN` 内 | `get_locale_type()` 回退 `DEFAULT_LOCALE`（`ZH_CN`，`dx/runtime/scripts/managers/localization/localization_manager.gd:23`、`:59`） |
| 资源库 id 不存在 | `push_error("DX_ResManager cannot find resource id ...")` 并返回 null（`dx/runtime/scripts/managers/res/res_manager.gd:17-24`） |
| 滚动容器路径未填 | `_ready` 打 error（「requires a valid ScrollContainer path」）并停用（`dx/runtime/scripts/component/scroll/scroll_interaction_comp.gd:33`） |

## 8. 已知限制与后续

- **无 `settings` 管理器**：用户设置走存档 `music/plugin_settings` 段 + `assets/scripts/ui/music_app/controllers/music_app_settings_controller.gd`；DX 层只管只读 `config.json`。
