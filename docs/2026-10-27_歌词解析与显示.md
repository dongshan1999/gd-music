> 一句话定位：歌词能力分两半——`MusicAppLyricParser` 把 LRC/纯文本切成「时间 + 文本」数组，`MusicAppPlayerView` 负责把数组渲染成可滚动、可拖动、随时高亮的行；歌词文本只从曲目的 `lyric_path` 读取，不联网。

## 1. 功能概述

- **用户视角**：在播放器页点封面进入歌词页，当前句加粗高亮并自动居中；上下拖动歌词时出现中央时间游标，松手跳到居中那句；没有歌词时显示「暂无歌词」，点空白回到封面。
- **实现视角**：解析器 `MusicAppLyricParser`（`assets/scripts/ui/music_app/player/music_app_lyric_parser.gd`，`RefCounted`、纯静态函数、无节点依赖）把文本切成「时间 + 文本」数组；展示全在 `MusicAppPlayerView` 的 `_refresh_lyrics_for_track()` / `_rebuild_lyric_lines()` / `_scroll_lyrics_to_line()`（`assets/scripts/ui/music_app/views/player/music_app_player_view.gd:650-813`）；来源只有 `TrackData.lyric_path`，经 `DX.files.read_text()` 读取，兼容 Android SAF 虚拟路径。
- **不在本期范围（与任务描述的偏差，以代码为准）**：
  - **插件歌词未接入**：`MusicAppPluginController.get_lyric()`（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:354-364`）与 `plugin_browser_controller.resolve_track_plugin_lyric()`（`:197-199`）存在，但播放器页没有任何调用点；
  - **无歌词磁盘缓存、无翻译行合并**：解析结果只在 `_lyrics` 内存数组里，换曲即丢弃；双语 LRC 的翻译行被当成一条无时间的普通行，不与原文配对（见 4.1）。

## 3. 核心数据结构

### 3.1 解析结果

`parse(text) -> Array[Dictionary]`（`assets/scripts/ui/music_app/player/music_app_lyric_parser.gd:6`），每条两个字段：`time: int`（该行开始秒数，纯文本/翻译行为 `-1`、不可 seek）与 `text: String`（去掉时间戳并 `strip_edges()` 后的歌词）。

### 3.2 解析常量与规则

| 项目 | 值 | 位置 |
| --- | --- | --- |
| `TIMESTAMP_PATTERN` | `\[(\d+):(\d+(?:\.\d+)?)\]` | `assets/scripts/ui/music_app/player/music_app_lyric_parser.gd:4` |
| 时间换算 | `int(minutes * 60 + seconds)`，负数夹 0 | `:27-31` |
| 换行归一 | `\r\n`、`\r` → `\n` 后按 `\n` 分割（保留空串） | `:12` |
| 元数据行 | `[ti:...]`、`[ar:...]` 等「方括号内含冒号」的行直接丢弃 | `:35-41` |

### 3.3 展示侧状态

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `_lyrics` / `_lyric_line_labels` | `Array[Dictionary]` / `Array[Label]`（`assets/scripts/ui/music_app/views/player/music_app_player_view.gd:24-25`） | 当前曲目的解析结果，与一一对应的行节点 |
| `_lyrics_track_key` | `String`（`:23`） | `track.id + "|" + track.lyric_path`，换曲才重建 |
| `_active_lyric_index` / `_lyrics_manual_scroll_until_msec` | `int` / `int`（`:26-27`） | 当前高亮行（`-2` 表示强制重算）；手动滚动后 4 秒内暂停自动定位 |

## 4. 关键实现

### 4.1 LRC 解析：多时间戳展开、纯文本降级

```gdscript
# assets/scripts/ui/music_app/player/music_app_lyric_parser.gd:14-32（节选）
var matches := timestamp_regex.search_all(raw_line)
if matches.is_empty():
	var plain_text := raw_line.strip_edges()
	if not plain_text.is_empty() and not _is_lrc_metadata(plain_text):
		lines.append({"time": -1, "text": plain_text})
	continue
var lyric_text := raw_line.substr(matches[matches.size() - 1].get_end()).strip_edges()
if lyric_text.is_empty():
	continue
for timestamp_match in matches:
	...
```

三个设计点：

1. **重复时间戳**：`[00:02.00][00:03.50]Repeated line` 会展开成两条记录（同一文本、两个时间）。这是 LRC 里表达「副歌重复」的常见写法，展开后高亮/滚动不用特判。
2. **时间戳前缀丢失**：歌词文本取「最后一个时间戳之后」的内容，所以不会把 `[00:02.00]` 留在正文里。
3. **纯文本降级**：没有时间戳的行（含翻译行、`txt` 歌词）保留文本但 `time = -1`。它们能显示，但不参与高亮与自动滚动——`_get_active_lyric_index()` 遇到 `time < 0` 直接跳过（`assets/scripts/ui/music_app/views/player/music_app_player_view.gd:722-727`）。

**已知取舍**：解析不排序、也不做「翻译行合并」。如果 LRC 的时间戳乱序，`_get_active_lyric_index()` 的 `break` 会提前终止，后续行永远不高亮；双语字幕的翻译行会作为独立的一行挤在原文后面。

### 4.2 逐行高亮：只在高亮行变化时改样式

```gdscript
# assets/scripts/ui/music_app/views/player/music_app_player_view.gd:661-672（节选）
var next_active_index := _get_active_lyric_index(elapsed_seconds)
if next_active_index == _active_lyric_index:
	return
_active_lyric_index = next_active_index
for index in _lyric_line_labels.size():
	var line_label := _lyric_line_labels[index]
	var is_active := index == next_active_index
	line_label.add_theme_color_override("font_color", Color(1, 1, 1, 0.96 if is_active else 0.48))
	line_label.add_theme_font_size_override("font_size", 22 if is_active else 18)
```

每秒的进度事件都会调用到这里，但只有 `next_active_index` 变化才遍历行。否则每秒给 N 个 Label 重设主题覆盖，长歌词（200+ 行）会明显掉帧。高亮用「白色 96% + 22px」、普通行「白色 48% + 18px」，不做逐字卡拉 OK。

### 4.3 滚动定位：行中心对齐视口中心

```gdscript
# assets/scripts/ui/music_app/views/player/music_app_player_view.gd:731-739（节选）
var line_label := _lyric_line_labels[index]
var target_scroll := roundi(line_label.position.y + line_label.size.y * 0.5 - lyrics_scroll.size.y * 0.5)
var max_scroll := roundi(maxf(0.0, lyrics_lines.size.y - lyrics_scroll.size.y))
lyrics_scroll.scroll_vertical = clampi(target_scroll, 0, max_scroll)
```

调用是 `call_deferred("_scroll_lyrics_to_line", next_active_index)`（`:674`），延后一帧，等新行的 `size` 与容器布局完成，否则会按旧高度算偏。

为了让**第一句**和**最后一句**也能停在视口正中，`_rebuild_lyric_lines()` 在首尾各加一个占位 Control（`:695`、`:716`），其高度由 `_update_lyrics_edge_padding()` 算成「视口一半 − 行高一半 − 行间距」（`:789-798`）；窗口尺寸变化时 `_request_lyrics_edge_padding_update()` 延时到布局完成后重算（`:800-812`）。这是自动滚动能「顶到底」的关键，否则最后一句最多滚到底部而无法居中，用户会以为歌词滚动错位。

### 4.4 手动拖动：4 秒免打扰 + 松手 seek

| 行为 | 实现 |
| --- | --- |
| 滚轮/拖动/触摸移动 | `_mark_lyrics_manually_scrolled()`，把 `_lyrics_manual_scroll_until_msec` 设为 `now + 4000`（`:747-748`） |
| 拖动期间 | `_on_lyrics_drag_scroll_started()`（`:750-753`）打开中央虚线时间游标 `_show_lyrics_time_cursor()`（`:772-776`） |
| 松手 | `_on_lyrics_drag_scroll_finished()`：找居中带时间歌词，命中则 seek；否则继续保持手动滚动窗口（`:755-759`） |
| 轻点某行 | `_handle_lyric_tap_or_scroll()` 判断位移 < 8px 才视为点击，seek 到该行时间（`:470-479`、`:501-511`） |

`_get_centered_timed_lyric_index()`（`:484-499`）用「行中心与滚动区中心的绝对距离」找最近的一句，跳过 `time < 0` 的行；因此纯文本歌词拖动后不会 seek，符合预期（没时间可跳）。自动定位同样受抑制：`_refresh_lyrics_for_track()` 里只有 `Time.get_ticks_msec() >= _lyrics_manual_scroll_until_msec` 才滚动（`:673`）。

时间游标 `MusicAppLyricTimeCursor`（`assets/scripts/ui/music_app/player/music_app_lyric_time_cursor.gd`）是一个自绘 `Control`：`_draw()` 画等距虚线（`:24-30`），`set_timestamp()` 把秒格式化成 `mm:ss`，`-1` 时清空文本（`:11-18`）。虚线居中、文字挂在 `%CursorTimeLabel`（场景 `assets/scenes/ui/music_app/player/music_app_player_page.tscn:356`），不随滚动移动，作为「松手会跳到这里」的视觉锚点。

### 4.5 无歌词 / 纯文本歌词态

`_rebuild_lyric_lines()`（`:689-718`）在每次换曲后重建：

| 状态 | 表现 |
| --- | --- |
| `_lyrics` 为空（无文件/读失败/空文件） | `NoLyricsCenter` 显示，`LyricsScroll` 隐藏，文案 `music_app.player.no_lyrics`（「暂无歌词」） |
| 只有纯文本行（`txt` 或无时间戳 LRC） | 行全部渲染，但不自动高亮/滚动；用户可拖动阅读 |
| 正常 LRC | 行渲染 + 高亮 + 自动居中 |

每行都是运行时 `Label.new()`：最小高度 40、自动换行、居中、`MOUSE_FILTER_IGNORE`（`:704-714`）——忽略鼠标是为了让点击/拖动事件落到外层 `LyricsScroll` 与 `LyricsStage`，否则点到 Label 上就不会触发「点空白返回封面」。

### 4.6 歌词来源与读取路径

| 来源 | 是否接入 | 代码位置 |
| --- | --- | --- |
| 本地旁挂文件（同名 `.lrc` / `.txt`） | 是 | `assets/scripts/ui/music_app/controllers/music_app_local_scan_controller.gd:320-327`，`LYRIC_EXTENSIONS` 在 `:15` |
| 目录扫描时的同目录歌词汇总 | 是 | `:194-216`（按文件名主干匹配，避免逐首 `DX.files.exists` 走 SAF JNI） |
| 插件返回的歌词 | 否（有接口无调用） | `assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:354`、`assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:197` |
| 歌词缓存文件 | 否 | 无磁盘缓存；仅内存 `_lyrics` |

读取统一走 DX 文件系统，因此 `saf-tree://` 授权目录里的 `.lrc` 也能读；`read_text()` 内部用 `get_string_from_utf8()`（`dx/runtime/scripts/managers/files/file_manager.gd:155-161`），非 UTF-8 编码（如 GBK）的 LRC 会解出乱码，当前没有编码探测。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| `lyric_path` 为空 | 直接返回空数组，显示「暂无歌词」（`:681-683`） |
| 文件读取失败（被删/无权限） | `read_result.ok == false` 返回空数组，不抛错（`:684-686`） |
| 空文件 / 全是元数据 | 解析结果为空 → 无歌词态 |
| 时间戳格式非法（`[mm:ss:xx]`、`[1:2:3]`） | 不匹配正则，整行按纯文本处理 |
| 小数秒 | `to_float()` 后截断为整秒，不做四舍五入 |
| 时间戳乱序 | 不高亮后续行（`break` 提前退出），无排序修正 |
| 歌词行超长 | `AUTOWRAP_WORD_SMART` 自动换行，行高随内容增长；滚动计算用实时 `size.y` |
| 换曲 | `_lyrics_track_key` 变化才重建，避免每秒进度刷新反复 `queue_free` 行节点 |
| 快速切歌 | 重建是同步的（无异步请求），不会出现旧歌词盖新曲目 |
| 手动拖动中进度更新 | 4 秒窗口内不自动滚动，避免「手还没松就被拽走」 |

## 8. 已知限制与后续

- **插件歌词未打通**：插件侧已有 `get_lyric()` 与 `hasGetLyric` 能力标记（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:476`），播放器页仍只读本地文件；接入时需要异步请求 + 缓存 + 与本地文件优先级策略。
- **无翻译行合并**：双语歌词目前是「原文一行、译文一行」平铺，未做按时间配对或上下两行排版。
- **解析不排序**：乱序时间戳会导致高亮提前终止，后续可在 `parse()` 末尾按 `time` 稳定排序（`-1` 行保持原位）。
- **无编码探测**：GBK/Big5 的 LRC 会乱码，需要 BOM/chardet 之类的兜底。
- **无逐字高亮**：只支持整行高亮，不支持增强型 LRC（`<mm:ss.xx>` 逐字时间）。
- **无缓存**：每次换曲重新读文件、重建 Label；对长歌词可考虑「按曲目 ID 缓存解析结果」。
