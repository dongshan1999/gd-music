| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | 应用界面 / 数据存档 |
| 覆盖范围 | `PlaylistData` 模型、收藏歌单归一化与置顶、创建/删除歌单、歌单详情页的播放/排序/批量删除、插件临时歌单与收藏 |

> 一句话定位：歌单是「只存 track_id 的命名列表」：首页负责创建与删除，详情页负责播放、排序与批量删除，收藏歌单（「我喜欢」）靠固定 ID 在整个应用里被特殊对待。

## 1. 功能概述

用户视角：

- 首页「我的歌单」区域列出所有歌单，末尾有「新建歌单」按钮；每个歌单卡显示图标、标题与「N 首」，长按或菜单可删除；
- 点歌单进入详情页：顶部是大封面块（其实是图标）、标题、总数，下面是曲目列表；
- 详情页有「播放全部」，也可以直接点某首开始播；
- 右上「更多」菜单里可以进入排序模式（拖动行重排）或批量删除模式（勾选后删除选择）——搜索、添加歌曲、编辑歌单目前只有占位提示；
- 在插件（B 站等）的专辑详情里点「播放全部」会生成一个临时歌单，详情页顶部出现「收藏歌单」，收藏后它会出现在首页。

实现视角：

- 歌单模型极简：`PlaylistData` 只有 `title / count / mark / tracks / deletable` 五个字段，没有独立 ID；
- 系统「我喜欢」歌单用 `title` 复用为 ID（固定字符串），启动时由存档归一化强制唯一并置顶；
- 首页控制器负责增删，歌单详情控制器只操作「当前选中的那个歌单」，两者都直接改 `tracks` 与 `playlists` 引用，改动后通过 `save(false)` 标记脏数据。

不在本期范围：歌单重命名、向已有歌单添加歌曲、歌单内搜索、自定义封面。

## 3. 核心数据结构

## 4. 关键实现

### 4.1 收藏歌单的两层归一化

收藏歌单必须在任何读取前就存在且位于索引 0，否则首页高亮、播放器「喜欢」按钮、队列都可能指向错位。代码用两层保护：

- 存档层（`assets/scripts/save/music/music_app_state_data.gd:135-170`）：反序列化后扫描 `playlists`，丢弃 `mark == "__plugin_collection__"` 的临时视图（:143-144，插件专辑/歌手详情不能落盘），把 title 等于收藏 ID 的条目合并成唯一一个并移到最前（:146-150），再按 `track_id_map` 过滤失效曲目并重算 `count`（:152-162），最后重置收藏歌单的 `title/mark/deletable`（:163-166）并调用 `_ensure_default_favorite_playlist()`（:169）补建缺失项；
- 运行期（`assets/scripts/ui/music_app/controllers/global/music_app_playlist_state_controller.gd:33-39`）：`normalize_favorite_playlist()` 调 `get_or_create_favorite_playlist()`（:76-100），只要发现收藏歌单不在 0 号位就 `remove` + `insert(0)`，并用 `_rebase_selected_playlist_index_after_favorite_move()`（:138-143）修正 `selected_playlist_index`。

为什么要两层：存档层保证「冷启动的磁盘数据是干净的」，运行期保证「任何写操作看见的都是干净数据」。只做一层时，运行期某个流程（比如插件页收藏）先把歌单插到了中间，下一层还没跑就会出现一帧错位。

`find_favorite_playlist_index()`（:103-108）按 title 查找；`track_key()`（:111-114）返回 `track.id`，收藏时用 ID 而不是路径，路径变化不影响「已收藏」。

### 4.2 新建歌单

`create_playlist_from_current()`（`assets/scripts/ui/music_app/controllers/music_app_home_controller.gd:29-40`）：

1. `_next_playlist_title()`（:97-104）以 `tr("music_app.playlist.new_playlist")` 为基名，重名时依次尝试 `基名 2`、`基名 3`——为什么不用时间戳：用户需要可读、可预期的名字，且首页列表按顺序展示，重名会让人分不清；
2. `mark` 取标题首字符（中文标题的第一个字在卡片上比通用图标更好认）；
3. `deletable = true`；
4. `append` 之后把 `selected_playlist_index` 设为最后一个，这样「新建完立刻点开」时打开的就是新歌单。

注意这里只改内存，没有调 `save()`；落盘依赖 DX 存档链路的脏标记（推断，创建后紧接着的其它操作会触发实际写入）。

### 4.3 删除歌单

`delete_playlist()`（`assets/scripts/ui/music_app/controllers/music_app_home_controller.gd:43-58`）：

- 先判 `deletable`，收藏歌单直接返回 `false`；
- 被删项在选中项之前时 `selected_playlist_index -= 1`，再 `clamp` 到 `[0, size-1]`；
- 不清理 `tracks`：歌单只是引用 ID，曲目仍可能被队列或其它歌单使用。

这也是为什么首页删除按钮对收藏歌单隐藏（`assets/scripts/ui/music_app/views/home/music_app_home_playlist_row.gd:43`）：入口层先挡一次，控制器再兜底。

### 4.4 重命名与「添加曲目」：当前没有实现

任务描述里的「重命名」「向歌单添加曲目」在代码中只有占位入口：

```gdscript
func show_edit_placeholder() -> void:
	show_toast("编辑歌单信息暂未接入。")
```

`assets/scripts/ui/music_app/controllers/music_app_playlist_controller.gd:93-118` 集中了一组只弹 toast、不写任何数据的占位方法：歌单内搜索（:96-97）、更多歌单操作（:99-100）、添加歌曲（:111-112）、编辑歌单信息（:114-115）、单曲操作（:117-118），另有空歌单/空选择时的三种提示（:93-94、:102-109）。因此 `tracks` 的写入路径只有三条：

| 写入方 | 方法 | 说明 |
| --- | --- | --- |
| 收藏开关 | `set_track_liked()`（`assets/scripts/ui/music_app/controllers/global/music_app_playlist_state_controller.gd:50-67`） | append/erase 后重算 `count`，无变化返回 `false` 避免多存一次 |
| 插件专辑详情 | `MusicAppPluginBrowserController` 直接 `playlist.tracks.append(...)` | 临时歌单，不落盘 |
| 收藏临时歌单 | `save_temporary_collection()`（`assets/scripts/ui/music_app/controllers/music_app_playlist_controller.gd:168-189`） | 把临时歌单转正：mark 改回首字符、`deletable=true`、去重后 `save(false)` |

`save_temporary_collection()` 的去重逻辑值得注意：若已存在「标题相同且 tracks 完全一致」的非临时歌单，则把当前临时项移除并返回 `false`，视图仍然提示「歌单已在我的歌单中」（:191-205），成功路径的 toast 是「专辑已收藏到我的歌单」——用户视角是「收藏成功」，实际复用了已有歌单，避免出现两个「周杰伦」专辑。

### 4.5 封面不是首曲封面

歌单卡片与详情页 hero 展示的都是图标，不是首曲封面：

- 首页行（`assets/scripts/ui/music_app/views/home/music_app_home_playlist_row.gd:35-39`）：`display_mark` 等于收藏标记时用 `HEART_FILLED`，否则用 `MUSICAL_NOTE`；
- 详情页（`assets/scripts/ui/music_app/views/playlist/music_app_playlist_view.gd:91-95`）：同样按「是否收藏歌单」二选一。

原因很直接：`PlaylistData` 没有封面字段，歌单里混着本地曲与插件曲，要取「首曲封面」得先读音频内嵌图（`assets/scripts/save/music/audio_artwork_reader.gd`）并给每个歌单做缓存，成本远高于本次范围。任务描述中的「歌单封面取首曲封面」与实现不符，这里按真实代码记录。

### 4.6 详情页刷新与三种模式

`refresh()`（`assets/scripts/ui/music_app/views/playlist/music_app_playlist_view.gd:68-106`）负责标题、封面图标、计数、操作按钮、空态与行列表。注意两个「空」不是一回事：`playlists` 整体为空（兜底）时直接渲染成「我喜欢」的空页并 return（:72-80）；真正的空歌单走 `_sync_empty_state()`（:135-138）隐藏列表、显示「这个歌单里还没有歌曲」，并把模式复位为普通（:87-88）。

页面有三个模式（`MODE_NORMAL / MODE_SORT / MODE_DELETE`，定义在 `assets/scripts/ui/music_app/views/playlist/music_app_playlist_song_row.gd:7-9`）：

| 模式 | 进入方式 | 行内变化 |
| --- | --- | --- |
| 普通 | 默认 | 播放按钮可点，点行切歌 |
| 排序 | 更多菜单 → `_enter_sort_mode()`（:211-216） | 显示拖拽把手，播放按钮隐藏 |
| 批量删除 | 更多菜单 → `_enter_delete_mode()`（:218-223） | 显示勾选框与删除按钮，顶部出现「全选」「删除选择 N」 |

`_set_management_mode()`（:225-233）统一设置每行的 `set_management_mode()`（`assets/scripts/ui/music_app/views/playlist/music_app_playlist_song_row.gd:63-73`），并切换顶部操作按钮文案（`_update_action_buttons()` :239-250）。

排序的拖拽实现在行内：`_on_drag_handle_gui_input()`（:90-108）同时处理鼠标与触摸，按下后由 `_input()`（:110-124）跟随指针，松手时发 `sort_drag_ended` 信号。页面用 `_find_sort_target_slot()`（:309-316）以「目标行中心线」判断落点，再调 `move_selected_playlist_track()`（`assets/scripts/ui/music_app/controllers/music_app_playlist_controller.gd:58-74`）就地 `remove_at` + `insert` 并重算 `count`——不重建数组，因为其它控制器持有 `tracks` 的引用。

批量删除先在控制器里 `_normalize_slot_indices()`（`assets/scripts/ui/music_app/controllers/music_app_playlist_controller.gd:132-143`）去重并**降序**排序，再逐个 `remove_at`。降序是必须的：升序删除会让后面每个下标前移，第二次就删到别的歌。删除完成后 `count` 重算，顶部「删除选择 N」与「全选/取消全选」文案由 `_update_action_buttons()`（:239-250）统一刷新。

## 8. 已知限制与后续

- `PlaylistData` 没有稳定 ID，系统歌单靠 title 字符串识别。当前重命名未实现所以不会冲突，一旦开放重命名必须补上独立 `id` 字段，否则「我喜欢」会被改名后重新创建一份。
- 歌单页与首页共用 `selected_playlist_index` 这一全局单值；同时打开两个歌单页（例如插件页再叠一层）会互相覆盖，属于结构性问题。
- 没有封面：只显示标记图标，无法从首曲内嵌封面生成缩略图。
- 排序只支持单行拖动，没有「拖到列表末尾」的吸附逻辑；落点判断用的是行中心线，行高不一时体验一般。
- 批量删除没有二次确认，也没有撤销；删错只能重新添加。
- 「添加歌曲」「歌单内搜索」「编辑歌单信息」都只是 toast 占位，藏在更多菜单里。
