| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | DX 框架 / 文件抽象 |
| 覆盖范围 | `dx/runtime/scripts/managers/files/`（`file_manager.gd`、`virtual_path.gd`、`providers/`、`platform/`） |

> 一句话定位：`DX.files` 把 `res://`、`user://`、Android 的 `content://` 统一成 4 种虚拟路径（`app://`、`local://`、`saf-file://`、`saf-tree://`），对外只暴露一套读写/复制/删除/申请目录的 API；业务代码永远不直接拼 `content://`。

## 1. 功能概述

- **用户视角**：手机上点「添加本地音乐」会弹出系统目录选择框，选一次后授权被持久化；之后扫描、下载、打开文件都能直接落在那棵树里。桌面平台用系统原生文件对话框替代。
- **实现视角**：
  - `DX_FileManager` 是门面：解析虚拟路径 → 选 provider → 转成 Godot 可操作的路径或原生 URI → 把 provider 结果归一化成 `{ok, path, error, ...}` 字典。
  - 4 个 provider：`app://`→`user://`、`local://`→真实文件系统、`saf-file://`→单个 SAF 文档、`saf-tree://`→SAF 目录树。
  - 「安全写入」不依赖 Godot 的 `FileAccess.WRITE` 直接覆盖，而是写临时兄弟文件再 `rename`；「安全移动」保留旧名做回滚备份。
- **不在本期范围**：不提供 FTP/SMB/zip 挂载、不做文件哈希、不监听文件变化、不处理 iOS 沙箱外的路径。

## 3. 核心数据结构

### 3.1 4 种虚拟路径（`dx/runtime/scripts/managers/files/virtual_path.gd:4-7`、`dx/runtime/scripts/managers/files/virtual_path.gd:9-67`）

| scheme | 形式 | 解析结果 | 落地位置 |
| --- | --- | --- | --- |
| `app://` | `app://save/data.json` | `relative_path = "save/data.json"` | `user://save/data.json` |
| `local://` | `local:///storage/emulated/0/x.mp3` | `body` 就是原生绝对路径 | 真实文件系统 |
| `saf-file://` | `saf-file://content://com.android.providers.../document/123` | `body` = 单个文档 URI | SAF 文档 |
| `saf-tree://` | `saf-tree://content://.../tree/abc#Music/a.mp3` | `body`=树 URI（`#` 前），`relative_path`=`#` 后的相对路径 | SAF 目录树 |

解析器要求路径必须含 `://` 且 scheme 非空（`:18-24`，错误文案 `"Path must use a virtual scheme, for example app://exports/file.csv."`）；除 `app://` 外 body 不能为空（`:32-38`）。`saf-tree` 只有找到 `#` 才拆成 URI + 相对路径（`:51-63`），因此 `saf-tree://<uri>` 合法但只能表示树根。

`normalize_relative_path()`（`:98-118`）会剥掉前导 `/`、跳过空段与 `.`，**遇到 `..` 直接报错** `"Parent path segments are not allowed."`，这是防目录穿越的唯一闸门。

### 3.2 统一返回结构

| 键 | 出现场景 | 说明 |
| --- | --- | --- |
| `ok` | 全部 | `bool`，唯一可靠的成败判据 |
| `path` | 全部 | 回填的虚拟路径（拷走后是目标路径） |
| `error` | 失败 | 英文原因，含失败的具体路径 |
| `cancelled` | 选择器 | 用户取消对话框 |
| `partial` | `move()` | 已复制但删除源失败（`:463-467`） |
| `uri` / `uris` | 选择器 | 原生 URI（`content://`），用于持久化授权 |
| `native_path` | `list_dir` 条目 | SAF 条目为 `document_uri`，其余为绝对路径 |

`list_dir` 的每个条目字段：`name`、`path`、`native_path`、`is_dir`、`is_file`、`is_link`、`size`（`dx/runtime/scripts/managers/files/providers/app_data_file_provider.gd:37-65`、`dx/runtime/scripts/managers/files/providers/android_saf_file_provider.gd:100-126`）。

## 4. 关键实现

### 4.1 为什么用「临时兄弟文件 + rename」写文件

```gdscript
# providers/file_provider.gd:90-100（节选）
var temporary_path := _temporary_native_sibling_path(native_path)
var file := FileAccess.open(temporary_path, FileAccess.WRITE)
...
file.flush()
var replace_result := _move_native_path(temporary_path, native_path, true)
```

- 临时文件放在**同一目录**（`_temporary_native_sibling_path()`，`:330-335`，名字 `.name.dx-tmp-<usec>-<rand>`），保证 `rename` 是同分区操作、能原子完成；
- 直接 `FileAccess.open(path, WRITE)` 会先截断，写到一半崩溃就得到 0 字节文件；先写 temp 再替换，最坏情况只是留下一个临时文件；
- SAF 的树内写入也走同样思路：先写树内临时相对路径，再用 `AndroidSafTree.move_path()` 覆盖（`dx/runtime/scripts/managers/files/providers/android_saf_file_provider.gd:31-54`），但 **`saf-file://`（单文档 URI）无法原子替换**，注释明确写为「直接对应授权文档，不生成临时兄弟文件」。

### 4.2 安全复制：先拷到 staging 再 move，而不是「拷一半直接覆盖目标」

`copy_file()`（`dx/runtime/scripts/managers/files/file_manager.gd:269-325`）的顺序是：

1. 源是符号链接或目录 → 直接拒绝（`:274-276`）；
2. 目标已存在且 `overwrite=false` → 失败（`:281-285`）；
3. `_temporary_sibling_virtual_path(target)` 生成 staging 路径（`.name.dx-tmp-...`）；
4. `provider.copy_from_access_path(staging_path, access, chunk_size)` 流式拷贝（`dx/runtime/scripts/managers/files/providers/file_provider.gd:173-224`，默认 1 MB 块）；
5. `provider.move_path(staging, target, overwrite)` 原子落位；staging 失败则清理掉。

这样复制中断只会污染 staging 文件，不会破坏已有目标。`copy_dir()` 递归时额外做两件事：进入前拒绝「把目录复制到自己内部」（`_is_path_inside`，`:339-341`），并用 `visited` 字典防符号链接环路（`:374-379`）。

### 4.3 移动与回滚

`move()`（`:439-488`）先做 4 道检查：源/目标是否受保护根、是否符号链接、源类型、目标冲突。跨 provider 或 provider 不支持原生移动时退化为「复制 + 删除源」，此时若删除失败返回 `partial = true` 并在 `error` 里说明「Move copied the target but failed to delete the source」。

`_move_native_path()`（`dx/runtime/scripts/managers/files/providers/file_provider.gd:226-274`）在同名旧目标存在时先把旧目标 rename 成 `.dx-backup-*`，新文件就位成功后再删备份；就位失败则把备份改回原名——保证目标路径要么是旧内容、要么是新内容，不会两头空。

### 4.4 递归删除为什么需要 `visited`

`delete_dir_recursive()`（`:226-261`）与 `_copy_dir()` 都维护一个 `visited` 字典存 `_canonical_path_key`（`:685-704`，Windows/macOS 上先 `to_lower()`）。SAF 或用户手动建的环形符号链接会让朴素递归无限下降，`visited` 让每个真实目录最多进一次；遇到 `is_link` 的目录按文件删除（`:258`），不跟进去。

### 4.5 受保护根：不允许删 `user://` 与授权树根

`_is_protected_root()`（`:706-730`）拒绝 `app://`（空相对路径）、`saf-tree://<uri>`（无 `#` 片段，即树根）、以及 `/`、盘符根这类文件系统根。判断发生在 `move()`、`delete_file()`、`delete_dir()`、`rename()` 之前——注释写明「避免一个空路径被解析成 user:// 而把整个存档目录删掉」的意图。

### 4.6 SAF 目录授权要「申请 + 持久化」两步

Android 的 `ACTION_OPEN_DOCUMENT_TREE` 授权默认只在当前会话有效，重启后失效。所以选择器回调里额外做了一次 `persist_saf_uri_permission(uri)`（`dx/runtime/scripts/managers/files/platforms/file_platform.gd:195-196`），它会遍历所有 provider 找支持持久化的实现，Android 侧调 `DX_AndroidSafTree.persist_uri_permission()`（`dx/runtime/scripts/platform/android/dx_android_saf_tree.gd:7`）落一个 `takePersistableUriPermission`。

业务侧把拿到的树 URI 存进存档（`MusicPluginSettingsData.android_tree_plugins`），下次启动直接用 `saf-tree://<uri>#` 构造路径，不需要重新弹框。

### 4.7 provider 选择与「桌面回退」

`_resolve()`（`:620-631`）按注册顺序取第一个 `supports(scheme)` 的 provider，因此注册顺序即优先级。`saf-*` 的 provider 只在 Android 上 `is_supported()` 为真（`dx/runtime/scripts/managers/files/providers/android_saf_file_provider.gd:189-190`），桌面端请求 `saf-tree://` 会得到 `"Android SAF is not available on this platform."`。

平台实现由 `_create_platform()`（`:591-603`）按 `OS.get_name()` 选择 `macos_/windows_/linux_/android_file_platform.gd`，未知平台用基类 `file_platform.gd`（`DisplayServer` 原生对话框）。四个平台文件的共同点是：**只覆写选择器与打开/定位**，路径解析与原子写完全共享基类逻辑。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| 路径无 `://` | `to_virtual_path` 默认按 `app://` 解释（`dx/runtime/scripts/managers/files/file_manager.gd:71`）；若显式 scheme 非法则 `parse` 报错 |
| 相对路径含 `..` | `normalize_relative_path` 报错，调用返回 `{ok:false}` |
| 已有原生对话框打开 | 第二次选择请求返回 `"A native file picker is already open."`（`dx/runtime/scripts/managers/files/platforms/file_platform.gd:100-104`） |
| 平台无原生对话框 | `"Native file picker is not available on this platform."`，回调收到空结果 |
| Linux 无 zenity/kdialog | `"No Linux native file picker command found. Install zenity or kdialog."` |
| SAF 权限被用户撤销 | 底层 `content://` 打开失败，provider 把错误包装进 `{ok:false, error}`，不崩溃 |
| 目标已存在且未允许覆盖 | 返回失败并提示 `"Target file already exists."` / `"Target directory already exists."` |
| 复制目标是自身子目录 | 直接失败 `"Cannot copy a directory inside itself."` |
| 移动跨 provider | 退化为复制+删除，删除失败返回 `partial=true` |
| 删除树根 / `user://` | `_is_protected_root` 拦截，返回 `"Deleting a protected filesystem root is not allowed."` |
| 临时文件残留 | 写失败时 `_cleanup_native_temporary_path()` 立即清理，清理失败写进 `cleanup_error`（`dx/runtime/scripts/managers/files/providers/file_provider.gd:91-108`） |
| 文件名含 `/` | `_is_valid_entry_name` 校验失败（`:762-764`），写/建目录前拒绝 |

## 8. 已知限制与后续

- `saf-file://` 无法原子写（单文档 URI 不能 rename），写入中断会留下半截文件；
- 无批量事务：`copy_dir` 中途失败会留下部分已拷贝文件（staging 只保护「目标文件」本身）；
- 平台选择器用 `OS.execute` 调 `osascript`/`powershell`/`zenity`，是阻塞子进程，大目录下会卡住主线程（注释里承认这点）；
- 路径规范化只做字面归一，不做 `res://`→`local://` 之外的资源解析；
- 没有文件监听/变更通知，外部 App 改了 SAF 目录后需要业务侧重新 `list_dir`。
