> 一句话定位：项目通过 `tools/package.sh` 一条命令产出 Android APK / Windows EXE，导出时由 `addons/dx_build_number` 编辑器插件自动给构建号 +1 并写进包内的 `build_info.cfg`，随后可用 `tools/deploy_device.sh` 直接装到真机。

## 1. 功能概述

- **用户视角**（开发者视角）：`tools/package.sh` 默认打 Android debug 包，`-p windows` 打 Windows 包，`-m release` 打发布包；脚本会自动检查 Godot、导出模板、Android SDK、JDK、签名配置，缺失时给出明确报错而不是导出到一半失败。
- **实现视角**：
  - 平台与产物路径由 `export_presets.cfg` 定义（预设名 `Windows Desktop` / `Android`）；
  - `tools/package.sh` 负责环境探测与调用 `godot --headless --export-<mode> <preset> <output>`（`tools/package.sh:268`）；
  - `addons/dx_build_number` 是 EditorPlugin，内部挂一个 `EditorExportPlugin`，在导出开始前把 `build_number` 写进 `build_info.cfg` 并作为资源塞进包；
  - `tools/deploy_device.sh` 用 `adb` 完成安装、启动、抓日志。

## 2. 功能入口与调用链

### 2.1 命令行打包

```
tools/package.sh [-p android|windows] [-m debug|release] [-o 输出路径] [-c 只检查]
        │
        ├─ 解析参数（:50-90）
        ├─ 定位 Godot（resolve_godot，:95-115）
        ├─ 读 Godot 版本 → 推导导出模板目录（:121）
        ├─ 读编辑器设置 editor_settings-*.tres（:123-152）
        ├─ 校验预设存在 + 模板文件存在（:173-183）
        ├─ Android 额外校验 SDK / platforms / build-tools / JDK≥17 / 签名（:186-228）
        ├─ 计算输出路径（默认 builds/android|windows/…，:235-248）
        ├─ 记录构建号（read_build_info，:250-255）
        ├─ 执行 godot --headless --path . --export-<mode> <preset> <output>（:268）
        ├─ 校验产物存在 → 输出大小 / sha256 / 构建号变化（:275-292）
        └─ 日志写 builds/logs/package-<platform>-<mode>-<时间戳>.log
```

### 2.2 编辑器内导出

在 Godot 4.7 编辑器中 `项目 → 导出`，选择同名预设后导出；效果与脚本一致，构建号插件同样生效（`EditorExportPlugin` 与手动导出无关，只在导出管线里运行）。

### 2.3 安装到设备

```
tools/deploy_device.sh [-s 序列号] [-a apk] [-k 包名] [-u] [-n] [-l]
        ├─ 定位 adb（:91）
        ├─ 选 APK：默认取 builds/android 下最新包（:155）
        ├─ 选包名：默认读 export_presets.cfg 的 package/unique_name（:168-171）
        ├─ adb install 并解析结果（:196）
        ├─ adb shell am start 启动（:206）
        └─ 可选 adb logcat 打印 Godot 日志（:216）
```

## 4. 关键实现

### 4.1 为什么打包要写脚本而不是纯靠编辑器

编辑器导出有三个问题：一是手动操作容易漏选预设 / 漏填签名；二是导出失败时 Godot 的原生报错埋在几百行日志里；三是产物没有校验（Godot 返回 0 但没生成文件的情况真实存在）。

`tools/package.sh` 因此把「环境校验」和「导出」分开（`:95-233` 全部是检查，真正的导出只有 `:268` 一行）：

```bash
# tools/package.sh:268
if ! "${GODOT}" --headless --path "${ROOT_DIR}" "--export-${MODE}" "${PRESET}" "${OUTPUT}" >"${LOG_FILE}" 2>&1; then
```

导出后还会做三件事（`:275-292`）：确认产物存在（防止「返回 0 无产物」）、计算 `sha256` 便于分发校验、比较构建号前后值确认插件真的生效。

### 4.2 Android 环境校验的细节

- **导出模板**：目录名形如 `4.7.stable`，脚本从 `godot --version` 去掉 `.official.<hash>` 后缀得到（`:121`），再到 `~/Library/Application Support/Godot/export_templates/<ver>` 等三个候选目录找（`:123-152`）；
- **SDK**：优先 `ANDROID_HOME`/`ANDROID_SDK_ROOT`，其次读编辑器设置 `export/android/android_sdk_path`，最后回退 `~/Library/Android/sdk`；还要求 `platforms` 与 `build-tools` 子目录存在（`:186-205`）；
- **JDK**：`JAVA_HOME` → 编辑器设置 `export/android/java_sdk_path` → `/usr/libexec/java_home` 三级回退，并要求 `bin/java` 可执行（Godot 4.7 要求 JDK 17+）；
- **签名**：debug 包允许 keystore 缺失（Godot 会尝试自动生成），release 包必须显式配置 `keystore/release`，否则直接 `die`（`:213-228`）。

这套探测顺序的本质是「命令行环境 → 编辑器 GUI 配置 → 系统默认」，保证在 CI 和本地都能跑。

### 4.3 构建号自增插件

`addons/dx_build_number/dx_build_number_export_plugin.gd` 有两个角色：

1. `_get_export_options_overrides()`（:15）：导出前把 `build_number` 覆盖为「上次 +1」，让导出对话框也显示新号；
2. `_export_begin()`（:25）：真正导出时再次 `+1`，生成 `build_info` 文本，写回项目内 `build_info.cfg`（:61-65），并通过 `add_file()` 把它塞进导出包。

为什么用 EditorPlugin 而不是在游戏运行时生成：构建号必须在**打包时**确定，运行时生成没有意义；同时编辑器插件能拿到 `is_debug` 与平台信息，比 GDScript 运行时猜更可靠。

### 4.4 部署脚本

`tools/deploy_device.sh` 解决的是「打完包还要手动 adb install + am start + logcat」的重复劳动：默认取 `builds/android` 下最新的 APK（`:155`），包名从 `export_presets.cfg` 读取（`:168`），因此改包名不需要改脚本。

### 4.5.1 gdmpv：macOS 构建（开发期）

```bash
cd addons/gdmpv

# 1. 开发期 libmpv（brew 版是 GPL 构建，只能本机调试，不得分发）
brew install mpv
export PKG_CONFIG_PATH="$(brew --prefix)/lib/pkgconfig:$PKG_CONFIG_PATH"

# 2. godot-cpp：4.6/4.7 没有 stable tag，只能跟 master
git clone --depth 1 -b master https://github.com/godotengine/godot-cpp.git vendor/godot-cpp

# 3. 编译；api_version=4.7 必须显式给，否则 scons 首行就报
#    'api_version' must be provided to build against a custom Godot version
scons platform=macos target=template_debug arch=arm64 api_version=4.7 -j8
```

产物 `bin/libgdmpv.macos.template_debug.arm64.dylib` **带 arch 后缀**，与 `gdmpv.gdextension` 的 `macos.debug.arm64` 键对应；改错名字的表现是「扩展静默不加载」。`otool -L` 里能看到它用绝对路径引用 `/opt/homebrew/opt/mpv/lib/libmpv.2.dylib`——开发期免拷贝，分发期要改（见 [libmpv原生扩展](2026-10-27_libmpv原生扩展.md) §8）。

### 4.5.2 gdmpv：桌面另两端

```bash
# Windows（在 Windows 或交叉工具链下）
scons platform=windows target=template_debug arch=x86_64 api_version=4.7 -j8
# Linux
scons platform=linux target=template_debug arch=x86_64 api_version=4.7 -j8
```

要备的运行时库与落位（拷到 `addons/gdmpv/bin/`，由 `.gdextension` 的 `[dependencies]` 段声明）：

| 平台 | 扩展产物 | 需随包的 libmpv |
| --- | --- | --- |
| macOS | `libgdmpv.macos.*.arm64.dylib` | `libmpv.2.dylib` |
| Windows | `libgdmpv.windows.*.x86_64.dll` | `libmpv-2.dll`（官方 mpv-dev 预编译包） |
| Linux | `libgdmpv.linux.*.x86_64.so` | `libmpv.so.2`（`libmpv-dev`） |

三端产物目前只有 macOS arm64，Windows/Linux 未实际构建验证。

### 4.5.3 gdmpv：Android 两步构建

```bash
cd addons/gdmpv

# 第 1 步：交叉编译 Android 版 libmpv（内部调 mpv-android 官方 buildscripts）
./tools/build_android_libmpv.sh arm64

# 第 2 步：编译 GDExtension（NDK 用第 1 步装好的 r30）
export ANDROID_HOME="$HOME/.cache/gdmpv-build/mpv-android/buildscripts/sdk/android-sdk-mac"
export MPV_ANDROID_PREFIX="$PWD/thirdparty/mpv-android"
scons platform=android target=template_debug arch=arm64 api_version=4.7 \
      ndk_version=30.0.16248370 -j8
```

第 1 步做的事：`git clone` mpv-android → `download.sh`（装 SDK/NDK、拉 ffmpeg/mpv 源码，首次数 GB）→ `buildall.sh --arch arm64 mpv` → 产物分两处整理：

| 位置 | 内容 | 用途 |
| --- | --- | --- |
| `thirdparty/mpv-android/{include,lib/arm64}` | 头文件 + 未 strip 的 `libmpv.so` | 链接用 |
| `bin/android_arm64/*.so` | strip 后的 libmpv + `libav*` + `libc++_shared.so` | 打进 APK |

实测算过的坑，四条都是硬约束：

1. **构建树必须落在 `~/.cache/gdmpv-build/mpv-android`**（脚本默认值，可用 `GDMPV_MPV_ANDROID_DIR` 覆盖）。放项目里会让 Godot 扫描约 6 万个构建文件，编辑器与导出卡死——`addons/gdmpv/tools/build_android_libmpv.sh:12-15` 的注释就是为此写的。
2. **需要 bash 4+**：macOS 自带 bash 3.2 不支持 mpv-android `buildall.sh` 里的 `declare -g`，脚本会优先找 `/opt/homebrew/bin/bash`，找不到就报 `declare: -g: invalid option`（`addons/gdmpv/tools/build_android_libmpv.sh:32-44`）。`brew install bash` 即可。
3. **耗时与下载量**：实测约 35 分钟、下载 1–2 GB（`addons/gdmpv/README.md` 的记录是首次 40 分钟到 1 小时）。
4. **NDK 不用手工装**：`download.sh` 会把 SDK 与 NDK 一起装进构建树（实测目录名 `android-ndk-r30`，`ndk_version=30.0.16248370`）；`SConstruct:11` 的要求是 NDK r29+。

产物版本特征（实测）：mpv 0.41.0 系 + FFmpeg 8.0 系，ELF `LOAD` 对齐 `0x4000`（16 KB 页，满足 Android 15+ 与 Play 的要求）。

**JDK 17 与 GDExtension 编译无关**：`scons` 编 GDExtension 不经过 Gradle，只调 NDK 的 clang，所以 `package.sh` 里「JDK≥17」的校验只对 APK 导出（Gradle 构建）有意义，不影响 `addons/gdmpv` 的编译。

### 4.5.4 导出后的原生库自检

```bash
godot --headless --path . --export-debug "Android" builds/android/gd-music-debug.apk
unzip -l builds/android/gd-music-debug.apk | grep 'lib/arm64-v8a/'
```

`lib/arm64-v8a/` 内应有 **12 个 `.so`**：`libmpv.so`、`libav{codec,device,filter,format,util}.so`、`libsw{resample,scale}.so`、`libc++_shared.so`、`libgdmpv.*.so`、`libgdffmpeg.*.so`、`libgodot_android.so`；同时 `android/build/libs/gdextensionlibs.json` 应有 17 条记录。少库时导出**不会报错**，只会在运行期 `dlopen` 失败——所以这一步必须是打包流程的固定动作（实测 2026-10-27 的 debug APK 两项都符合）。

### 4.6 版本号展示

游戏内「关于」页读包内 `res://build_info.cfg` 展示版本与构建号（`DXBuildNumberStore` 提供读取），因此同一份代码在不同时间打出的包能看出先后。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| 未安装导出模板 | `package.sh` 在导出前报错并提示「编辑器 > 管理导出模板」 |
| 缺 Android SDK / JDK | 分别报错并指出期望路径与最低 JDK 版本 |
| release 未配签名 | 直接失败，避免产出不可分发的包 |
| Godot 返回 0 但无产物 | 打印日志尾部并报错（`:280-283`） |
| 同时连接多台设备 | `deploy_device.sh` 要求用 `-s` 指定序列号 |
| 构建号文件损坏 | `read_build_info` 失败按 0 处理；`DXBuildNumberStore` 加载失败同样回退 0 |
| 缺原生扩展产物（`addons/gdmpv/bin/` 为空） | **导出照常成功**，运行期由 `AudioBackendFactory` 回退到 Godot 原生播放器；Android 上表现为「远端音频要整首下载」，无任何报错 |
| 原生库声明了但没打进 APK | 同样导出零报错，运行期 `dlopen` 失败、回退原生后端；只能靠 §4.5.4 的解包自检发现 |
| `.gdextension` 段内写了 `#` 注释 | ConfigFile 把注释粘进下一个键名，该段依赖被静默丢弃（这是上面两行最常见的成因） |
| scons 报 `'api_version' must be provided` | 编 gdmpv 时必须显式传 `api_version=4.7` |
| scons 报 `pkg-config` 找不到 mpv | 桌面端缺 `PKG_CONFIG_PATH=$(brew --prefix)/lib/pkgconfig` |
| NDK 版本不符 | 报找不到工具链；`addons/gdmpv/SConstruct:11` 要求 NDK r29+，本项目 Android 构建用 r30（`ndk_version=30.0.16248370`） |
| mpv-android 构建树放进项目目录 | Godot 扫描约 6 万个文件，编辑器与导出都会卡死；必须放 `~/.cache/gdmpv-build/mpv-android` |
| 无 CI | 仓库当前没有 `.github/workflows` 等 CI 配置，打包依赖本地脚本；也意味着「误用 GPL 版 libmpv」「APK 少库」两类问题没有自动化闸门 |

## 6. 相关测试

构建流程没有自动化测试。手工验证：

1. `tools/package.sh -c` → 应输出「环境检查通过（android / debug）」；
2. `tools/package.sh` → 产物落到 `builds/android/gd-music-debug.apk`，日志显示构建号 `N -> N+1`；
3. 解包或运行后检查 `build_info.cfg` 的 `number` 与脚本输出一致；
4. `tools/deploy_device.sh -l` → 装到真机并打印启动日志；
5. `tools/package.sh -p windows -m release` → 产物为 `builds/windows/gd-music.exe`。

### 6.1 原生扩展的五步自检

改过 `addons/gdmpv` 或 `addons/ffmpeg` 之后，按顺序跑这几条（`godot` 指本机 Godot 4.7 可执行文件）：

```bash
# ① 产物在不在：文件名必须带 arch 后缀，与 .gdextension 的键一致
ls addons/gdmpv/bin/

# ② 入口符号在不在：找不到就说明编译产物不对
nm -gU addons/gdmpv/bin/libgdmpv.macos.template_debug.arm64.dylib | grep gdmpv_init

# ③ 依赖链指向哪：开发期应指向 Homebrew 的 libmpv.2.dylib
otool -L addons/gdmpv/bin/libgdmpv.macos.template_debug.arm64.dylib

# ④ 引擎能否干净加载并在 90 帧后退出：加载失败会打印 Can't open dynamic library
godot --headless --path . --quit-after 90

# ⑤ 冒烟 14 项断言 + 后端抽象 20 项断言（样本必须 ≥3 秒，否则 is_playing() 会因已播完误判）
ffmpeg -f lavfi -i "sine=frequency=440:duration=3" -c:a aac -y /tmp/gdmpv_test_tone.m4a
SMOKE_AUDIO=/tmp/gdmpv_test_tone.m4a godot --headless --path . res://addons/gdmpv/test/gdmpv_smoke_scene.tscn
SMOKE_AUDIO=/tmp/gdmpv_test_tone.m4a godot --headless --path . res://addons/gdmpv/test/audio_backend_smoke_scene.tscn
```

桌面端八项人工验收（自动化盖不住的部分）：能出声、本地 m4a 可播、远端 URL 边下边播、play/pause/seek 正常、与 UI 音效互不掐、seek 后位置抖动 <50ms、音量生效、`finished` 只发一次。真机侧（后台播放、通知栏、耳机拔出等）见 [Android后台音频](2026-10-27_Android后台音频.md) §6。

打 APK 前的原生库自检见 §4.5.4（`lib/arm64-v8a/` 12 个 `.so`、`gdextensionlibs.json` 17 条），这一步失败时导出本身是成功的，只有运行期才会暴露。

## 8. 已知限制与后续

- 仅两个平台预设（Windows / Android），没有 iOS / Linux / Web；
- Android 只保留 arm64，未提供 universal APK 或 AAB；
- 构建号按平台独立计数（`user://dx_build_numbers.cfg`），换机器后本地构建号会从 0 重新开始；
- 没有 CI：建议后续把 `package.sh -c` 与导出步骤搬进 GitHub Actions，并缓存导出模板与 Gradle 依赖；
- **原生扩展只有 debug 产物**：`addons/gdmpv/bin/` 里是 `template_debug`，release 导出时 `libgdmpv` 会被跳过（回退原生后端，功能可用但失去 mpv 能力），正式发包前必须补 `target=template_release` 的产物；
- **桌面端只有 macOS arm64 的 gdmpv 产物**，Windows/Linux 需自行构建，未验证；
- **iOS 无任何产物**：FFmpeg 未提供 iOS 库（`addons/ffmpeg/` 只有 `android`/`linux64`/`macos`/`win64`），gdmpv 也未交叉编译过 iOS；iOS 导出要补静态 `.a`、`Info.plist` 后台音频与 `AVAudioSession` 配置（详见 [libmpv原生扩展](2026-10-27_libmpv原生扩展.md) §8）；
- **macOS 分发要自带 libmpv**：当前产物用绝对路径引用 Homebrew 的 `libmpv.2.dylib`，拷进包内并 `install_name_tool -change` 改路径这一步没做过；
- **libmpv 必须按 LGPL 构建**：`brew install mpv` 与官方 mpv-dev 包都是 GPL 构建，只能本机调试；构建脚本未把 `-Dgpl=false` 固化成断言，也没有 CI 校验（详见 [libmpv原生扩展](2026-10-27_libmpv原生扩展.md) §4.9）；
- **包体积未定案**：debug APK 实测 139,280,767 字节（≈133 MiB），裁剪路径（砍解码器 + strip）估计能到 8~15 MB，但未实测；
