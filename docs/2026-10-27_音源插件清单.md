> 一句话定位：App 里「能搜到哪些平台的歌」由这 22 个音源决定；每个音源是一份 MusicFree 插件源码，能否搜索 / 出歌单 / 出详情 / 解析播放地址 / 需要登录，全部写在它导出的能力字段里。

## 1. 功能概述

- **用户视角**：搜索页的音源下拉列表、插件管理里的插件列表，条目数量与能力都来自本清单；每个音源的可用能力不同（有的只能搜歌词，有的只能导入歌单）。
- **实现视角**：`source_plugins/<目录名>/index.ts` 是唯一事实来源，`module.exports` 里声明 `platform`、`version`、`supportedSearchType` 与若干方法；GDScript 侧加载的是据此迁移（或直接手写）出来的插件脚本。
- **不在本期范围**：不改造上游插件源码；不补齐缺失能力；`.generated/` 里未迁移的音源在 App 内不可用。

## 3. 核心数据结构

### 3.1 一个音源的导出字段

| 字段 | 类型 | 含义 | 备注 |
| --- | --- | --- | --- |
| `platform` | string | 显示名，同时是 GDScript 插件 id | 唯一性由它保证，见 §4.1 |
| `version` | string | 插件版本 | 与原站无关 |
| `author` | string | 作者 | 22 个里 16 个为「猫头猫」 |
| `srcUrl` | string | 上游发行地址（gitee MusicFreePlugins） | 全部指向 `MusicFreePlugins/raw/v0.1/dist/<目录>/index.js` |
| `cacheControl` | string | 缓存策略 | 多为 `no-cache`，`qmkg` 用 `no-store` |
| `supportedSearchType` | string[] | 可搜索类型 | 缺省即「不支持搜索」，如 `qmkg`、`suno` |
| `primaryKey` | string[] | 曲目去重主键 | 仅有 `audiomack`、`bilibili`、`kugou`、`migu`、`qq` |
| `hints` | object | 给用户的导入提示 | `kugou`、`kuwo`、`migu`、`netease`、`qq`（`importMusicSheet` 文案） |
| `userVariables` | object[] | 需要在设置里填的凭证 | 仅 `airsonic`、`navidrome`、`webdav` |

## 4. 关键实现

### 4.1 目录组织：三处存放、一套 id

| 位置 | 性质 | 是否运行期加载 |
| --- | --- | --- |
| `gdmusic_plugin_codegen/source_plugins/<目录>/index.ts` | 上游快照，只读参考 | 否 |
| `gdmusic_plugin_codegen/.generated/gdmusic_*_plugin.gd` | 手写迁移工作区（隐藏目录，Godot 忽略） | 否，需人工拷出 |
| `plugins/builtin/bilibili.gd` | 随包内置 | 是（`BUILTIN_PLUGINS` preload） |
| `user://gdmusic_plugins/<id>/plugin.gd` | 用户安装 | 是（`refresh_plugins()` 扫盘） |

`plugins/README.md` 明确了两条约定：① 目前只有 `bilibili.gd` 由启动流程自动加载；② 手动安装同 id 插件会覆盖内置实现，`.generated` 里的旧文件保留为「迁移参考入口」，不再参与加载。**为什么用同一个 id 覆盖而不是并列**：`plugin.id` 来自 `platform` 字段，它同时是存档键（停用列表、cookie、登录态）和曲目 `plugin_id` 的来源；并列会立刻造成存档键冲突。

### 4.2 能力缺口：清单里那 8 个「不能搜」和 4 个「不能放」

- **只能搜歌词**：`geciqianxun`、`geciwang` 的 `supportedSearchType` 只有 `lyric`，没有 `getMediaSource`——它们只能给已有曲目配歌词，不能独立出歌。这也是它们为什么在 UI 上无法作为独立音源被选中（推断，依据是控制器 `search()` 按类型透传，未做 `lyric` 专属入口）。
- **完全不能搜**：`qmkg` 没有 `supportedSearchType`，只有 `importMusicItem` + `getMediaSource`；`suno` 只有榜单和歌词。二者都是「先导入、再播放」的模型。
- **自建服务**：`airsonic`、`navidrome`、`webdav` 在 `userVariables` 里声明地址与账号，未填时请求必然 4xx；字段定义见各文件 `gdmusic_plugin_codegen/source_plugins/airsonic/index.ts:506`、`gdmusic_plugin_codegen/source_plugins/navidrome/index.ts:139`、`gdmusic_plugin_codegen/source_plugins/webdav/index.ts:107`。
- **需要登录才能拿地址但上游没写**：`netease`、`qq` 的 VIP 曲目在 TS 层没有 cookie 注入逻辑，迁移时若照抄会得到「搜索有结果、播放无地址」。

### 4.3 状态判定：未迁移的音源在 App 里是什么样

`.generated/` 只存在 10 个手写实现 + 1 个 Bilibili 兼容入口，其余 11 个音源**没有任何 `.gd` 产物**，因此：

- 插件管理列表里看不到它们（宿主只扫 `user://gdmusic_plugins/` 与内置 preload）；
- 曲目永远不会带这些 `plugin_id`，`get_media_source()` 会走「曲目没有关联的音源插件」分支。

想补齐，必须按 §4.4 走一遍迁移，生成器只帮忙列出方法签名和依赖。

### 4.4 新增音源步骤（按代码实际流程）

1. 新建 `gdmusic_plugin_codegen/source_plugins/<目录>/index.ts`，参照 `source_types/plugin.d.ts` 的 `IPluginDefine` 实现 `module.exports`；
2. 跑 `node gdmusic_plugin_codegen/scripts/check_source_utf8.js` 确认文件是 UTF-8（README 特别提醒：中文乱码不要改编码，先跑校验）；
3. 跑 `node gdmusic_plugin_codegen/scripts/generate_gd_skeletons.js` 或 `scripts/generate_all_source_plugins.ps1`，产出 `.generated/<目录>_plugin.gd` 骨架与 `migration_report.md`，从 `MIGRATION_DIFFICULTY` 判断工作量；
4. 按骨架里的 `TODO` 逐方法迁移（`http` 用 `gdmusic_http_json_client.gd`，签名用 `gdmusic_hash_utils.gd`，文本用 `gdmusic_text_utils.gd`）；
5. 插件类 `extends "res://gdmusic_plugin_codegen/godot/base/gdmusic_plugin_methods.gd"`，保持 `get_platform()` / `get_supported_search_types()` 可调用，否则宿主 `_validate_plugin_instance()` 会拒绝；
6. 调试面板 `Refresh Plugins`（`assets/scripts/ui/music_app/music_app_showcase.gd:38`）验证搜索、播放地址、歌词三条链路；
7. 若要随包发布，放到 `plugins/builtin/` 并加进 `BUILTIN_PLUGINS`；若要给用户装，放到 `user://gdmusic_plugins/<id>/plugin.gd`。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| 音源无 `supportedSearchType` | 搜索页不出现该类型；宿主层面不阻止调用，由插件自行返回空 |
| 搜索只支持 `lyric` | 结果不能当作曲目播放（无 `getMediaSource`） |
| 自建服务未填凭证 | 请求失败，插件侧应写 `last_error`；未写则 UI 静默无结果（见 [插件系统与代码生成](2026-10-27_插件系统与代码生成.md) §4.6） |
| 播放地址为空 | 宿主统一提示「插件未返回可播放的音频地址。」 |
| 两个音源同名 `platform` | 后加载者覆盖前者，存档键跟着变，表现为「插件设置丢失」 |
| 上游 `srcUrl` 失效 | 只影响「重新拉取上游源码」，不影响已迁移的 `.gd` |

## 8. 已知限制与后续

- 22 个音源里 11 个只有 TS 源，App 内不可用；清单的「✓」只代表上游 `index.ts` 导出了该方法，不代表 GDScript 侧已迁移。
- 很多站点的真实可用性依赖 `appVersion` 门控（如 `kugou` 要求 `>0.1.0-alpha.0`）与签名算法（`bilibili` 的 WBI、`kugou` 的 mid 签名），迁移时比方法签名复杂得多。
- 官方音乐平台（网易云/QQ/酷狗/酷我/咪咕）均未实现 cookie 登录，付费曲目拿不到播放地址。
- 后续可做：把 `manifest.json` 里的能力/难度汇总接进插件管理页，让「哪些音源还差什么」在 App 内可见。
