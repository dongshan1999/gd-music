> 一句话定位：迷你播放器是主场景里一块**常驻底部面板**，不随页面切换销毁；它只负责「显示当前曲目 + 一个播放键 + 一个队列键 + 点一下进播放器页」，真正的播放状态全部向 `MusicAppController` 查询。

## 1. 功能概述

- **用户视角**：有歌在播时，底部浮起一条圆角面板：左边圆形封面（无封面时音符图标），中间歌名与歌手，右边播放/暂停键（外圈是播放进度环），再右侧是播放队列按钮；点面板空白处进入全屏播放器页。没有歌时显示「暂无播放 / 从首页选一首歌开始」的空态。
- **实现视角**：场景实例在主场景 `assets/scenes/music_app_showcase_scene.tscn:65`，子场景是 `assets/scenes/ui/music_app/mini_player/music_app_mini_player.tscn`；视图 `MusicAppMiniPlayerView` 把「读状态、调命令」全部转交给 `MusicAppMiniPlayerController`，自己不持有播放器；进度环是自绘 `MusicAppRingProgress`，只在进度事件里重设 `progress` 并 `queue_redraw()`。
- **与任务描述不符之处（以代码为准）**：
  - **没有显隐逻辑**：全仓没有任何 `mini_player.visible = ...` 赋值，迷你播放器**始终可见**，无曲目时退化成一个空态条；「播放器页打开时隐藏」实际靠全屏弹层覆盖实现，不是隐藏节点；
  - 因此 Toast 的 `104 / 28` 像素分支（有迷你播放器时抬高 104、否则 28）当前**恒为 104**（`assets/scripts/ui/music_app/controllers/global/music_app_popup_router_controller.gd:104`），28 分支是给未来「可隐藏的迷你播放器」预留的。

## 4. 关键实现

### 4.1 场景位置与尺寸：为什么是 -86 而不是 -82

子场景根 `MiniPlayer`（`assets/scenes/ui/music_app/mini_player/music_app_mini_player.tscn:47`）用 `anchors_preset = 12` 贴底横向：`offset_left = 12`、`offset_top = -82`、`offset_right = -12`、`offset_bottom = -12`，自身高度 70。主场景实例把 `offset_top` 覆盖为 **-86**（`assets/scenes/music_app_showcase_scene.tscn:65`），于是实际高度 **74px**、离屏幕底 12px。

差值 4px 是给 `StyleBoxFlat` 的 `shadow_size = 12` / `shadow_offset = (0, 4)` 留的视觉余量——Panel 的 `offset` 只约束内容矩形，阴影画在矩形外，如果贴底 12px 且不预留，阴影会在屏幕底边被裁掉一截；同时首页 `MarginContainer` 底部留白 100（`assets/scenes/ui/music_app/home/music_app_home_page.tscn:52`）保证列表最后一项不被这条常驻面板挡住。

### 4.2 点击热区：OpenButton 不能盖住播放键

`MiniOpenButton` 是铺满面板的透明按钮，用来「点任意空白进播放器页」。它天然会抢走右侧播放键/队列键的点击，所以布局完成后按播放键的实际位置收回右边界：

```gdscript
# assets/scripts/ui/music_app/views/mini_player/music_app_mini_player_view.gd:56-58
func _update_open_hit_area() -> void:
	mini_open_button.offset_right = \
		$Margin/Row/MiniPlaySlot.global_position.x - global_position.x - size.x - 6.0
```

要点：

1. 用 `global_position.x - global_position.x - size.x` 换算成「节点坐标系里的负偏移」，而不是假设父容器布局，窗口缩放/横竖屏切换都成立；
2. `- 6.0` 再让出 6px 间隙，避免边界像素误触；
3. 绑定在 `MiniPlaySlot.item_rect_changed`（`assets/scripts/ui/music_app/views/mini_player/music_app_mini_player_view.gd:42-54`）上，并用 `call_deferred` 触发首次计算——`_ready` 时容器还没排版，`global_position` 是旧值。

`MiniPlayButton` 与 `MiniListButton` 都是 `mouse_filter = STOP` 的普通按钮，绘制顺序在 `MiniOpenButton` 之前但 z 顺序更高，点击优先命中它们；`MiniOpenButton` 设 `focus_mode = FOCUS_NONE`，键盘/手柄不会多出一个焦点站。

### 4.3 进度环：自绘而不是 TextureProgressBar

```gdscript
# assets/scripts/ui/music_app/views/mini_player/music_app_ring_progress.gd:27-40
func _draw() -> void:
	var center := size * 0.5
	var radius := minf(size.x, size.y) * 0.5 - ring_width
	draw_arc(center, radius, 0.0, TAU, 64, track_color, ring_width, true)
	if progress <= 0.0:
		return
	draw_arc(center, radius, -PI * 0.5, -PI * 0.5 + TAU * progress, 64, progress_color, ring_width, true)
```

- 从 12 点方向（`-PI/2`）顺时针画，符合播放进度直觉；整圈底环用低透明度白色（0.18），进度用主题粉 `Color(1, 0.176, 0.333)`；
- `progress` 的 setter 做 `clampf` 并 `queue_redraw()`（`:4-7`），控制器传什么都不会画出越界弧；
- `_ready()` 把 `mouse_filter` 设为 `IGNORE`（`:24-25`），否则 54×54 的环会挡住下面 `MiniPlayButton` 的点击；
- 节点自身在编辑器里默认 `progress = 0.42`，只是为了让美术/策划在场景里看到一段弧，运行时会立刻被 `refresh()` 覆盖。

### 4.4 封面：本地/远程/占位三级兜底 + 10 秒超时

`refresh()` 在每次进度事件都会跑，但封面不能每次重建：

```gdscript
# assets/scripts/ui/music_app/views/mini_player/music_app_mini_player_view.gd:119-142（节选）
var artwork_key := "%s|%s" % [track.id, source]
if artwork_key == _artwork_key:
	return
_artwork_key = artwork_key
_artwork_request_id += 1
```

| 步骤 | 行为 |
| --- | --- |
| 1. 去重 | `track.id + artwork_source` 相同直接 return，避免每秒一次进度事件触发 `Image.load_from_file` |
| 2. 占位 | 先清空 `MiniCoverTextureRect.texture`，显示 `MiniCoverIconRect`（音符图标），Panel 背景用默认深灰 |
| 3. 本地 | `FileAccess.file_exists()` → `Image.load_from_file()` → `ImageTexture.create_from_image()`（`:196-202`） |
| 4. 远程 | `HTTPRequest.new()`、`timeout = 10.0`、挂在 `_controller` 下、`await request_completed`、`queue_free()`（`:205-233`） |
| 5. 校验 | 回来后比对 `_artwork_request_id` 与 URL（`:182-183`、`:226-227`），丢弃过期响应 |
| 6. 解码 | 按后缀选 `load_png/jpg/webp`，无后缀则三种依次尝试（`:236-259`） |

`REMOTE_ARTWORK_TIMEOUT_SECONDS = 10.0`（`:11`）是关键取舍：封面是弱网环境下最容易被拖住的资源，10 秒足够慢速 3G 拉一张 200KB 图，又不会让用户盯着占位图一分钟。请求节点挂 `_controller` 而不是 `self`，是为了让「视图被销毁但请求还在飞」时仍能安全 `queue_free`，不会因宿主节点释放而报错。

圆形封面不靠 `StyleBoxFlat` 圆角（TextureRect 不吃圆角裁剪），而是给 `MiniCoverTextureRect` 挂 `ShaderMaterial_mini_cover_mask`：像素在 UV 圆外 `discard`，所以无论封面图是方是长，都稳定裁成圆，且 `stretch_mode = 6`（KEEP_ASPECT_COVERED）先铺满再裁。

### 4.5 空态

`refresh()` 的空队列分支（`:65-71`）：

| 元素 | 空态表现 |
| --- | --- |
| 封面 | 清空纹理、显示音符占位 |
| 歌名 | `tr("music_app.mini_player.empty")` →「暂无播放」 |
| 歌手 | `tr("music_app.ui.mini_hint")` →「从首页选一首歌开始」 |
| 进度环 / 播放键 | `progress = 0` 不画弧；`PLAY` 图标（点了没反应，`_toggle_playback` 里 `has_tracks()` 为假直接 return） |

### 4.6 显示/隐藏与 Toast 避让（实际行为）

| 场景 | 任务描述期望 | 实际代码 |
| --- | --- | --- |
| 无曲目 | 隐藏 | 仍显示，进入空态（`:65-71`） |
| 播放器页打开 | 隐藏 | 仍显示，被 `FullscreenPopupHost`（场景 `:69`，绘制在 `:65` 之后）整屏覆盖 |
| 播放队列页打开 | 隐藏 | 同上，被全屏宿主覆盖 |
| Toast 位置 | 有迷你播放器 104px、无则 28px | 路由器判断 `mini_player.visible`（`:104`），但该值恒为 `true` → 恒 104px |

Toast 的 `show_message(message, bottom_offset)` 默认值就是 104（`assets/scripts/popup/common_toast_popup.gd:29`），位置算法 `y = layout_height - bottom_offset - toast_height`（`:86-100`），即「距底 104px 再往上放」——正好落在迷你播放器上沿之上，不遮挡。

**为什么不做隐藏**：迷你播放器是常驻控制面，隐藏会让「暂停/继续」多一步跳转；用全屏弹层覆盖的好处是播放器页关闭后无需恢复状态，节点树和封面纹理都不重建，返回时没有闪烁。代价是空态条常驻，以及 Toast 分支变成死代码。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| 无曲目 | 空态；播放键/展开键都不会崩（展开键仍可进播放器页看「无曲目」态） |
| 时长为 0（流媒体/未解析） | `get_playback_progress_ratio()` 返回 0，进度环不画弧 |
| 封面路径失效 / 格式不支持 | 本地 `file_exists` 为假直接返回；后缀不在 png/jpg/webp 内时三种解码依次尝试，全失败保持占位 |
| 远程封面 4xx/5xx 或超时（10s） | 检查 `RESULT_SUCCESS` 且 `200 <= code < 300`，否则放弃，占位图保持、不重试 |
| 快速切歌 | `_artwork_request_id` 自增使旧响应失效；旧连接 `queue_free` |
| 视图销毁时请求在飞 | 请求挂在 `_controller` 下，`await` 恢复后先判 `is_instance_valid`，不会 use-after-free |
| 长歌名/歌手 | Label `clip_text = true` + `text_overrun_behavior = TRIM_ELLIPSIS`，不撑破布局 |

## 8. 已知限制与后续

- **无显隐动画**：常驻 + 空态是当前设计，若后续要「无曲目隐藏」，必须同步把 Toast 的 28px 分支接上，否则 Toast 会悬在空白处。
- **Toast 避让是死分支**：`mini_player.visible` 恒真，`28.0` 永远走不到；建议要么删掉分支，要么改成「面板实际可见且非空态」的判断。
- **占位图忽略曲目参数**：`_apply_cover_placeholder(track)`（`:154-156`）签名带 `track` 但实现恒用默认配色，注释里「按曲目取色」的意图没落地，属于可清理的接口噪音。
- **远程封面无缓存**：每次切回同一首歌都会重新请求（`_artwork_key` 只在当前曲目内去重）；对列表反复切换的场景，建议加一层按 URL 的内存/磁盘缓存。
- **无加载态**：远程封面在 10 秒超时窗口内只显示音符占位，没有 loading 指示；慢网下用户无法区分「加载中」和「没有封面」。
- **进度环精度**：`progress` 是浮点比例、按秒级进度事件更新，短音频（<10s）的弧会一跳一大段；如需平滑可在 Tween 里插值。
