> 一句话定位：曲目信息编辑只改「本机显示名」：标题与艺术家写回存档里的 `TrackData`，同时同步已下载记录；不读改音频标签、不碰音源平台。弹窗打开时锁定的是「当前播放曲目」。

## 1. 功能概述

用户视角：

- 播放器页正在播放的标题、艺术家文字可以点击（鼠标变手型、有 tooltip），点击后弹出居中的「编辑曲目信息」；
- 弹窗有「歌名」「UP 主 / 艺人」两个输入框，歌名必填；
- 标题框回车跳到创作者框，创作者框回车直接保存；底部「取消」关闭，「保存」写回并提示「已更新曲目信息」；
- 没有播放中的曲目时，弹窗里两个输入框与保存按钮都是禁用的，并提示「当前没有播放中的曲目。」；
- 说明文案按来源区分：B 站曲目提示「作者其实是 UP 主」，其它曲目提示「只修改本机曲库里的显示名称」。

实现视角：

- 弹窗 `MusicAppTrackEditPopup` 只管界面与提示，业务规则在 `MusicAppTrackEditController`；
- 目标曲目 = `get_current_track()`（`selected_track_id` 对应的曲目），不是队列游标；
- 保存时 `strip_edges()` 后空标题直接拒绝，艺术家允许为空；写入后 `track.normalize()`、同步下载记录、`save(false)` 标记脏数据。

与任务描述的偏差（以代码为准）：

| 描述 | 实际 |
| --- | --- |
| 字段：标题 / 艺术家 / 专辑 / 封面 | 只有标题与艺术家两个字段。场景里没有专辑与封面控件，控制器也不写这两个属性 |
| 保存到存档 | 有。`save_manager.save(false)`（`dx/runtime/scripts/managers/save/save_manager.gd:45-48` 只标记脏数据，由存档链路延后落盘） |
| 把封面写回音频文件 | 不存在。`assets/scripts/save/music/audio_artwork_reader.gd:19` 只有 `read_embedded_artwork()`，全仓库没有写标签/写封面的实现 |
| 本地与插件曲目的差异 | 只有提示文案不同（B 站特判）与下载记录联动；保存规则完全一致，`plugin_data` 不动 |

## 3. 核心数据结构

编辑对象不是独立模型，而是全局 `tracks` 里的那个 `TrackData`（`assets/scripts/save/music/track_data.gd`）：

| 字段 | 行号 | 编辑弹窗是否修改 | 说明 |
| --- | --- | --- | --- |
| `title` | :4 | 是（必填，strip 后非空） | 显示名 |
| `artist` | :5 | 是（可为空） | 创作者 |
| `subtitle` | :6 | 否 | 列表副标题第二段 |
| `file_path` / `lyric_path` | :7-8 | 否 | 本地文件与歌词 |
| `duration` / `preview_start` | :9-10 | 否 | 时长与试听起点 |
| `source` / `plugin_id` / `plugin_data` | :13-15 | 否 | 来源与插件扩展字段 |

ID 生成规则（`assets/scripts/save/music/track_data.gd:17-43`）：本地曲目 `id` 为 `file_path` 的 SHA-256（`:32-36`），插件曲目使用插件生成的稳定 ID（`:38-43`）。**`title` 不参与 ID 计算**，所以改歌名不会让歌单、播放队列、下载记录里的引用失效——这是「随便改名」能安全实现的前提。

返回值约定（`assets/scripts/ui/music_app/controllers/music_app_track_edit_controller.gd:19-36`）：

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `ok` | `bool` | 是否保存成功 |
| `error` | `String` | 失败时的可读文案，界面直接 toast |

## 4. 关键实现

### 4.1 目标曲目取当前播放项

```gdscript
func get_target_track() -> TrackData:
	return get_current_track()
```

`get_current_track()` 走 `playback_state.selected_track_id`（`assets/scripts/ui/music_app/controllers/music_app_controller_base.gd:190`），而不是 `track_ids[queue_index]`。原因是 `selected_track_id` 在任何切换路径（队列点行、歌单播放、插件播放）都会被同步更新，是「此刻正在播放什么」的唯一权威指针；直接读队列数组则要处理游标越界、队列被替换等边界。

### 4.2 保存规则与校验

`save_track_info()`（`assets/scripts/ui/music_app/controllers/music_app_track_edit_controller.gd:19-36`）的顺序：

1. 取不到目标曲目 → `{"ok": false, "error": "当前没有播放中的曲目。"}`；
2. `next_title.strip_edges()` 为空 → `{"ok": false, "error": "歌名不能为空。"}`，**此时原曲目未被修改**，测试专门断言了这一点；
3. 写入 `track.title` 与 `track.artist`（艺术家同样 strip，允许空串）；
4. `track.normalize()`：钳制时长、补齐缺失 ID 等一致性处理；
5. `_sync_download_record(track)`；
6. `save_manager.save(false)`。

先校验再写入，是为了让失败路径不留下「改了标题但没改艺术家」的半成品状态。界面侧失败只 toast、不关窗（`assets/scripts/popup/music_app_track_edit_popup.gd:70-72`），用户可以改完再试。

### 4.3 下载记录联动

```gdscript
var record: MusicDownloadRecordData = downloads.get_download_record(track.id)
if record == null:
	return
record.title = track.title
record.artist = track.artist
record.normalize()
```

下载列表与播放器是两套渲染：下载列表显示的是 `MusicDownloadRecordData` 里的名字（`assets/scripts/ui/music_app/controllers/music_app_track_edit_controller.gd:39-48`），不同步就会出现「播放器里改了，下载列表还是旧名」。按 `track.id` 查记录，查不到就静默跳过——没下载过的曲目本来就没有记录。

### 4.4 提示文案按来源区分

`get_hint_text()`（`:11-16`）对 `plugin_id == "bilibili"` 返回专门的文案。B 站视频的「作者」实际是 UP 主，被当作艺术家显示后用户会困惑，所以提示里明确说「这里只改本机显示，不会改动视频本身」；其它来源统一提示改的是本机曲库。

场景里 `TrackEditHintLabel` 的默认文本写死在 `assets/scenes/popup/music_app_track_edit_popup.tscn:58`，`refresh()` 打开后会立刻用控制器文案覆盖（`assets/scripts/popup/music_app_track_edit_popup.gd:58`），所以默认值只是编辑器里的占位。

### 4.5 弹窗交互细节

`refresh()`（`assets/scripts/popup/music_app_track_edit_popup.gd:39-59`）：

- 无曲目：清空两个输入框、`editable=false`、保存禁用、提示「当前没有播放中的曲目。」；
- 有曲目：回填标题与艺术家，`caret_column` 移到末尾，用户直接输入就是追加/修正；
- 两个输入框都监听 `text_submitted`：标题回车只是把焦点交给创作者（`:61-63`），创作者回车等价于点保存（`:34`）。这样单手操作时不用去点小按钮。

保存成功后 `show_toast("已更新曲目信息")` 再 `close_popup()`（`:74-75`）；失败只 toast 错误文案并保留弹窗。

### 4.6 入口绑定与可点击标签

`_bind_track_metadata_input()`（`assets/scripts/ui/music_app/views/player/music_app_player_view.gd:98`）把 `now_title_label` 与 `now_artist_label` 的 `mouse_filter` 设为 `MOUSE_FILTER_STOP`、光标改为手型并加 tooltip「点击编辑曲目信息」——`Label` 默认不吃鼠标事件，不显式改 `mouse_filter` 时点击会穿透到父容器，看起来像「点不动」。

`_open_track_edit()`（`:115-118`）先判 `has_tracks`，没有队列时直接返回，避免弹出一个「没有播放中的曲目」的窗口。弹窗内还做了同样的兜底（禁用控件），两层保护。

## 5. 边界与失败处理

| 场景 | 处理 | 位置 |
| --- | --- | --- |
| 没有播放中的曲目（入口层） | `_open_track_edit()` 直接返回，不弹窗 | `assets/scripts/ui/music_app/views/player/music_app_player_view.gd:115-118` |
| 没有播放中的曲目（弹窗层） | 输入框禁用、保存禁用、提示文案 | `assets/scripts/popup/music_app_track_edit_popup.gd:44-51` |
| 标题为空或全空格 | 返回错误文案，原数据不变 | `assets/scripts/ui/music_app/controllers/music_app_track_edit_controller.gd:24-26` |
| 艺术家为空 | 允许，写入空串 | `:29` |
| 已下载曲目找不到下载记录 | 静默跳过同步 | `:43-45` |
| 保存失败 | toast 错误、弹窗不关，用户可继续修改 | `assets/scripts/popup/music_app_track_edit_popup.gd:70-72` |
| 取消 | 直接 `close_popup()`，不写任何数据 | `assets/scripts/popup/music_app_track_edit_popup.gd:31` |
| 覆盖层点击 | 不关闭。场景里 `Overlay` 只是遮罩，没有绑定点击关闭 | `assets/scenes/popup/music_app_track_edit_popup.tscn:16` |

有一个真实存在的风险：弹窗只在自己 `on_popup_shown` 时 `refresh()` 一次，打开后如果外部切了歌（例如键盘快捷键、队列自动推进），输入框仍是旧曲目的值，而保存时 `get_target_track()` 取的是**保存那一刻**的当前曲目——会把旧文本写到新曲目上。当前没有监听 `track_changed` 之类的信号，见第 8 节。

## 8. 已知限制与后续

- 只有标题与艺术家。任务描述里的专辑、封面字段没有实现，控制器也不写 `subtitle`/`album` 一类的属性。
- 不写回音频文件：没有标签写入与封面嵌入能力，`audio_artwork_reader.gd` 只读。想在别的播放器里看到新名字，必须等后续接入标签写入库。
- 弹窗打开期间切歌会写错对象（见 5 节）。建议监听 `playback_state` 变化或在 `save_track_info()` 里比对「弹窗打开时的 track_id」与当前 `track.id`，不一致就提示「当前播放已变化，请重新打开」。
- 覆盖层点击不关闭，与大多数弹窗的直觉不一致；要么绑定关闭，要么把行为写进产品说明。
- 改名后没有去重：两首歌可以被改成同名，列表里会出现两条一样的标题（各自 ID 不同，播放不受影响）。
- 保存只标记脏数据，若进程在落盘前被杀，改动会丢失。
