# DX 调试工具（功能实现文档）

| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | `develop` 分支，工作区 2026-10-27（HEAD `91d939d`） |
| 功能分类 | DX 框架 / 运行时调试 |
| 覆盖范围 | `dx/runtime/scripts/debug/`、`dx/runtime/scenes/debug/`、`dx/runtime/scripts/managers/debug/`（占位）、`dx.tscn` 的 `DebugLayer` |

> 一句话定位：debug 构建里，按 `F10` 或在 `DebugLayer` 的触发按钮上 1.2 秒内连点 3 次，会打开一个四页签浮层（选项 / 日志 / 系统 / 性能）；业务对象通过 `DX.debug.register_*` 把自己暴露成可读可写的调试项，release 构建里所有注册调用都是空操作。

## 1. 功能概述

- **用户视角**（开发者）：真机上不接 ADB 也能改参数——调时间倍速、切播放器状态、看 FPS/内存/节点数、按级别筛日志、全文搜日志、一键复制日志。
- **实现视角**：
  - 触发器 `DX_DebugTrigger` 是 `DebugLayer`（`CanvasLayer.layer = 10000`）下的一个 `Control`，两种触发：`F10` 键盘事件（`_input`）与按钮连点计数。
  - 面板 `DX_DebugPopup` 是一个注册在 `DX_PopupRegistry.PopupId.DX_DEBUG` 的普通弹窗，走 `DX.popup.show()`，因此同样遵守弹窗的层级/复用规则。
  - 调试项由 `DX_DebugManager` 的 `_targets` 字典维护，面板每次重建时读 `get_target_descriptors()`。
- **不在本期范围**：没有远程调试通道、没有作弊码命令台、没有场景树浏览器；`debug_options_data.gd` 的 `OptionsScripts` 当前为空数组，即"选项脚本自动发现"机制在本项目未启用。

## 3. 核心数据结构

### 3.1 调试项（`dx/runtime/scripts/debug/debug_manager.gd:238-264` 的 `item` 字典）

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `target_id` | `String` | 归属对象 ID，默认取脚本 `class_name` 或 `DX_DebugManager` 的 `resolve` 结果 |
| `type` | `String` | `action` / `string` / `number` / `boolean` / `select` / `readonly`（`:8-13`） |
| `group` | `String` | 分组名，`""` 归一化成 `"Default"`（`:7`、`:384`） |
| `name` | `String` | 面板显示名，空则回退 `member_name`（`:388`） |
| `member_name` | `String` | 读写用的属性名 / 方法名 |
| `is_method` | `bool` | `action` 为 `true`，属性类为 `false` |
| `range` | `Dictionary` | 仅 `number`：`{min, max, step}`，面板据此选 Spin/Slider |
| `options` | `Array` | 仅 `select`：每项 `{label, value}` |
| `getter` | `Callable` | 仅 `readonly`：值从 Callable 取，不读属性 |
| `callback` | `Callable` | `register_callable_action` 注册的动作 |

### 3.2 目标（`_targets`，`dx/runtime/scripts/debug/debug_manager.gd:24`）

```gdscript
_targets[target_id] = { "id": target_id, "target": Object, "items": [item...] }
```

`get_target_descriptors()`（`:137-159`）遍历时做两件清理：目标已 `free` 的条目直接 `erase`；`items` 为空的跳过。返回值是 `{id, items, group_display_modes}`，供面板直接渲染。

### 3.3 日志条目（`dx/runtime/scripts/managers/logger.gd:201-215`）

| 键 | 含义 |
| --- | --- |
| `time` | `dx.time.now().format("yyyy-MM-dd HH:mm:ss")`，无 time 时用系统时间（`:259-262`） |
| `tag` | 标签（分组过滤用），可为空 |
| `level` | `INFO` / `WARN` / `ERROR`（`:5-7`） |
| `message` | 原始消息 |
| `text` | `"[time] [tag] message"` 拼好的完整行（面板直接显示） |

环形缓冲 `MAX_ENTRIES = 200`（`:4`），`_revision` 自增供面板做增量刷新（`:113`）。

## 4. 关键实现

### 4.1 为什么所有注册 API 都以 `OS.is_debug_build()` 开头

```gdscript
# debug_manager.gd:38-40
func register_target(target_id: String, target: Object) -> void:
	if not OS.is_debug_build() or not _is_valid_target(target):
		return
```

同一个门出现在 `_register_member_item()`（`:248`）、`register_readonly()`（`:93`）、`register_callable_action()`（`:118`）、`discover_targets()`（`:162`）、`dx/runtime/scripts/debug/debug_options_registry.gd:18`。

目的有两个：

1. **release 构建不持有业务对象引用**：`_targets` 里的 `target` 是强引用，若 release 也注册，弹窗一关但目标已 `queue_free` 时就要靠 `_prune` 兜底，且会让本该释放的控制器延迟一轮；直接不注册最干净。
2. **开关成本为零**：业务代码可以无条件写 `DX.debug.register_number(...)`，不用每处自己套 `if OS.is_debug_build()`；release 里就是一次函数调用 + 一次常量判断。

`_is_valid_target()`（`:392`）额外要求目标 `is_instance_valid()` 且不是 `RefCounted` 之外的失效对象，避免注册瞬间目标已被释放。

### 4.2 六类注册 API 与面板控件的对应

| API（`debug_manager.gd`） | 面板控件（`dx_debug_popup.gd`） | 写回方式 |
| --- | --- | --- |
| `register_action(group, target, method_name, name)`（`:59`） | 按钮，点击 `invoke_action()` | `target.call(method_name)`（`:171-180`） |
| `register_number(..., value_range)`（`:62`） | 有 `range` 用 Slider（`:345`），否则 SpinBox（`:325`） | `write_number()` 按属性原类型回写 int/float（`:197-207`） |
| `register_string(...)`（`:74`） | LineEdit，提交或失焦时写 | `write_string()`，`StringName` 属性自动转换（`:209-218`） |
| `register_boolean(...)`（`:77`） | CheckButton | `target.set()`（`:220-223`） |
| `register_select(..., options)`（`:80`） | OptionButton，按当前值选中（`:384-399`） | `write_select()`，保留 `StringName`/`int` 原类型（`:225-236`） |
| `register_readonly(group, getter, name)`（`:92`） | 只读文本 | 每次重建调 `getter.call()`（`:182-186`） |

读值统一走 `read_item_value()`（`:182`）：有 `getter` 用 `getter`，否则 `target.get(member_name)`。这也是 `readonly` 能展示"计算值"（如 FPS、节点数）而不需要一个真实属性的原因。

### 4.3 触发按钮连点：`F10` 之外的移动端入口

`_register_trigger_tap()`（`:40-51`）：

```gdscript
var reset_msec := int(maxf(0.1, tap_reset_seconds) * 1000.0)   # 默认 1.2s
if _last_tap_msec <= 0 or now_msec - _last_tap_msec > reset_msec:
	_tap_count = 0
_tap_count += 1
if _tap_count < maxi(1, required_tap_count):   # 默认 3
	return false
```

设计意图：Android 上没有 `F10`，而调试按钮又不能太显眼——所以按钮本身做成一个小热点（`@export var debug_only := true`，release 里 `visible=false`），要求"短时间连点"，避免用户误触单次就弹出调试面板。`required_tap_count` / `tap_reset_seconds` / `keyboard_shortcut_keycode` 都是 `@export`，可在场景里改（`:9-14`）。

### 4.4 面板打开时把触发按钮藏起来

`_resolve_and_hide_trigger()`（`:533-541`）与 `_restore_trigger()`（`:569-575`）：面板铺满全屏后，触发按钮若还在 `DebugLayer` 上会盖在面板之上或与其抢点击，所以打开时隐藏、`on_popup_hidden()` 时恢复（`:70`）。

面板同时持有 `_trigger_control` 引用（`:48`），恢复时优先恢复原节点；找不到时按组名 `"dx_debug_trigger"`（`:11`）重新找。这是"面板与触发器解耦"的兜底——两者都可能在别的场景里实例化。

### 4.5 四页签的数据来源

| 页签 | 常量 | 数据来源 |
| --- | --- | --- |
| 选项 | `TAB_OPTIONS = 0`（`:7`） | `DX.debug.get_target_descriptors()`，按 target/group 折叠（`:101-116`、`:141-208`） |
| 日志 | `TAB_LOG = 1`（`:8`） | `DX.logger.get_entries()` + 本地搜索/级别过滤（`:307-318`） |
| 系统 | `TAB_SYSTEM = 2`（`:9`） | `debug_metrics.get_system_descriptors()`：FPS、平台、Godot 版本、debug 构建、窗口尺寸、当前场景（`dx/runtime/scripts/debug/debug_metrics.gd:6-19`） |
| 性能 | `TAB_PROFILER = 3`（`:10`） | `get_profiler_descriptors()`：进程/物理帧耗时、静态内存、对象/节点/资源/孤儿节点数、绘制调用（`dx/runtime/scripts/debug/debug_metrics.gd:21-36`） |

日志页的过滤是"级别三开关 + 全文搜索"（`dx/runtime/scripts/debug/debug_log_view.gd:44-56`），`rebuild()` 每次都重建 VBox 子节点（`:13-25`）——日志只有 200 条，重建比增量维护简单且不会错位。

### 4.6 日志采集是"全局"的，不只在 debug 构建

`DX_Logger._init()` 与 `in_ready()` 都会 `_register_engine_logger()`（`dx/runtime/scripts/managers/logger.gd:53-60`、`:247-252`），把自定义 `Logger`（`DXEngineLogger`）挂到 `OS.add_logger()`，从而捕获 `push_error`、GDScript 运行时错误、引擎告警；`_capture_native_message()`（`:148-164`）再加 `_suppress_native_once()` 去重，避免"自己打的日志被原生回调重复记一遍"（`:232-246`）。

注意：**采集与展示分离**——release 也采集（业务用 `dx.logger.error()` 上报/落盘），只是没有面板可看；因此日志相关能力不能当"只在 debug 启用"用。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| release 构建调用 `register_*` | 静默返回，不报错、不注册、不持有引用 |
| 注册时目标已释放 | `_is_valid_target()` 返回 false，直接丢弃（`:392-393`） |
| 面板打开时某个目标已 `free` | `get_target_descriptors()` 里 `erase` 该条目，其余照常（`:144-148`） |
| `OptionsScripts` 为空 | `discover_targets()` 扫不到任何脚本，选项页只剩手动注册的项 |
| `show_popup` 不可用（非本项目的 showcase） | 退化为在 `DebugLayer` 上手动实例化 `dx_debug_popup.tscn` 并 `setup()`（`:70-85`） |
| `showcase_path` 指向的节点不存在 | `_open_debug_popup()` 依次回退 `get_parent()` → `get_tree().current_scene`，全空则返回 false（`:54-60`） |
| `F10` 被编辑器占用 | `_input` 里 `get_viewport().set_input_as_handled()` 只在成功打开后调用（`:33-34`），不抢占编辑器 |
| 日志超过 200 条 | 环形覆盖最旧条目，`_revision` 递增触发面板刷新 |
| 多线程打日志 | `_mutex` 保护 `_entries`（`dx/runtime/scripts/managers/logger.gd:49`），面板读的是副本（`get_entries()` 返回 `duplicate`） |
| 面板刷新时目标属性类型变了 | `write_number`/`write_select` 按**当前值类型**分支回写，不会因为属性从 int 改成 float 就写错类型 |

## 6. 相关测试与业务用法

| 位置 | 用法 |
| --- | --- |
| `dx/runtime/scenes/managers/dx.tscn:14-17` | `DebugLayer`（layer 10000）与 `DXDebugTrigger` 实例 |
| `dx/runtime/scenes/debug/dx_debug_trigger.tscn` | 触发按钮场景（`TriggerButton`、`%` 唯一名） |
| `dx/runtime/scenes/debug/dx_debug_popup.tscn` | 面板场景（四页签 + 日志列表 + 刷新 Timer） |
| `assets/scripts/ui/music_app/controllers/music_app_controller_base.gd` | 业务控制器在 `_ready` 里 `DX.debug.register_*` 暴露自身字段（推断：按项目约定接入） |
| `dx/runtime/scripts/debug/debug_options_data.gd:4-6` | `OptionsScripts` 占位空数组，改这里可启用"选项脚本自动发现" |

手工验证：

1. 用 **Debug** 导出/编辑器运行 → `F10` → 面板出现，四个页签可切；
2. 点击触发按钮 3 连点（间隔 < 1.2s）→ 同样打开；单点不打开；
3. 用 **Release** 运行 → 触发按钮不可见、`F10` 无效、`register_*` 不报错；
4. 在面板改一个 `number` 项 → 后台控制器字段立即变化；改 `select` 项 → `StringName` 属性仍是 `StringName`；
5. 日志页输入关键字 → 只显示匹配行；关掉 `WARN` 开关 → 警告消失，切回页签仍保持过滤状态。

## 8. 已知限制与后续

- 只有 debug 构建可用；想在 release 复现问题必须重新打 debug 包；
- "选项脚本自动发现"（`debug_options_registry.gd`）依赖 `OptionsScripts` 非空，本项目为空，等于只有手动 `register_*` 一条路；
- 日志只在内存（200 条），关掉面板/重启即丢，没有落盘或导出到文件（复制只能到剪贴板）；
- 调试面板本身是 `DX_PopupView`，与业务页面共用弹窗栈，若业务侧把全屏页压在它上面，面板会被盖住；
- `get_target_descriptors()` 每次重建都全量遍历 + `_prune`，目标很多时（几十个脚本）面板打开会有可感知的卡顿；
- 没有"只读/可写"权限模型：能注册就能写，误改关键字段（例如播放器状态机）可能导致运行期状态不一致。
