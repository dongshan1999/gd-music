| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 对应代码版本 | develop @ 91d939d（工作区 2026-10-27） |
| 功能分类 | 应用界面 / 音源插件 |
| 覆盖范围 | `views/plugin_browser/` 视图与子组件、`controllers/music_app_plugin_browser_controller.gd`、全局 `MusicAppPluginController` 的 `search()`/`list_plugins()`、音乐存档中的 `plugin_search_history` |

> 一句话定位：插件浏览器是「选音源插件 → 选搜索类型 → 输关键词 → 看结果」的单一搜歌页；界面由 `MusicAppPluginBrowserView` 承担，搜索与历史由 `MusicAppPluginBrowserController` 转发到全局插件控制器和存档。

## 1. 功能概述

- 用户视角：从首页进入「插件搜索」，页面顶部是返回键 + 搜索框 + 搜索按钮；未搜索时展示「历史记录」标签流，搜索后展示三层内容：搜索类型 tab（单曲 / 专辑 / 作者 / 歌单）、插件 tab（每个已启用插件一个）、结果列表与底部「上一页 / 第 N 页 / 下一页」分页条。点击结果行，单曲直接播放，专辑/作者打开临时合集页。
- 实现视角：严格的两层结构 —— 视图 `music_app_plugin_browser_view.gd`（726 行）只做渲染与交互；`MusicAppPluginBrowserController`（199 行）负责搜索历史、把搜索结果转成 `TrackData`、发起播放、构造临时歌单；真正调用插件的 `search()` 在全局控制器 `MusicAppPluginController.search()`。属于「视图 + 轻控制器 + 全局域控制器」模式，与其它页面一致。
- 不在本期范围（以真实代码为准，与任务描述有偏差）：
  - **没有「加载更多 / 无限滚动」**，分页是显式的上一页/下一页按钮（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:376`）。
  - **没有结果项长按或「更多操作」菜单**。结果行右侧的 `⋮` 只是 `MoreLabel` 装饰标签，没有点击处理；行内唯一交互是整行 `HitButton`（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:526`）。
  - **没有「加入队列 / 加入歌单 / 下载」入口**。播放语义固定为「空队列时播放整页结果、非空队列时插到队首单曲播放」（`assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:73-99`）。
  - **没有「歌单推荐」**。首页才有推荐歌单；本页的「歌单」只是 `_get_search_type_label()` 里的一个搜索类型文案（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:304-317`），且插件若未声明 `playlist` 类型就不会出现该 tab。

一次搜索的完整链路：

1. 视图取当前插件、校验 `hasSearch`、校验关键词非空（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:616-628`）。
2. 记录 `previous_page`、写入 `_last_query`，进入 searching 态（按钮文案变「搜索中」并整体禁用，`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:439-442`）。
3. `await MusicAppPluginController.search(plugin_id, query, page, media_type)`（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:319`），内部 `await plugin.search(query, maxi(1, page), media_type)` 并把插件异常写进 `last_error`（`:329-332`）。
4. 回来后先做「请求是否过期」校验：插件、搜索类型、输入框文本任一变过，就丢弃本次结果并按新条件重搜第 1 页（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:645-648`）。
5. 成功后写页码、压历史、读回历史、重建标签、按 `data` / `isEnd` 字段刷新结果（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:659-671`）。
6. 点结果行时再分叉：`music` 类型先 `resolve_collection_result()` 探一次合集曲目数，>1 则改判为 `album`（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:534-540`）；`album`/`artist` 走 `open_collection_result()`，否则走 `play_search_result()`（`:541-551`）。

## 4. 关键实现

### 4.1 两级 tab：搜索类型 + 插件

`_render_tabs()` 同时重建两行 tab，逻辑复用一个 `_sync_tab_row()`（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:155-175`）：先 `queue_free()` 旧节点再按 items 实例化，不做节点 diff。tab 数量等于插件数或插件声明的 `supportedSearchType` 数（个位数），重建成本远低于维护「复用 + 换绑信号」的复杂度。搜索类型缺省回落到 `music`（`:10` `:181-182`）；切换插件时如果新插件不支持当前类型，自动切到它的第一个类型（`:515-519`）。

### 4.2 搜索竞态：用「三个条件是否仍然成立」代替取消请求

插件搜索是 `await` 的网络调用，无法中途取消。实现不去做取消，而是在结果回来后校验请求快照（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:645`）：

```gdscript
if plugin_id != _get_selected_plugin_id() or requested_type != _get_selected_search_type() or query != query_input.text.strip_edges():
    if not query_input.text.strip_edges().is_empty():
        await _search_page(1)
    return
```

这样「快速连点两次搜索、或搜索中途切换插件」都不会让旧结果覆盖新结果；条件不成立且输入框仍有关键词时，直接以最新条件重搜第一页。同一时刻只允许一个搜索在飞：`_search_page` 入口 `if ... or _is_searching: return`（`:614`）。

### 4.3 分页：显式上一页/下一页，空页也要能翻

分页条不是场景里的节点，而是首次用到时用代码建的（`_ensure_pagination_bar()`，`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:376-403`），按钮复用主题 `SegmentButton`，三个子节点命名固定为 `PrevPageButton` / `PageLabel` / `NextPageButton`。可见性规则在 `_sync_pagination_state()`（`:415-426`）里，注释写明了两个坑：

```gdscript
# 有结果时始终显示分页条；首末页通过禁用态表达，避免用户以为翻页入口又丢了。
# 结果为空但后面还有页时也要显示：插件侧过滤（例如「专辑」标签只留合集）
# 可能让整页变空，此时用户仍需要能翻到下一页。
_pagination_bar.visible = has_query and (has_results or not _last_is_end)
```

翻页失败时页码要回滚，否则会出现「页码前进但列表空白」（`:649-656`）。

### 4.4 结果渲染分帧 + 渲染代号

一页结果可能到几十条，一次性 `instantiate` + `add_child` 会卡住主循环（音频也在主循环里跑）。`_render_results()`（`:203-221`）只做清场与空态判定，然后 `call_deferred("_render_result_rows_batched", render_generation)`；批量函数每帧最多建 `RESULT_ROWS_PER_FRAME = 6` 行（`:14`），帧间 `await get_tree().process_frame`（`:244`）。每次重建都自增 `_result_render_generation`，批量循环每帧开头比对代号，不一致立刻 `return`（`:227-228`），避免上一轮没建完的行混进新结果。

### 4.5 点结果：单曲播放 vs 打开合集

`_on_result_row_pressed(index)`（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:526-551`）的判定顺序：

1. `result_type` 取 `collectionType` / `mediaType` 里的 `album`，否则用当前搜索类型。
2. 若 `result_type == "music"`，先 `await resolve_collection_result()` 探合集曲目数 —— 因为 B 站「单曲」tab 里的一个视频本身可能是多 P 合集，必须先看页面数据才能决定行为（代码注释 `:532-533`）。
3. `album` / `artist` → `open_collection_result()`；其它非 `music` 类型 → toast「当前搜索类型暂不支持打开详情」；`music` → `play_search_result()`。

播放语义在 `assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:73-99`：队列非空时 `play_track_at_queue_top(selected_id)`（不打断当前队列，只把这一首放到队首）；队列为空时把整页结果按顺序塞成播放队列并从选中项开始播。搜索结果先经 `ensure_plugin_track_from_search_result()` 落成 `TrackData`，`track.id` 格式固定为 `plugin:<插件id>:<媒体id>`，两段都 `uri_encode()`（`:46`），这样同一首歌跨页反复出现时能命中已有曲目而不是重复插入（`:47-50` 线性查重）。

合集打开会新建**临时歌单**：`mark = "__plugin_collection__"`、`deletable = false`，然后以全屏层打开歌单弹窗（`assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:131-145`）。注释说明了为什么不能复用已收藏歌单：`# 每次从搜索打开都创建独立的临时展示歌单。不能直接复用已收藏歌单，否则弹窗会显示成“已收藏”状态，收藏按钮也会错误地消失`（`:138-139`）。打开前先 `_cleanup_temporary_collections()` 清掉上一份临时歌单并修正 `selected_playlist_index`（`:162-171`）。

### 4.6 搜索历史：10 条、去重置顶

`push_plugin_search_history()` 先 `erase` 再 `push_front`，最后 `resize(10)`（`assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:14-24`）；`remove_plugin_search_history()` / `clear_plugin_search_history()` 分别供标签上的 `×` 与「清空」按钮使用（`:27-39`）。历史只在**搜索成功**后才写入（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:660`），失败或空关键词不会污染历史列表。

### 4.7 管理面板（内嵌于搜索页）

页面底部 `ManagementPanel`（场景 `assets/scenes/ui/music_app/plugin_browser/music_app_plugin_browser_page.tscn:223`）是开发期遗留的插件管理入口，默认隐藏，由 `ManageToggleButton`（`:251`）以「Manage / Hide」切换（`assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:553-555`）。内含启动/刷新插件、按路径安装、按 URL 安装、插件信息文本；`_set_plugin_info()` 会把名称、版本、搜索类型、作者、描述拼进 `PluginInfoLabel`（`:265-285`）。注意：**按 URL 安装实际不可用**，全局控制器写死返回失败（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:131-132`），界面上会显示 `last_error`。

### 4.8 三种中间态

| 状态 | 表现 | 位置 |
| --- | --- | --- |
| 加载中 | 搜索按钮文案「搜索中」并禁用；开始/刷新按钮、清空历史同时禁用 | `assets/scripts/ui/music_app/views/plugin_browser/music_app_plugin_browser_view.gd:368-371` `:439-442` |
| 空结果 | 结果区显示 `EMPTY_RESULT_TEXT`「暂无搜索结果」；未搜索时显示「请选择插件并输入搜索关键字」 | `:215-218` `:12-13` |
| 失败 | `_show_error()` 弹公共确认框（标题固定 `Plugin Search`）；轻提示走 `_toast()`；翻页失败额外回滚页码 | `:350-356` `:649-657` |

## 5. 边界与失败处理

| 情形 | 行为 |
| --- | --- |
| 没有任何插件 / 全部被停用 | 清空 tab 与结果，状态栏显示 `Plugins ready. No plugins installed yet.`（`:723-724`）；搜索按钮因无插件而禁用（`:366-368`） |
| 插件不支持搜索（`hasSearch == false`） | 直接 toast「Selected plugin does not support search.」（`:621-623`） |
| 关键词为空 | toast「Please enter a search keyword.」，不写历史（`:625-628`） |
| 搜索期间重复触发 | `_is_searching` 拦截，直接 return（`:614`） |
| 插件抛异常 / 返回非字典 | 全局控制器把 `_get_plugin_error()` 写进 `last_error` 并返回空字典（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:329-333`）；视图按失败处理并清空结果 |
| 翻页时插件返回空 `data` | 页码回滚到进入前的页，`_last_is_end = true`（`:649-656`） |
| 插件在搜索中途被停用 | `play_search_result()` 会再次检查 `is_plugin_enabled()` 并返回 false，视图提示「播放失败」（`assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:82-83`） |
| 插件失败导致合集为空 | 把插件自己的 `last_error` 透传成 toast，而不是笼统的「未找到可播放内容」（`assets/scripts/ui/music_app/controllers/music_app_plugin_browser_controller.gd:126-130`） |

## 6. 相关测试

无针对本页的自动化测试。`assets/tests/music_app/music_app_ui_test.gd:46` 只校验首页特性标签（`推荐歌单 / 榜单 / 播放历史 / 本地音乐`），未覆盖插件搜索。手工复现步骤：

1. 进入插件搜索页，确认历史区可见、结果区隐藏；输入关键词回车，确认出现插件 tab 与搜索类型 tab。
2. 输入关键词后立刻切换插件 tab，确认旧结果不会覆盖新结果。
3. 搜索一个多页关键词，点「下一页」，确认页码变化、上一页可用；翻到末页确认「下一页」禁用。
4. 点一条单曲：队列为空时应整页入队并从该曲开始播；队列非空时应只把该曲插到队首。
5. 点一条专辑/作者结果：应打开全屏歌单页且该歌单不可删除；关闭后临时歌单被清理。

## 8. 已知限制与后续

- 结果行 `MoreLabel`（文案 `⋮`，`assets/scenes/ui/music_app/plugin_browser/plugin_result_row.tscn` 中的 `MoreLabel` 节点）没有点击处理，用户会以为是「更多」入口；要么接上菜单，要么去掉该标签。
- 按 URL 安装插件的入口仍在管理面板，但底层 `install_plugin_from_url()` 固定失败（`assets/scripts/ui/music_app/controllers/global/music_app_plugin_controller.gd:131-132`），属于已知不可用入口。
- 管理面板的 `LoadVarsButton` / `SaveVarsButton` / `VarsEditor` 三个节点存在于场景（`assets/scenes/ui/music_app/plugin_browser/music_app_plugin_browser_page.tscn:312` `:318` `:324`），但视图没有引用，是插件变量编辑功能的残留在途代码。
- 管理面板文案是中英混排（`Manage / Start / Refresh / Install / No plugin selected.`），未接入 `music_app.csv` 翻译表。
- 分页只有按钮，不支持滚动到底自动翻页；每页条数由插件决定（`plugins/builtin/bilibili.gd:47` 为 `PAGE_SIZE = 50`），前端不做二次切片。
- 切换「单曲 / 专辑 / 作者」会立刻重搜第 1 页，没有结果缓存；同一关键词来回切换会重复请求插件。
