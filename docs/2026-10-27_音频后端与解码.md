| 项目 | 内容 |
| --- | --- |
| 文档日期 | 2026-10-27 |
| 最后更新 | 2026-10-27（合并 `2026-10-26` 旧材料后的校订版） |
| 对应代码版本 | develop @ 91d939d（工作区 2026-10-27） |
| 功能分类 | 播放内核 |
| 覆盖范围 | `AudioBackend` 抽象、`NodeAudioBackend`、`LibMpvAudioBackend`、`AudioBackendFactory`、M4A/AAC 解码器、FFmpeg 回退链路，以及 EIRTeam.FFmpeg 扩展的产物、注册与构建脚本 |

> 一句话定位：播放器上层只认一套「后端接口」，同一份状态控制器可以跑在三种声音来源上——Godot 原生播放器、libmpv（移动端流式播放）、时间戳可拖的 FFmpeg 回退；选谁由能力探测决定，任何一环不可用都会安静降级而不是播放失败。

## 1. 功能概述

- 用户视角：同一个播放按钮，在桌面上用引擎自带解码，在 Android 上可以边下边播、后台不中断，遇到 mp3/ogg/wav 以外的容器（m4a、AAC、部分 mp4 音轨）也能播。
- 实现视角：四层结构
  1. 接口层 `AudioBackend`（`assets/scripts/ui/music_app/audio/audio_backend.gd`，81 行）；
  2. 原生实现 `NodeAudioBackend`（`node_audio_backend.gd`，116 行），包装 `AudioStreamPlayer` / `VideoStreamPlayer`；
  3. 流式实现 `LibMpvAudioBackend`（`libmpv_audio_backend.gd`，160 行），包装 `addons/gdmpv` 的 `GDMPVPlayer`；
  4. 选择器 `AudioBackendFactory`（`audio_backend_factory.gd`，58 行）+ 外部进程解码器 `assets/scripts/audio/music_app_m4a_decoder.gd`（80 行）。
- 不在本期范围：DSP/均衡、多设备输出切换、无缝淡入淡出、DSD。

## 2. 功能入口与调用链

后端不是由页面直接创建的，唯一入口是状态控制器的懒探测：

1. `assets/scripts/ui/music_app/controllers/global/music_app_audio_controller.gd:443` `_sync_audio_state()` 取 `_get_active_player()` `:1113`。
2. `_get_active_player()` 先问 `_get_audio_backend()` `:1127`；后者只在**第一次**调用时探测（`_audio_backend_probed` 守卫 `:1128-1130`），调用 `AudioBackendFactory.try_create(host)` `:1134`，成功后连 `finished` / `error_occurred` 并补一次音量（`:1137-1141`）。
3. 工厂返回 `null` 即代表「继续用 Godot 原生播放器」，此时 `_get_active_player()` 回落到 FFmpeg 播放器（有流时）或原生 `AudioStreamPlayer`（`:1120-1123`）。`null` 是正常路径，不是错误。
4. `_is_streaming_backend()` `:755` 用「后端有没有 `load_source` 方法」判定是否走流式分支——这是鸭子类型判定，避免 controller 依赖具体类名。

## 3. 核心数据结构

### 3.1 `AudioBackend` 接口

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `finished` | `signal` | 当前曲目**自然播完**（切换曲目不算） |
| `state_changed(playing)` | `signal` | 播放/暂停变化 |
| `error_occurred(message)` | `signal` | 后端内部错误（初始化/解码失败） |
| `stream` | 属性 | 与 `AudioStreamPlayer.stream` 对齐；`get` → `_get_stream()`，`set` → `_set_stream()` |
| `stream_paused` | 属性 | 与 `AudioStreamPlayer.stream_paused` 对齐 |
| `_get_stream()` / `_set_stream()` / `is_playing()` / `is_paused()` / `set_paused()` | 虚方法 | 子类必须实现（`:38-72`） |
| `play(from_position)` / `seek(seconds)` / `stop()` | 虚方法 | 传输控制 |
| `get_playback_position()` / `get_duration()` | 虚方法 | 位置与时长；`get_duration()` 允许返回 `-1.0` 表示未知 |
| `set_volume_db(db)` / `shutdown()` | 虚方法 | 音量（dB）与释放 |
| `has_stream()` | 非虚 | 默认 `stream != null`（`:76`），mpv 后端覆写 |
| `is_available()` | 非虚 | 默认 `true`（`:80`） |

**为什么刻意做成「鸭子接口」**（文件头 `:1-10` 原注释）：让控制器里 20 多处 `audio_player.xxx()` 的调用一行都不用改，`LibMpvAudioBackend` 才能无缝替换现成节点；`stream` / `stream_paused` 保留下来只为兼容这些调用点，即使 mpv 根本不用 `AudioStream`。

### 3.2 各后端的关键差异

| 能力 | `NodeAudioBackend` | `LibMpvAudioBackend` |
| --- | --- | --- |
| 底层节点 | `AudioStreamPlayer` / `VideoStreamPlayer`（场景持有） | `GDMPVPlayer`（自己 `add_child` 到 host） |
| 数据来源 | 必须先有完整 `AudioStream` 或本地文件 | 直接 `load_source(url, headers)` 吃 URL |
| `has_stream()` | `stream != null` | `_last_loaded_url` 非空（`:102-104`） |
| `_get_stream()` | 透传节点 stream | 恒 `null`（`:89-92`），避免 controller 误判「已有流可播」 |
| 生命周期 | `shutdown()` 只断信号不销毁节点（`:111-116` 注释） | `shutdown()` → `shutdown()` + `queue_free()`（`:155-160`） |
| 音量 | `player.volume_db = db` | `player.set_volume(db_to_linear(db))`（`:150-152`） |
| 失焦影响 | 走 `AudioServer`，会被引擎「失焦暂停音频」影响 | 不经过 `AudioServer`，不受影响 |

`NodeAudioBackend` 里 `AudioStreamPlayer` 与 `VideoStreamPlayer` 的属性名完全不同（`playing` vs `stream != null and not paused`、`stream_paused` vs `paused`、`get_playback_position()` vs `stream_position`），三种分支全部收在这一个文件里（`:38-103`），控制器侧不再出现 `is VideoStreamPlayer` 判断。注意 `finished` 只对 `AudioStreamPlayer` 自动连接（`:16-18`），`VideoStreamPlayer` 的完成信号由场景侧 `assets/scripts/ui/music_app/music_app_showcase.gd:69-74` 直接连接。

## 4. 关键实现

### 4.1 后端选择条件

`AudioBackendFactory` 的选择规则写在文件头（`:1-8`），优先级从高到低：

| 优先级 | 条件 | 结果 |
| --- | --- | --- |
| 1 | 项目设置 `audio/backend/use_mpv` 是布尔值 | 直接采用该值（人工强制） |
| 2 | `OS.get_name()` ∈ `["Android", "iOS"]` 且 `GDMPVPlayer` 已注册 | 用 libmpv |
| 3 | 其余情况 | 返回 `null`（原生播放器） |

细节：

- `is_mpv_built()` `:19` 只做 `ClassDB.class_exists("GDMPVPlayer")`，不检查 `.so` 是否真能初始化。
- 未编译时**静默**回退（`:35-42`）；只有用户把设置显式设成 `true` 才 `push_warning` 一次，提示「addons/gdmpv 未编译或未加载，已回退到 Godot 原生播放器」。设计意图：普通用户不该看到警告，排障的人必须看得到。
- `GDMPVPlayer` 存在但 `initialize()` 失败（驱动/mpv 依赖缺失）时，`try_create()` 打印 `libmpv 后端不可用，已回退：<原因>` 并 `shutdown()` 掉半成品（`:47-50`），绝不把半初始化对象交给控制器。
- 题外事实：`project.godot` 里**没有** `audio/backend/use_mpv` 键（grep 无结果），所以线上行为完全由第 2 条决定——移动端自动 mpv，桌面端原生。
- `wrap_node(player)` `:55` 保留给「已有节点要按后端用」的场景，返回 `NodeAudioBackend`。

### 4.2 为什么插件流不裸用 `AudioStreamPlayer`

四个具体原因，前三条在代码里直接可见：

1. **原生 loader 一次只能吃完整内存缓冲**：`AudioStreamMP3.load_from_buffer()` 这类 API 没有「边下边解」形态（`_load_remote_stream()` `:551` 是先 `HTTPRequest` 拉完整个 body 再建流，上限 64MB）。插件返回的 bilibili CDN 地址需要 `Referer` 等请求头（`_build_http_headers()` `:671`），原生 loader 也无从携带。
2. **格式覆盖不足**：Godot 原生只认 mp3/ogg/wav（`SUPPORTED_AUDIO_LOADERS`，`:20`）。B 站插件给的常是 `m4a`/`aac`/`mp4`，必须外部解码或 mpv。
3. **后台/失焦**：`AudioStreamPlayer` 走 `AudioServer`，移动端切后台或失焦会被引擎暂停；libmpv 不经过 `AudioServer`（`assets/scripts/ui/music_app/audio/libmpv_audio_backend.gd:3-6`）。
4. **位置读取成本**：mpv 侧 native 缓存位置，`get_playback_position()` 是 O(1)（同上注释），而原生路径每秒 tick 都要向引擎查询。

### 4.3 FFmpeg 回退的三种触发点

代码里 FFmpeg 不是「首选」，而是「容器不受支持时的兜底」（`_should_use_ffmpeg_for_extension()` `:686` 的注释原文：「仅让原生不支持的容器进入 FFmpeg/VideoStreamPlayer」）。

| 场景 | 位置 | 判定 |
| --- | --- | --- |
| 远端 + m4a/aac/mp4 + FFmpeg 可用 + **Android** | `:501-502` | 直接 `_load_remote_ffmpeg_stream()`，不再尝试原生 |
| 远端 + 其它可解码格式 | `:505` | 先走原生 `_load_remote_stream()`；返回空且 FFmpeg 可用才回退 `:508` |
| 本地文件 | `_load_local_stream()` `:514` | m4a/`ftyp` **先**给 `M4ADecoder`（`:537-542`），失败且 FFmpeg 可用才回落 FFmpeg（`:543-547`），否则原生 loader |

Android 单独短路的原因（推断自代码结构）：移动端没有 `AudioStreamMP3` 之外的原生容器支持，先试一遍原生必然失败，只会白等一次 20 秒超时。

### 4.4 FFmpeg 流的产物与缓存

`_create_ffmpeg_stream_from_buffer()` `:625`：

```gdscript
var directory := OS.get_cache_dir().path_join(FFMPEG_CACHE_DIR)
...
var stream: Variant = ClassDB.instantiate("FFmpegVideoStream")
stream.file = path
```

- 必须**先落盘**再建流：`FFmpegVideoStream` 只接受文件路径，不接内存缓冲。落盘目录是 `OS.get_cache_dir()/gdmusic-ffmpeg-audio`，文件名为 `cache_key` 把 `/`、`:` 替换成 `_`（`:628`）后的 `<track.id>.audio`。
- **复用语义**：`cache_key` 用的是 `track.id`，所以同一首歌再播会命中同一路径、直接复用已下载的文件，不会重复拉 CDN——这是「卡顿后重试」体验的关键。
- 流是 `VideoStreamPlayer` 用的类型，故控制器在 FFmpeg 模式下拿 `_get_ffmpeg_player()` 当播放器，时长/位置走 `NodeAudioBackend` 的 `VideoStreamPlayer` 分支。
- **扩展不靠扩展名判断容器**：落盘文件名统一是 `<cache_key>.audio`（`:629`），建流时只做 `stream.file = path`（`:640`），容器与编码完全交给 FFmpeg 按内容探测。好处是 CDN 地址没有后缀、或扩展名与实际内容不符（如 `aac` 内容按 `m4a` 命名）都不影响播放；反过来说，解码失败只可能是内容真的坏了，不是「后缀认错了」。
- **纯音频容器需要扩展侧补丁**：上游 EIRTeam.FFmpeg 对「没有视频流」的容器会直接失败并报 `Couldn't find video stream`；项目内置产物打过「无视频流则直接选择音频流」的补丁，裸 M4A/AAC 才能播（注意两条链路并不互斥：本地 m4a——包括下载功能落盘的文件——在 `_load_local_stream()` `:537-542` 里**先**交给 `music_app_m4a_decoder.gd` 的外部进程解码，失败且 FFmpeg 可用才回落到 FFmpeg（`:543-547`）；只有「远程 m4a + Android」才是 FFmpeg 优先（`:501`））。macOS release 框架里仍能 grep 到 `Couldn't find video stream: %s` 字符串——该文案打补丁后只服务视频路径；「运行期确实不再报错」这一条本次无法复跑（本环境不运行 Godot），按二进制与历史集成记录判定（推断）。

### 4.5 M4A/AAC 外部进程解码（`music_app_m4a_decoder.gd`）

用于「桌面/无 mpv、又必须播 m4a」的场景：把音频字节交给系统转换器转成 WAV，再交给 `AudioStreamWAV.load_from_buffer()`。

| 设计点 | 代码 | 说明 |
| --- | --- | --- |
| 安全边界 | `:3` 注释 | 「Convert downloaded AAC locally; no URL or credentials are passed to a process」——**只传本地字节**，不把插件 URL/header 交给外部进程，避免凭据泄漏到进程列表/日志 |
| 转换器探测 | `_find_converter()` `:70-80` | macOS 优先 `/usr/bin/afconvert`；其它桌面平台在 `PATH` 找 `ffmpeg`（Windows 找 `ffmpeg.exe`，且只接受绝对路径项） |
| 找不到时 | `:10-12` | `last_error = "当前设备缺少 AAC/M4A 解码支持。桌面版可安装 FFmpeg 后重试。"` 直接返回 `null` |
| 参数 | `:28-30` | afconvert：`-f WAVE -d LEI16`；ffmpeg：`-nostdin -v error -y -i in -vn -ac 2 -ar 44100 -c:a pcm_s16le`（固定 44.1kHz 立体声 s16，牺牲体积换兼容性） |
| 超时与取消 | `TIMEOUT_MSEC = 30000` `:4`，轮询 `:35-42` | 每 50ms 查 `OS.is_process_running()` 与 `is_cancelled`，超时或取消就 `OS.kill()`；切歌不必等转换跑完 |
| 缓存目录 | `:16` | `OS.get_cache_dir()/gdmusic-audio`，输入文件名带 `pid` + `ticks_usec`（`:20`）防并发撞名，用完两个文件都删（`:46-48`） |
| WAVE_FORMAT_EXTENSIBLE 补丁 | `_load_pcm_wave()` `:53-68` | afconvert 即便输出 16-bit PCM 也会写 `0xFFFE`（Extensible）标签，Godot 的 WAV loader 只认普通 PCM tag，所以把 fmt 块里的 format tag 改回 `1`（GUID 必须精确匹配才改，`:63-65`），否则表现为「转换成功但加载失败」 |

### 4.6 错误与「重连」

- 后端 `error_occurred` → `_on_backend_error()` `:1147`：`push_warning("[MusicAppAudio] 播放后端报错：%s")`，然后 `_record_background_error()` `:1152` 记一条时间戳（只保留 `BACKGROUND_ERROR_STREAK_WINDOW_MSEC` 窗口内的）。
- 熔断：`_is_background_error_streak_exceeded()` `:1162` 在 `on_audio_finished()` `:333` 里被查；命中就停止自动切歌，避免「一首坏流把整队列跳完 + Android 反复拉起前台服务导致闪退」。成功推进后 `_clear_background_errors()` `:1166` 清零。
- 没有「自动重连后端」：后端初始化失败一次就固定为 `null`（`_audio_backend_probed` 已置 true），后续全部走原生路径。**这是有意的**——运行期热切换播放器会丢当前播放位置，也会在 Android 上留下没 shutdown 的 native 实例。
- 单曲失败不会污染存档：`_mark_playback_unavailable()` `:970` 只改内存里的 `last_error` 与 `is_playing`。

### 4.7 内置产物与扩展注册

四个平台共用**同一份** `addons/ffmpeg/ffmpeg.gdextension`：`[libraries]` 只声明各平台入口库，`[dependencies]` 按平台列 FFmpeg 运行库（dll/dylib/so）供启动时预加载；`entry_symbol = "ffmpeg_init"`、`compatibility_minimum = 4.1`（`:3-4`）。

| 平台键（`ffmpeg.gdextension:6-14`） | 声明的入口与依赖 | 仓库实际产物 |
| --- | --- | --- |
| `windows.x86_64` | `win64/libgdffmpeg.windows.template_*.dll` + 6 个 ffmpeg dll（`:18-24`） | 有 |
| `linux.x86_64` | `linux64/libgdffmpeg.linux.template_*.so` + 6 个 `.so.xx`（`:26-32`） | **没有 `linux64/` 目录**，声明悬空 |
| `android.arm64` | `android/libgdffmpeg.android.template_*.arm64.so` + 6 个 `.so`（`:34-42`） | 有（arm64-v8a） |
| `macos` | `macos/libgdffmpeg.macos.template_*.framework` + 6 个 `.dylib`（`:44-52`） | 有（Apple Silicon） |

注册与用法上有三个事实值得记住：

1. 扩展注册的类名是 `FFmpegVideoStream` 与 `FFmpegVideoStreamPlayback`；前者在代码里被直接实例化（`ClassDB.instantiate("FFmpegVideoStream")` `:636`），macOS release 框架二进制里也能找到这两个类名字符串。「启动时注册成功」这条旧记录在本环境无法复跑（不运行 Godot），仅由二进制与 `ClassDB.class_exists()` 用法佐证（推断）。
2. 可用性判定只有一条：`_ffmpeg_available()` `:1110-1111` = `ClassDB.class_exists("FFmpegVideoStream")` **且** showcase 里存在 `ffmpeg_player` 节点。节点通过 `_get_ffmpeg_player()` `:988-993` 从 showcase 反射取 `ffmpeg_player`；它是 `assets/scenes/music_app_showcase_scene.tscn:83` 的 `VideoStreamPlayer`（`%FFmpegPlayer`，`visible = false` 且 `process_mode = 3`）——不可见但暂停/后台时仍推进，否则回退播放会随主循环停摆。
3. macOS 框架目录名是 `libgdffmpeg.macos.template_*.framework`，内部入口二进制叫 `libgdffmpeg_advanced.*`：找产物时按 `.gdextension` 的路径找**目录**，不要按「同名的 `.dylib` 主库」去找。

### 4.8 扩展构建脚本（`tools/build_eirteam_ffmpeg.sh`）

该脚本负责「从上游源码重建 `addons/ffmpeg/`」，只做 macOS 与 Android 两个平台：

| 事实 | 位置 | 说明 |
| --- | --- | --- |
| 源码目录 | `:8` | 默认 `~/Downloads/EIRTeam.FFmpeg-master`，可用环境变量 `EIRTEAM_FFMPEG_SOURCE` 覆盖 |
| 必须是已初始化的 git 仓库 | `:19-23` | 没有 `.git` 直接 `exit 1`；脚本**不自动下载源码**，也不下载预编译二进制 |
| macOS | `:27` | `make gdextension PLATFORM=macos TARGET_ARCH=arm64`，只产 Apple Silicon |
| Android | `:31-33` | 走上游 `ffmpeg-kit/android.sh`，禁用 `arm-v7a`/`x86`/`x86-64`（只留 arm64-v8a），`--enable-android-media-codec --enable-android-zlib --no-archive` |
| 只启用解码组件 | `:29-30` 注释 | 「Android playback only needs FFmpeg's decoders」，刻意不引入 x264/x265/lame/libiconv，以便用 stock NDK 构建 |
| 依赖库拷贝 | `:34-38` | 把 `ffmpeg-kit` 预编译的 6 个 `.so` 与 include 拷进 `thirdparty/ffmpeg/android/arm64`，再对 `template_debug` / `template_release` 各跑一次 scons（`:42-44`） |
| NDK 版本 | `:9-11`、`:39-41` | 默认 `28.2.13676358`（可用 `ANDROID_NDK_VERSION` 覆盖）；上游 `gdextension_build` 硬编码找 `ndk/23.2.8568313`，脚本在缺失时**建软链**绕开 |
| 最终落点 | `:46-48` | 只把 `addons/ffmpeg/` 拷进项目，不覆盖项目里的其它文件 |

**Windows 产物不来自这个脚本**：`addons/ffmpeg/win64/` 的 dll 是另建/手工放入的，脚本只认 macos + android（见 §8 第一条）。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| `addons/gdmpv` 未编译 | 工厂 `null`，静默走原生播放器；显式配置时才告警 |
| `GDMPVPlayer` 存在但 `initialize()` 失败 | 打印原因 + `queue_free()` + 回退，`is_available() == false` |
| 桌面端要播 m4a 且没有 FFmpeg/afconvert | `M4ADecoder.last_error` 给出「可安装 FFmpeg」的指引，播放器标记不可播 |
| 转换进程卡住 | 30 秒超时后 kill，报「AAC/M4A 音频转换失败或超时。」 |
| 用户切歌时还在转换 | `is_cancelled` 回调让它立刻 kill 并清理临时文件 |
| mpv 播完后状态既不 playing 也不 paused | 由 `_sync_streaming_playback()` `:759` 特殊处理（见[播放状态与全局控制](2026-10-27_播放状态与全局控制.md)） |
| 远端 body 超 64MB | `body_size_limit` 让 `HTTPRequest` 直接失败，`last_error = "音频下载失败，请重试。"` |
| 插件返回非 http(s) 地址 | `_is_remote_stream_url()` 拦截，报「插件返回了无效的音频地址。」 |
| Linux 桌面 | `ffmpeg.gdextension` 声明了 `linux64/*.so` 但仓库没有该目录：`ClassDB.class_exists("FFmpegVideoStream")` 为假，`_ffmpeg_available()` 恒假，静默走原生 loader 与 `M4ADecoder`，不会报错 |
| 换了未打补丁的扩展 | 无视频流的 M4A/AAC 会以 `Couldn't find video stream` 失败；内置产物已修，自编译上游原版必须重新打补丁（§4.4） |
| Android 13+ 首次播放 | 请求 `POST_NOTIFICATIONS`；拒绝不阻塞出声，但媒体卡片可能不显示；小米 HyperOS 的「灵动岛/超级岛」没有第三方绘制接口，只能由用户开启通知/锁屏显示并关闭后台限制，应用不能强制创建——系统侧细节见 [Android后台音频](2026-10-27_Android后台音频.md) |

## 6. 相关测试

**无自动化测试**：`assets/tests/music_app/` 下没有覆盖 `AudioBackendFactory` / `LibMpvAudioBackend` / `M4ADecoder` 的脚本（grep 这些类名在测试目录无命中）。原因可以理解——三者都强依赖平台能力（GDExtension、外部进程、音频设备），在 CI 里跑会不稳定。

手工验证步骤：

1. 桌面直接运行 → 确认 `音乐` 页能播放 mp3，且日志无 `[MusicAppAudio] 播放后端报错`。
2. 在 `project.godot` 临时加 `audio/backend/use_mpv=true` 再跑 → 应看到「GDMPVPlayer 未注册……已回退」警告且仍能播放（验证静默降级）。
3. 构造一首只有 m4a 源的曲目 → 无 FFmpeg 的环境应提示缺少解码支持而不是静默无声。
4. Android 真机：切后台 30 秒再回来，确认播放未中断（验证不走 `AudioServer`）。

## 8. 已知限制与后续

- `FFmpegVideoStream` 必须先落盘整首再播，意味着「开始播放」要等下载完；真正的边下边播只有 mpv 后端具备。
- FFmpeg 缓存目录（`gdmusic-ffmpeg-audio`）与 m4a 转换目录（`gdmusic-audio`）都没有容量上限与清理策略，长期使用会累积；目前依赖系统清理 `OS.get_cache_dir()`。
- 后端在运行期不可热切换（探测一次即固定），调试 mpv 时需要重启 App。
- `M4ADecoder` 固定转成 44.1kHz/16bit 立体声 PCM，高码率源会有一次有损且有 CPU 成本的转换；大文件时 30 秒超时可能不够（推断，需按真机实测调整）。
- `libmpv` 的 `get_duration()` 在流式场景可能先返回 0 再更新，控制器用 `_sync_track_duration_from_backend()` `:948` 延迟 0.6 秒回填时长。
- **Windows 产物没有脚本可复现**：`tools/build_eirteam_ffmpeg.sh` 只做 macOS 与 Android，`addons/ffmpeg/win64/` 的 dll 是另行放入的。升级 FFmpeg 时三平台版本容易漂移，Windows 端行为要以实际产物为准。
- **Linux 声明悬空**：`ffmpeg.gdextension` 保留 `linux.x86_64` 条目却无对应 `linux64/` 目录，效果是「Linux 桌面永远用不上 FFmpeg 回退」且不报错。要么补产物，要么删掉该段声明，避免读者以为 Linux 也支持。
- 扩展必须自带「无视频流选音频流」补丁，上游 EIRTeam.FFmpeg 原版不支持纯音频容器；这是升级扩展时最容易回归的一条，而且**症状会骗人**：本地 m4a（下载落盘的曲目）先被 `M4ADecoder` 兜住，扩展坏了也照样出声，只有远程 m4a（Android 上直接进 FFmpeg，`:501`）才会暴露成 `Couldn't find video stream` / 无声。
- 构建脚本把 NDK `28.2.13676358` 与软链目标 `ndk/23.2.8568313` 都写死了（`tools/build_eirteam_ffmpeg.sh:9-11`、`:39-41`），换 NDK 要同时改两处，否则会在 `scons` 阶段报路径不存在。
