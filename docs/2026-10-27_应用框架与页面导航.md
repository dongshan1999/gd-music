> 一句话定位：本项目没有传统的「Godot 场景切换」，整个应用是一个常驻的 `MusicAppShowcase` 主场景，所有页面（首页、播放器、歌单、设置……）都是弹窗，由 `MusicAppPopupRouterController` 统一压栈、弹栈与返回。

## 1. 功能概述

- **用户视角**：应用从首页进入，点「菜单 / 设置」进入二级页面，点返回逐层退回；在首页连按返回两次才退出应用。页面切换带平移/底部上滑动画，全局背景音乐在页面切换时不中断。
- **实现视角**：
  - `MusicAppShowcaseController`（`assets/scripts/ui/music_app/music_app_showcase.gd`）是主场景根脚本，在 `_ready()` 中装配全部全局控制器，并把两个弹窗宿主（普通层 / 全屏层）交给路由控制器（`assets/scripts/ui/music_app/music_app_showcase.gd:54`）。
  - 页面统一继承 `MusicAppPage`（`assets/scripts/ui/music_app/music_app_page.gd`），而 `MusicAppPage` 继承 DX 的 `DX_PopupView`（`assets/scripts/ui/music_app/music_app_page.gd:1`），因此页面天然具备「开/关动画 + 输入拦截 + 宿主分层」能力。
  - 页面 ID 与场景路径集中登记在 `DX_PopupRegistry`（`dx/runtime/scripts/managers/popup/popup_registry.gd:4`），新增页面必须同时改这份注册表。
- **不在本期范围**：页面间传参不走 Godot 的 `change_scene`，也没有 URL/路由字符串；页面只通过全局控制器读写数据（见 4.5）。

### 2.2 页面前往

任何界面点按钮都走「控制器 → 路由」：

```
按钮 pressed → 页面 View 调 controller.xxx()
            → 控制器内 show_popup(DX_PopupRegistry.PopupId.MUSIC_APP_XXX)
            → MusicAppPopupRouterController.show_popup()   router:68
            → DX_PopupManager.show(id)                      popup_manager.gd:17
```

例：首页菜单按钮在 `assets/scripts/ui/music_app/controllers/music_app_home_controller.gd:78` 直接调用 `show_popup(DX_PopupRegistry.PopupId.MUSIC_APP_SETTINGS)`。

### 2.3 返回链路

```
_unhandled_input(event)                    music_app_showcase.gd:128
 └─ event.is_action_pressed("ui_cancel")?
     └─ _handle_back_requested()           :134
         ├─ 先问路由：_popup_router_controller.handle_back()
         │    ├─ 当前页 == 首页 → false（交给根页面）
         │    └─ 否则 close_popup()；若关掉的是 Toast，继续判断下层页面
         ├─ 路由返回 true → 消费事件
```

## 4. 关键实现

### 4.1 控制器装配：为什么是一个常驻主场景

`assets/scripts/ui/music_app/music_app_showcase.gd:6-12` 用 `MusicAppScriptPaths.MUSIC_APP_*_CONTROLLER` 常量 `preload` 六个全局控制器脚本（Playback / PlaybackState / PlaylistState / PopupRouter / Plugin / Download），而不是散落在各处 `load()`。这样：

- 所有路径集中在 `assets/scripts/constants/music_app_script_paths.gd`，重命名脚本只改一处；
- 控制器实例挂在主场景上，生命周期与 App 一致，页面反复开关不会重建播放状态。

`_ready()`（`assets/scripts/ui/music_app/music_app_showcase.gd:48`）里刻意先把 `audio_player.process_mode` 与 `ffmpeg_player.process_mode` 设为 `PROCESS_MODE_ALWAYS`：Android 退到后台时 UI Activity 被暂停，若用默认 `INHERIT`，音频节点会跟着停，导致「后台播放」失效。

`_timer` 以 1 秒间隔调用 `_on_tick()`（`:98`），作为全局低频刷新节拍（播放进度、下载进度、插件状态），避免每个页面各起定时器。

### 4.2 页面即弹窗

`MusicAppPage` 只有一个职责：把「页面语义」映射到 `DX_PopupView` 的动画语义：

```gdscript
# assets/scripts/ui/music_app/music_app_page.gd:4-6
enum Presentation { NONE, PUSH, SHEET, DIALOG }
@export var presentation: Presentation = Presentation.PUSH
@export_node_path("Control") var transition_target: NodePath = NodePath(".")
```

- `_popup_open(manager)`（`:15`）在弹窗打开时播放对应入场动画；
- `_travel()`（`:52`）计算平移终点，`PUSH` 从屏幕右侧滑入，`SHEET` 从底部上滑，`DIALOG` 原地缩放；
- `_set_input_guard(enabled)`（`:60`）在动画期间屏蔽输入，防止连点重复入栈；
- `_finish_dismissal()`（`:74`）动画结束后真正 `queue_free`。

选择「弹窗」而不是「场景切换」的原因：`change_scene` 会销毁整棵 UI 树，迷你播放器、播放进度和滚动位置全部丢失；弹窗方案让页面只是叠在同一个宿主上的 Control，关闭即释放，底层状态零成本保留。

### 4.3 双宿主分层

主场景有两个宿主（`assets/scenes/music_app_showcase_scene.tscn:55` 与 `:69`）：

- `NormalPopupHost`：普通页面（首页、歌单、本地音乐、设置……），层级在迷你播放器之下，页面内容不会被迷你播放器遮挡；
- `FullscreenPopupHost`：全屏页（播放器页）与队列页，覆盖迷你播放器。

页面通过场景里的 `popup_layer` 决定去哪个宿主（首页场景 `popup_layer = 0`）。`show_popup()` 的 `layer_override` 参数允许临时覆盖，用于同一页面在两种层级下复用。

### 4.4 返回键：Toast 也占一个弹窗位

路由的 `handle_back()`（`router:113`）有一个容易出错的细节：

1. 若栈顶是 `COMMON_TOAST`，先关 Toast，**并且**返回「下层是否还有非首页页面」；
2. 下层还有页面时返回 `true`，让这次返回键「只吃掉 Toast、不关页面」；
3. 下层就是首页时返回 `false`，把事件交回主场景，恢复「再按一次退出」倒计时。

否则会出现「首页提示了一个 Toast，按返回直接把 App 退了」的体验问题。

### 4.5 页面数据访问：控制器基类

页面不直接持有存档，而是通过 `MusicAppPopupRouterController` 暴露的 `_get_base_controller()`（`router:17`）再取 `get_tracks_ref()` / `get_playlists_ref()` / `get_selected_playlist_index()` 等（`router:20-29`）。这样 View 只依赖路由控制器一个入口，测试时可以替换底层控制器。

### 4.6 页面滚动

所有可滚动页面在场景里挂 `MusicAppScrollInteractionComp`（`assets/scripts/ui/music_app/music_app_scroll.gd`），它继承 DX 的通用组件 `DX_ScrollInteractionComp`（`dx/runtime/scripts/component/scroll/scroll_interaction_comp.gd:1`）：

- 基类负责鼠标滚轮、触摸拖动、触控板 Pan 手势、横向滚动的开关（`dx/runtime/scripts/component/scroll/scroll_interaction_comp.gd:5-16` 的 `@export`）；
- 子类 `assets/scripts/ui/music_app/music_app_scroll.gd:15` 把配置改成「只垂直、滚轮步长 72、平滑补间」，并让滚动条默认透明、滚动时淡入（`_show_indicator()`，`:77`），随后 1 秒淡出；
- 触摸事件期间不做补间（`_input()`，`:10` 记录 `_touch_event`），避免手指拖动和惯性动画打架。

### 4.7 文本、图标与主题

- 文本：所有界面字符串走 `tr()`，翻译表在 `project.godot:52` 注册（en / zh / zh_CN 三份 `.translation`，源 CSV 为 `assets/translations/music_app.csv`）。
- 图标：`MusicAppIcons`（`assets/scripts/constants/music_app_icons.gd:1`）集中 `preload` SVG；少量文字符号（♡、▶、🔎 等）在 `MusicAppUiSymbols`（`assets/scripts/constants/music_app_ui_symbols.gd:1`）。
- 主题：全局 `assets/themes/gd_music_theme.tres`（`project.godot:48`），页面内不重复定义控件样式。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| 重复点击同一入口 | `DX_PopupView` 打开期间有输入拦截（`_set_input_guard`），不会叠两个同样的页面 |
| 返回键在首页 | 路由返回 `false`，主场景进入 2 秒退出确认窗口；`BACK_EVENT_DEBOUNCE_MSEC = 120`（`:29`）防抖，避免一次按键触发两次 |
| 弹窗管理器为空 | 路由各方法先判空再调用，失败时静默返回，不抛错 |
| 页面场景缺失 | `DX_PopupRegistry.has_popup()` 可预判；未注册 ID 不会调到 `show()` |
| 退出 Play 模式预览（Editor） | `_notification()`（`:89`）里释放实例与计时器，避免 `instance` 悬垂 |
| 页面关闭时异步回调未完成 | 控制器持有数据而非页面持有，页面销毁不影响下载/播放回调 |

## 6. 相关测试

无针对「主场景装配 + 路由」的自动化测试。手工验证步骤：

1. 用 Godot 4.7 打开项目，F5 运行主场景；
2. 首页点菜单 → 进入设置 → 按 `ui_cancel` → 应回到首页且不退出；
3. 首页连续两次快速按返回 → 第二次退出应用；
4. 打开播放器页 → 切到队列 → 返回两次 → 应回到播放器页而非首页；
5. 触发一次 Toast（如收藏提示）后立刻按返回 → 只关 Toast，页面保留。

## 8. 已知限制与后续

- 所有页面常驻内存（弹窗关闭才释放），同时打开超过 3 层时需要注意页面内大列表的内存占用；
- 路由没有「替换当前页」语义，需要「A 页直接变 B 页」时只能先关再开，会出现一帧空白；
- 当前退出确认窗口固定 2 秒，未做用户可配置；
- 页面 ID 用整数枚举，插件侧无法动态注册新页面；若后续要支持插件自定义界面，需要把 `POPUP_SCENES` 改成运行时可注册的表。
