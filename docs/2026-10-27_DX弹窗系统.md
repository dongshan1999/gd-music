> 一句话定位：DX 的「弹窗」就是**整页 UI**。`DX_PopupRegistry` 把 16 个页面登记成 ID → 场景的映射，`DX_PopupManager` 按 NORMAL/FULLSCREEN 两层栈管理实例，业务页面继承 `DX_PopupView` 后由 `music_app_page.gd` 再补上返回栈、动画与输入守卫。

## 1. 功能概述

- **用户视角**：在首页点歌单进详情、点播放进播放页、点设置进设置页，每层都能左滑/返回键退回；同一页面二次打开不会重建，返回后状态还在。
- **实现视角**：
  - 注册是**编译期常量表**：`DX_PopupRegistry.PopupId` 枚举 + `POPUP_SCENES` 的 `preload` 字典（`dx/runtime/scripts/managers/popup/popup_registry.gd:4-40`），没有运行期注册 API。
  - 管理是**两个层级栈**：`NORMAL`（弹层）与 `FULLSCREEN`（整页），每个栈的元素是 `{id, popup}` 字典（`dx/runtime/scripts/managers/popup/popup_manager.gd:12-15`）。
  - 生命周期只有三个钩子：`_popup_open(manager)` → `on_popup_shown()`，关闭时 `_popup_close()` → `on_popup_hidden()`（`dx/runtime/scripts/managers/popup/popup_view.gd:23-30`）。动画、输入拦截、返回栈全在业务侧 `music_app_page.gd`。
- **不在本期范围**：DX 层没有弹窗队列、没有遮罩层、没有 Toast/Dialog 的特殊分支——`TOAST` 与 `DIALOG` 只是注册表里的两个 ID，行为由它们各自的脚本与页面基类决定。

## 2. 功能入口与调用链

### 2.1 打开一个页面

```
业务：DX.popup.show(DX_PopupRegistry.PopupId.MUSIC_APP_PLAYLIST)
   或 MusicAppPopupRouterController.show_popup(id)   music_app_popup_router_controller.gd:68
 └─ DX_PopupManager.show(popup_id, layer_override)   popup_manager.gd:17
     ├─ get_popup(id) 已有实例 → _bring_popup_to_front + _touch_popup_entry + emit   :18-23
     └─ _show_new_popup(id, layer_override)                                        :27
         ├─ has_popup(id) / get_scene(id) 校验（未注册/场景缺失 → push_error + null） :28-35
         ├─ scene.instantiate()；必须 is DX_PopupView（否则 queue_free）             :37-41
         ├─ layer_override >= 0 → 覆盖 popup.popup_layer                             :44-45
         ├─ _get_popup_host(popup.get_resolved_popup_layer())                        :46-47
         ├─ _stretch_popup(popup) → PRESET_FULL_RECT                                 :53
         ├─ host.add_child(popup) + _push_popup_entry                                :54-55
         └─ popup._popup_open(self) → visible=true → on_popup_shown() → emit popup_shown :57-58
```

### 2.2 关闭

```
页面内：close_popup()                    popup_view.gd:16
 └─ popup_manager.hide_popup(self)       popup_manager.gd:73
     ├─ _remove_popup_entry(self) 从栈里摘除   :77
     ├─ popup._popup_close() → on_popup_hidden()  :84
     └─ popup.queue_free() + emit popup_hidden    :85-86
```

栈被摘除后，`get_current_popup()` 自然回到下一层；页面基类在 `_popup_close` 前后做动画与路由栈同步（见 `assets/scripts/ui/music_app/music_app_page.gd:36-50`）。

## 4. 关键实现

### 4.1 「同 ID 复用」而不是每次实例化

```gdscript
# popup_manager.gd:17-25
func show(popup_id: int, layer_override: int = -1) -> DX_PopupView:
	var existing_popup := get_popup(popup_id)
	if existing_popup != null:
		_bring_popup_to_front(existing_popup)
		_touch_popup_entry(popup_id, existing_popup)
		popup_shown.emit(popup_id, existing_popup)
		return existing_popup
	return _show_new_popup(popup_id, layer_override)
```

设计意图：本项目页面之间有共享状态（歌单滚动位置、播放页的进度拖动），若每次进入都 `instantiate` 一个新页面，返回时状态全丢，且 `preload` 的场景反复实例化在低端机上有明显卡顿。复用时把节点 `move_child` 到父节点末尾（`_bring_popup_to_front`，`:183-189`），保证后打开的在下层页面上方。

代价：**同一页面不能同时存在两份**（例如「歌单 A → 歌单 B」会复用同一个实例），所以页面必须在 `on_popup_shown()` 里重新拉自己的数据，不能只依赖 `_ready`。

### 4.2 两层栈与「全屏优先」的查找顺序

`_find_popup_entry()`（`:162-181`）与 `_get_current_popup_entry()`（`:191-203`）都按 `FULLSCREEN → NORMAL` 顺序遍历，且层内**从后往前**找。原因：

- 全屏页在语义上压住普通弹层（例如播放页上方弹一个 Toast，`get_current_popup()` 必须返回播放页而不是 Toast）；
- 从后往前找是「最后打开的最先被找到/关闭」，等价于 `hide()`（`:67-71`）关掉当前最上层。

`_touch_popup_entry()`（`:142-160`）在被复用的弹窗重新显示时把它移到栈顶，否则 `hide()` 会关错对象。

### 4.3 宿主由页面注册、可撤销

`_get_popup_host()`（`:115-125`）不自己建容器，而是读页面通过 `set_normal_host()` / `set_fullscreen_host()` 注册进来的 `Control`；页面销毁前调用 `clear_normal_host(host)` / `clear_fullscreen_host(host)`（`:105-113`），传 `null` 表示无条件清空。

三个作用：

1. 弹窗的 z 序跟随宿主节点在场景树里的位置，而不是硬编码 `CanvasLayer.layer`；
2. 宿主是「页面」自己的子节点，页面被释放时弹窗跟着释放，不会留在根节点上变成孤儿；
3. 每次设置/清空后都调 `_prune_invalid_popup_entries()`（`:220-228`），把已被 `free()` 的弹窗从栈里剔除，避免拿到 `is_instance_valid == false` 的悬空引用。

### 4.4 `DX_PopupView` 只是「空壳」

`popup_view.gd` 只有 36 行：一个枚举、一个 `@export popup_layer`、`close_popup()`、`_popup_open/_popup_close` 与两个空钩子。它**不**处理：

| 能力 | 实际位置 |
| --- | --- |
| 打开/关闭动画 | `music_app_page.gd`（`_popup_open` / `close_popup` 里做 Tween） |
| 输入守卫（动画期间吞点击） | `assets/scripts/ui/music_app/music_app_page.gd:60` 的 `_set_input_guard(true/false)` |
| 页面栈/最近一次 | 业务侧路由控制器 `handle_back()` 逐个关非首页弹窗；最近一次由 `DX_PopupManager` 的 `last_shown_id`/`showing_order` 提供 |
| 返回键拦截 | `assets/scripts/ui/music_app/controllers/global/music_app_popup_router_controller.gd:107-112` 的 `handle_cancel_input()` 与 `:113` 的 `handle_back()` |

这样拆的理由：DX 是通用框架，不能假设业务用 Tween 还是 AnimationPlayer，也不能假设返回策略；把"页面外壳"留给 `music_app_page.gd`（它 `extends DX_PopupView`），DX 只负责"谁在前、谁被复用、谁被释放"。

### 4.5 Toast 与 Dialog 的「特殊处理」其实在业务侧

注册表里 `COMMON_TOAST` 与 `COMMON_DIALOG` 与其他页面同权，DIFF 通过场景与脚本表达：

| 项 | Toast | Dialog |
| --- | --- | --- |
| `popup_layer` | `1`（FULLSCREEN，`assets/scenes/popup/common_toast_popup.tscn:13`） | 场景内设定 |
| 鼠标穿透 | 根 Control `mouse_filter = IGNORE`，不挡点击 | 遮罩接收输入 |
| 重复调用 | `show_message()` 复用已存在的实例，重置文字与计时（`assets/scripts/popup/common_toast_popup.gd:29`） | `show_alert()` / `show_confirm()` 各自复用 |
| 自动关闭 | 定时后 `close_popup()` | 用户点按钮后 `close_popup()` |

因此"Toast/Dialog 特殊处理"不是 DX_PopupManager 的分支，而是**场景配置 + 脚本复用**；想加一种新弹层不需要改 DX。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| `show()` 传入未注册 ID | `push_error("Popup id is not registered: %s")`，返回 `null`（`:28-30`） |
| 注册了 ID 但场景 `preload` 失败 | 实际不会发生（`preload` 编译期即失败）；`get_scene` 返回 `null` 时有 `"Popup scene is missing for id"` 兜底（`:32-35`） |
| 场景根节点不是 `DX_PopupView` | `push_error("Popup root must extend DX_PopupView.")`，实例 `queue_free` 后返回 `null`（`:38-41`） |
| 该层宿主未注册 | `push_error("Popup host is missing for popup id")`，不实例化（`:48-51`） |
| 弹窗在外部被 `free()` | 每次查找/设置宿主前 `_prune_invalid_popup_entries()` 清理；`hide_popup` 对已释放实例只 `emit popup_hidden`，不重复释放（`:83-86`） |
| `hide_popup` 传入不在栈里的对象 | `_remove_popup_entry` 返回空字典，直接 return，不报错（`:78-79`） |
| `hide()` 无当前弹窗 | `get_current_popup()` 为 `null` 时直接返回（`:68-70`） |
| `close_popup()` 时 manager 已失效 | 先判 `popup_manager != null`，再判 `has_method("hide_popup")`，退化调 `hide()`（`dx/runtime/scripts/managers/popup/popup_view.gd:16-21`） |
| 同一 ID 二次 `show` | 返回同一实例，不会出现两个同 ID 页面（见 4.1） |
| `layer_override` 传负数 | 视为「不覆盖」，沿用场景里 `@export` 的值（`dx/runtime/scripts/managers/popup/popup_manager.gd:44`） |

## 8. 已知限制与后续

- 注册表是 `const` + `preload`，新增页面必须改框架代码并重新编译，无法热插拔；
- 无弹窗队列：同一时刻多层全屏页叠加时，`get_current_popup()` 只看栈顶，无法表达「模态优先级」；
- `show()` 不校验 `layer_override` 的取值，传越界整数会让 `_get_popup_host` 返回 `null` 并报错；
- 两层只有 NORMAL/FULLSCREEN，若需要「底部抽屉」「居中模态」等语义，要么复用 NORMAL 靠场景内布局区分，要么扩展枚举（影响 `_popup_stacks` 初始化）；
- 弹窗关闭靠 `queue_free()`，没有对象池，频繁开关 Toast 会有持续 GC 压力（Toast 已用"复用实例"规避）。
