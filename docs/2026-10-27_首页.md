> 一句话定位：首页是应用启动后的第一个弹窗页面，承担「资料库总览 + 快捷入口」两件事：上方是 2×2 功能卡与搜索栏，下方是「我的歌单」列表；它本身不播放音频，只把用户意图转发给路由控制器。

## 1. 功能概述

- **用户视角**：
  - 启动即见首页，可看到 4 张功能卡（推荐歌单 / 榜单 / 播放历史 / 本地音乐）和「我的歌单」列表；
  - 点搜索栏进入插件浏览器搜索；点右上角菜单按钮进入设置；
  - 点「+」新建歌单、点导入图标进入本地音乐导入入口、点歌单行进入歌单详情；
  - 可删除自建歌单（系统「我喜欢」歌单不可删）。
- **实现视角**：
  - 场景 `assets/scenes/ui/music_app/home/music_app_home_page.tscn` 的根节点 `HomePage` 挂 `MusicAppHomeView`，继承 `MusicAppPage`（即 `DX_PopupView`），因此首页也是一个弹窗；
  - View 只负责控件绑定与渲染，数据整理与导航动作全部在 `MusicAppHomeController`；
  - 歌单行按需实例化并复用（`_sync_home_playlist_rows()`），功能卡是固定 4 个实例，不动态增删。
- **不在本期范围**：
  - 首页没有「最近播放 / 播放历史」列表实体：`播放历史` 目前只是一张功能卡占位，点击只弹 Toast（见 4.6）；
  - 首页不做搜索输入，搜索行为在插件浏览器页完成（见 [插件浏览器与搜索](2026-10-27_插件浏览器与搜索.md)）。

## 2. 功能入口与调用链

### 2.1 首页如何出现

首页不是 `change_scene` 切出来的，而是主场景 `_ready()` 末尾由路由打开的第一个弹窗：

```
MusicAppShowcase._ready()                     assets/scripts/ui/music_app/music_app_showcase.gd:48
 └─ _popup_router_controller.show_home_popup()                                  :76
     └─ show_popup(PopupId.MUSIC_APP_HOME)         music_app_popup_router_controller.gd:79
         └─ DX_PopupManager.show(id)               popup_manager.gd:17
             └─ HomePage.instantiate → _popup_open → MusicAppHomeView.setup(showcase)
                 └─ MusicAppHomeController.new(controller) → bind() → refresh()
```

`MusicAppPopupRouterController.show_popup()` 在弹窗实例创建后统一调用其 `setup(get_showcase())`（`assets/scripts/ui/music_app/controllers/global/music_app_popup_router_controller.gd:73-75`），首页因此拿到全局控制器。

## 4. 关键实现

### 4.1 首页是「无动画」的普通层弹窗

首页场景刻意把两个属性写死（`assets/scenes/ui/music_app/home/music_app_home_page.tscn:31-32`）：

```ini
popup_layer = 0      # DX_PopupView.PopupLayer.NORMAL
presentation = 0     # MusicAppPage.Presentation.NONE
```

- `DX_PopupView` 的 `popup_layer` 默认值是 `FULLSCREEN`（`dx/runtime/scripts/managers/popup/popup_view.gd:9`），普通页面必须显式改成 `NORMAL` 才会挂到 `NormalPopupHost`；
- `presentation = NONE` 让首页跳过 `MusicAppPage._popup_open()` 的滑入动画（`assets/scripts/ui/music_app/music_app_page.gd:18-19` 直接 return）。启动瞬间若首页从右侧滑入，会和启动黑屏叠成一次明显闪动，所以首页保持「即开即见」。

首页场景的 `Margin` 底部留白 `100`（`assets/scenes/ui/music_app/home/music_app_home_page.tscn:52`），这是给常驻迷你播放器预留的高度（实例覆盖后高 74、离底 12，见 [迷你播放器](2026-10-27_迷你播放器.md)）。

### 4.2 功能卡：固定 4 实例 + 外部 `configure()`

功能卡不是 `Button`，而是 `Panel` 加一个铺满的透明 `Button`（`assets/scenes/ui/music_app/home/home_feature_card.tscn` 的 `OpenButton`），这样整张卡都能响应 hover / 点击，而视觉样式由 Panel 决定。

```gdscript
# assets/scripts/ui/music_app/views/home/music_app_home_feature_card.gd:24-32
func configure(index: int, icon_texture: Texture2D, display_text: String) -> void:
	setup()
	_feature_index = index
	_icon_rect.texture = icon_texture
	_text_label.text = display_text

func _on_pressed() -> void:
	pressed.emit(_feature_index)
```

View 侧用 `GridContainer columns = 2`（`assets/scenes/ui/music_app/home/music_app_home_page.tscn:165`）把 4 张卡排成 2×2；`refresh()` 只按 `FEATURE_CARD_KEYS` 长度循环 `configure()`（`assets/scripts/ui/music_app/views/home/music_app_home_view.gd:78-80`），因此新增卡要同时改场景节点、图标数组、翻译键三处。

### 4.3 歌单行按数量增删而不是全量重建

```gdscript
# assets/scripts/ui/music_app/views/home/music_app_home_view.gd:97-109
func _sync_home_playlist_rows() -> void:
	var target_size := _home_controller.get_playlists().size()
	while home_playlist_rows.size() < target_size:
		var row := HOME_PLAYLIST_ROW_SCENE.instantiate() as MusicAppHomePlaylistRow
		home_list.add_child(row)
		row.open_requested.connect(_open_playlist)
		row.delete_requested.connect(_delete_playlist)
		home_playlist_rows.append(row)
	while home_playlist_rows.size() > target_size:
		var row: MusicAppHomePlaylistRow = home_playlist_rows.pop_back()
		row.queue_free()
```

原因：新建/删除歌单后如果清空 `HomeList` 重新实例化，滚动位置会跳回顶部，正在 hover 的按钮也会丢失；增删差量最小化后，列表位置和交互状态保持稳定。注意行索引与歌单索引强绑定，删除中间歌单时必须同步刷新后续行的 `_playlist_index` —— 这里靠整体 `refresh()` 重新 `configure()` 每行实现（`:82-91`）。

### 4.4 「我喜欢」歌单的特判

系统收藏歌单在存档里是普通 `PlaylistData`，但首页要表现得不同：

- 标题与角标走翻译键（`assets/scripts/ui/music_app/controllers/music_app_home_controller.gd:14-26`），避免用户改语言后标题仍是旧语言；
- 行封面固定 `HEART_FILLED`，普通歌单用 `MUSICAL_NOTE`（`assets/scripts/ui/music_app/views/home/music_app_home_playlist_row.gd:35-39`）；
- 不可删除（`:43`），且点击区域铺满整行：`_open_button.offset_right = -56.0 if deletable else 0.0`（`:45`）——可删行给右侧删除按钮留 56px，不可删行让整行都可点。

### 4.5 首页与歌单状态的同步边界

首页刷新完全由本地动作触发：`_create_playlist_from_current()`、`_delete_playlist()` 在调用 Controller 后手动 `refresh()`（`assets/scripts/ui/music_app/views/home/music_app_home_view.gd:114-129`）；收藏状态变化由播放器页控制器反向刷新首页（`assets/scripts/ui/music_app/controllers/music_app_player_controller.gd:100-102`）。没有全局「歌单变更」信号，因此从其他页面（如歌单详情）改动歌单后回到首页，首页不会自动重算，需要下一次自身动作或重开页面才更新。

## 5. 边界与失败处理

| 场景 | 行为 |
| --- | --- |
| 控制器未注入（`_controller == null`） | `refresh()` 直接 return，不渲染（`assets/scripts/ui/music_app/views/home/music_app_home_view.gd:66-67`） |
| 歌单数组为空 | `open_playlist` 的 `_select_playlist()` 返回 false，不弹详情（`assets/scripts/ui/music_app/controllers/music_app_home_controller.gd:89-94`） |
| 删除系统歌单 | `playlist.deletable == false` 时直接返回 false，界面无变化（`:49-50`） |
| 删除索引越界 | 返回 false，不修改数组（`:45-46`） |
| 删除当前选中之前的歌单 | 选中索引同步减 1，再 clamp 到合法范围（`:52-57`） |
| 新建歌单重名 | `_next_playlist_title()` 递增后缀 `新歌单 2`、`新歌单 3`……（`:97-104`） |
| 功能卡 0–2 点击 | Toast「该入口暂未接入新页面。」，停留首页（`:81-86`） |
| 重复绑定 | `_is_bound` 守卫，`bind()` 只执行一次（`assets/scripts/ui/music_app/views/home/music_app_home_view.gd:49-51`） |
| 本地音乐页不提供 `open_page` | 先 `has_method("open_page")` 判断，避免旧页面直接报错（`assets/scripts/ui/music_app/controllers/music_app_home_controller.gd:69-71`） |

## 8. 已知限制与后续

- **功能卡 3 张是占位**：推荐歌单 / 榜单 / 播放历史没有对应页面，点击只提示；接入时需要在 `open_feature_card()` 里补索引分支并新增弹窗注册。
- **没有最近播放列表**：任务描述中的「最近播放 / 历史列表」在当前代码中不存在，首页下半区是「我的歌单」列表；若要做播放历史，需要先在存档模型里增加历史记录。
- **首页刷新依赖手动触发**：没有歌单变更信号，跨页面修改歌单后首页可能显示旧计数，后续可引入 `playlist_changed` 事件统一刷新。
- **功能卡网格固定 2 列**：窄屏（320px）下每张卡约 140px，长文案会截断，靠 `TextLabel` 的 `text_overrun_behavior` 兜底，未做自适应列数。
- **删除歌单无二次确认**：`delete_playlist()` 直接删除，误触只能重建（歌单内曲目不会从资料库删除）。
