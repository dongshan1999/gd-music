> 一句话定位：设置页是「三级跳转 + 一根音量滑条 + 版本号」的极简设置面；真正持久化的用户选项只有播放音量，其余入口要么跳到子页，要么是未接入的占位提示。

## 1. 功能概述

- 用户视角：从首页进入「设置」。顶部返回键 + 标题「设置」；下面一个标题为「功能」的分组面板，依次是「插件管理」、「音乐下载」、「语言设置」、「播放音量」（右侧百分比 + 滑条）；滚动区底部显示版本号。
- 实现视角：视图 `MusicAppSettingsView`（85 行）只做三件事 —— 绑定按钮、回填音量滑条、拼版本号；`MusicAppSettingsController`（35 行）全是转发与占位；音量状态归全局 `MusicAppAudioController` 所有；版本号由 `project.godot` 的 version 与导出期生成 `res://build_info.cfg` 的 build number 拼成。
- **与任务描述的偏差（以真实代码为准）**：
  - **没有「外观 / 播放 / 下载 / 插件 / 关于」五个分区**。场景里只有一个 `SettingsSection`，分组标题是「功能」（`assets/scenes/ui/music_app/settings/music_app_settings_page.tscn:91` `:95`），内含 3 个跳转行 + 1 个音量行；不存在主题、开关、下载目录之类的分区。
  - **唯一的持久化选项是播放音量**（`user://music_app_settings.cfg` 的 `[playback] volume`）。其余按钮都不写任何设置。
  - **没有跳转调试面板的入口**。`DX_DEBUG` 弹窗（`popup_registry.gd` 的 `PopupId.DX_DEBUG`）由其它地方打开，本页三个跳转分别是插件管理、下载管理、语言设置（后者还是占位）。
  - **「关于」没有独立页**，只在底部露出一行版本号文案。

刷新链路很短，值得注意的只有「刷新时绝不回写」：

1. `refresh()` 调 `_refresh_version_label()` 与 `_refresh_volume_slider()`（`:42-47`）。
2. `_refresh_volume_slider()`（`:49`）先 `_controller.sync_playback_volume()` 让全局控制器从配置文件重新读一次，再 `set_value_no_signal(percent)` 回填滑条，并同步右侧百分比标签 —— 用 `no_signal` 变体是因为普通 `value = ...` 会触发 `value_changed`，把「读出来回填」当成「用户拖动」再写一次盘（回环写）。
3. `_refresh_version_label()`（`:64`）拼 `"%s.%d"`。

## 3. 核心数据结构

本页涉及的持久化/只读数据只有三处：

| 数据 | 位置 | 键 / 来源 | 类型与默认 |
| --- | --- | --- | --- |
| 播放音量 | `user://music_app_settings.cfg` | `[playback] volume` | float，0~1，默认 `1.0`（`assets/scripts/ui/music_app/controllers/global/music_app_audio_controller.gd:63` `:1414-1421`） |
| 应用版本 | `project.godot` | `application/config/version` | String，当前 `"1.0.0"` |
| 构建号 | `res://build_info.cfg` | `[build] number` | int，导出期由插件写入；缺失时取 `0`（`assets/scripts/ui/music_app/views/settings/music_app_settings_view.gd:72-76`） |

插件、下载、语言相关的设置**不经过本页**：插件启停与 cookie 在 `music_plugins` 存档（见《插件管理》《插件账号登录》），下载与语言目前没有可持久化的选项。

## 4. 关键实现

### 4.1 版本号：语义版本 + 导出构建号两源拼接

`_refresh_version_label()`（`:64-70`）读 `ProjectSettings` 的 version，再调 `_read_exported_build_number()` 读 `res://build_info.cfg`，缺省 `DEFAULT_APP_VERSION = "0.0.0"`（`:7`）与构建号 `0`，拼成 `"%s.%d"`。

为什么拆成两个文件？`project.godot` 里的 version 是**人可控的语义版本**，而构建号是**每次导出自动递增的单调计数器**。后者如果每次导出都回写 `project.godot`，diff 会一直脏、还容易和分支上的版本改动打架；放进独立的 `build_info.cfg` 后，它只随导出包存在（`add_file`），工程内仅作为「上一次导出的产物」参考。

### 4.2 构建号插件：导出前 +1，并写回工程

`addons/dx_build_number/dx_build_number_export_plugin.gd`（78 行）是一个导出期 `EditorExportPlugin`：

1. `_get_export_options_overrides()`（`:15`）返回 `build_number = _read_project_build_number() + 1`，让导出对话框里默认就是「下一个号」。
2. `_export_begin()`（`:25`）把最终号写进工程根目录的 `build_info.cfg`，再 `add_file()` 打进导出包（`:31-33`）—— 一份给包里读、一份留在工程里，下次才能接着加。
3. `_make_build_info()`（`:46`）写 `[app] version`、`[build] platform`、`number`、`debug`、`unix_time`。
4. 运行时设置页只读 `[build] number`，不关心其它字段。

这套机制的代价：**在编辑器里直接运行（不导出）时，版本号显示的仍是上一次导出写下的数字**，因为 `build_info.cfg` 只在导出时更新。当前仓库里的值就是上次导出留下的 `[build] number=87`、`platform="android"`、`debug=true`。

### 4.3 音量：0 映射为 -80 dB 而不是 -inf

`_apply_playback_volume()`（`assets/scripts/ui/music_app/controllers/global/music_app_audio_controller.gd:1395-1405`）：

```gdscript
var db := linear_to_db(playback_volume) if playback_volume > 0.001 else -80.0
```

`linear_to_db(0)` 是 `-inf`，部分音频后端（尤其是流式后端）对 `-inf` 处理不一致，甚至会被当成非法值导致无声或爆音；统一钳到 `-80 dB`（≈ 人耳不可闻）既安全又几乎等价于静音。写后端时还分叉了两种播放器：流式后端调 `set_volume_db()`，普通 `AudioStreamPlayer` 直接赋 `volume_db`。

### 4.4 音量落盘：一次拖动一次写

`set_playback_volume()`（`:1386-1393`）先 `clampf`，再用 `is_equal_approx` 判等提前返回（避免滑条抖动产生无意义写入），变化时依次 `_apply_playback_volume()` + `_save_playback_settings()`。`_save_playback_settings()`（`:1422-1427`）是「load 覆盖 set_value 再 save」，而不是「全新 ConfigFile 直接 save」——这样将来同一个 cfg 里加了别的键（如其它页面设置），保存音量不会把它们冲掉。

代价是拖动过程中每个像素变化都会同步写一次文件（`value_changed` 逐帧触发）。当前滑条只有 0~100 且文件极小，实测无感；如果以后往这个 cfg 里塞大量键，应改成拖动结束（`drag_ended`）再落盘。

### 4.5 分区结构：GroupedPanel + Disclosure 箭头

场景用「`SettingsSection`（VBox）+ `SettingsSectionLabel`（分区标题）+ `Group`（`theme_type_variation = GroupedPanel`）+ `Rows`（VBox）」这套四层结构（`assets/scenes/ui/music_app/settings/music_app_settings_page.tscn:91-108`）表达「分组面板」。每个跳转行内部还带一个 `Disclosure` 子标签做右侧箭头（`:121` `:146` `:171`），箭头是纯文本标签而不是图标，避免多一套图标资源与主题适配。

`ScrollInteractionComp`（`:74`）挂在 `Scroll` 前，用于在滚动容器上处理「拖动时不要误触」的交互补偿，这是项目里滚动页的通用组件。

### 4.6 占位按钮：统一走 toast

`MusicAppSettingsController` 里 9 个方法（`:10-32`）全部只弹一句「暂未接入」：基础设置、主题设置、语言设置、定时关闭、备份与恢复、权限管理、检查更新、关于页面。这是刻意的「先占位后接线」写法：场景里先留好按钮与文案结构，功能实现时只改控制器内部，不动 `.tscn`。当前场景实际只挂了 `LanguageSettingsButton`（`:84`）一个占位入口，其余占位方法暂时没有对应节点。

## 5. 边界与失败处理

| 情形 | 行为 |
| --- | --- |
| `build_info.cfg` 不存在或打开失败 | `_read_exported_build_number()` 返回 `0`，版本号显示成 `1.0.0.0`（`:72-76`） |
| `project.godot` 未设置 version | 回落 `DEFAULT_APP_VERSION = "0.0.0"` |
| 音量配置文件不存在 | `config.load()` 失败直接 return，保持内存默认 `1.0`（`assets/scripts/ui/music_app/controllers/global/music_app_audio_controller.gd:1417-1418`） |
| 音量拖到 0 | 落盘存 0，下发 `-80 dB`（不静音后端、不销毁播放器） |
| 回填时值未变 | `set_playback_volume()` 的 `is_equal_approx` 提前 return，不写盘 |
| 音频后端尚未创建 | `_apply_playback_volume()` 里 `_get_active_player()` 为空则直接 return，下次播放时由 `_ensure_playback_volume_applied()`（`:1408`）补上 |
| 未接线的占位按钮 | 只弹 toast，不发生任何跳转或写入 |

## 6. 相关测试

无自动化测试。手工验证要点：

1. 进入设置页，确认底部显示 `1.0.0.<N>`，且 N 与 `build_info.cfg` 的 `[build] number` 一致。
2. 拖动音量到 50%，确认右侧标签同步为 `50%`、声音变小；退出再进，滑条回到 50%（持久化生效）。
3. 拖动到 0%，确认静音但播放不中断；再拖回 30%，确认声音恢复。
4. 点「插件管理」「音乐下载」，确认分别打开对应弹窗；点「语言设置」，确认只弹「暂未接入」提示。
5. 删除 `user://music_app_settings.cfg` 后重启，确认音量回到 100%。

## 8. 已知限制与后续

- 设置项严重偏少：外观/主题、播放（音质、播放模式）、下载目录、缓存清理、定时关闭、备份恢复全都只有占位方法，没有界面。
- 没有「关于」页，版本号只以一行小字出现；构建号在编辑器内运行时是上次导出的残留值。
- 语言设置按钮是占位：项目里已有 `music_app.csv` 翻译表与 tr() 调用，但切换语言的 UI 未接。
- 音量每次 `value_changed` 都写盘（见 4.4），后续应改为拖动结束落盘。
- `addons/dx_build_number/dx_build_number_store.gd` 提供了分平台计数存储，但当前导出插件直接读写工程根的 `build_info.cfg`，两套计数逻辑并存，容易对不上，建议收敛成一套。
- 设置页所有文案走 `tr("music_app.ui.settings")` 等翻译键，新增按钮需要同步补 `assets/translations/music_app.csv`。
